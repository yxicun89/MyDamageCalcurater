# 要件定義: ポケモン ダメージ計算 & 構築ビルダー

最終更新: 2026-09-20 / ステータス: v3(未決事項なし)

## 1. 目的と優先順位

1. **自分が一番使いやすい**ダメージ計算と構築ビルダーを作る
2. フロント〜バックエンド〜DB〜インフラ(Kubernetes)まで通して**学ぶ**
3. ストア公開は必須ではない(クラウドにデプロイするなら公開も検討)

利用者は自分1人。認証は不要。

## 2. 機能要件

### 対象ルール
- **ポケモンチャンピオンズ**(Lv50、個体値は全ステータス31固定)
- 能力ポイント(SP): 1ステータス最大32、合計66。1SP = 実数値+1
  - HP = 種族値 + 75 + SP
  - その他 = floor((種族値 + 20 + SP) × 性格補正)

### 設計原則: 入力の手間を最小にする
- 数値の直接入力は原則しない。**プリセットを選ぶだけ**で計算できること
- 相手側は入力させない。**代表的な調整を並べて一括表示**する

### 必須
- **ダメージ計算(1 vs 1)**
  - 画面: 攻撃側と防御側を左右に配置、計算結果は下
  - 両側に持ち物を設定できる
  - ダメージ幅(乱数16段階)、%表示(**小数第1位まで**。例 73.4%。HP 比率から直接求め、整数%に丸めてから表示しない)、確定数/乱数n発
  - 補正: タイプ一致・相性・急所・やけど・天候・フィールド・ランク・壁・持ち物・特性
  - 攻守入れ替えをワンタップで
- **自分側のプリセット**: 構築から個体を呼び出す / 「A特化」「A振り(補正なし)」「無振り」から選ぶ
- **相手側の一括表示**: 防御側の努力値は入力せず、以下の調整すべてに対するダメージを同時に表示
  - 無振り / H振り / HB振り(またはHD振り。技の分類で自動切替)/ H振り+B(D)補正 / HB特化(またはHD特化。性格補正込みの最大耐久)
    - `hb`: H32・B32・B への性格補正なし / `hd`: H32・D32・D への性格補正なし
    - `hb_boost`: H32・B0・B 上昇性格 / `hd_boost`: H32・D0・D 上昇性格
    - `hb_full`: H32・B32・B 上昇性格 / `hd_full`: H32・D32・D 上昇性格
  - 持ち物の差し替え候補(現行レギュレーションで使用可能なもの)もトグルで比較
- **調整の推定(逆算)**: 実際のダメージから相手の調整候補を複数挙げる。正確さより候補の提示を優先
  - 与えたダメージ(相手HPの減少%)→ 相手の耐久(H/B(D) 配分・性格・持ち物)の候補
  - 受けたダメージ(自分HPの減少量)→ 相手のA(C)配分・性格・持ち物の候補
  - 耐久の推定は固定プリセットからの選択にしない。**H振り(HP SP=32)を前提**に、B(D) の SP を 0〜32 で探索し、性格は「B(D) 補正なし」と「B(D) 上昇性格」の2通りを見る
  - 結果は「性格補正あり/なし × 持ち物」ごとに、観測を説明できる **SP の範囲**(例: 補正なし・B 20〜23 / 補正あり・B 4〜7)として返す。観測から区別できない候補は無理に1つに決め打ちせず残す
  - 「無振り」「HB特化」などの名前は、範囲の目安として併記してよい
  - 実機画面の整数%を入力とする場合の丸め規則は、アプリが表示する%(小数第1位)とは別概念として扱う
  - 同じ相手の観測を複数入力すると候補を絞り込める
- **計算結果の自動保存**: 計算するたびにイベントとして保存
- **よく使うポケモン**: 計算履歴から頻度×時間減衰で上位を表示
- **構築ビルダー**: 6体のパーティ、個体(技・持ち物・特性・性格・努力値・テラスタイプ)、Showdown形式のインポート/エクスポート
- **2つのクライアント**: iOSネイティブアプリ / ブラウザ版(React)

### あれば便利(マストではない)
- 計算候補の推薦(機械学習)。まず統計ベース、MLは比較して勝てたら採用
- お気に入り(手動ピン留め)

## 3. 非機能要件

| 項目 | 要件 |
|---|---|
| 計算の正確性 | `@smogon/calc` と同じ入力で同じ結果になること(ゴールデンテストで担保)。oracle は @smogon/calc 0.12.0(完全固定)の Champions 世代で、SP は直接渡して照合。Champions に無い効果の計算式だけは同じ版の gen9 世代で、SP を努力値 max(0, 8×SP−4) に換算して照合(ADR-0002 追記「P2-1b」) |
| 可用性 | 自宅Mac(k3d)で稼働。Mac起動中はTailscale経由で外出先からも利用可 |
| オフライン | ブラウザ版はWASMでバックエンドなしでも計算可能 |
| 認証 | なし。クライアント生成の端末IDで持ち主を識別 |
| 配布 | iOSは無料Apple IDでXcodeから実機インストール(7日ごと再署名) |
| 知財 | 個人利用前提。公開時に画像・名称を差し替えられる構造にしておく |

## 4. アーキテクチャ

```
iOS (SwiftUI)      ─┐
Web (React)  ────────┼─▶ gateway (Echo) ─┬▶ pokedex-svc ─▶ MySQL
  └ WASM engine      │                   ├▶ calc-svc (stateless)
    (オフライン計算)  │                   ├▶ record-svc ─▶ TiDB (record DB)
                      │                   └▶ team-svc   ─▶ TiDB (team DB)
                      │  calc-svc ─▶ NATS JetStream ─▶ record-svc
importer (CronJob) ─▶ MySQL
```

- 計算エンジンは**純粋なGoパッケージ**(I/Oなし)。calc-svc と WASM の両方から利用
- API契約は **OpenAPI 1本**。Go(Echo)/ TypeScript / Swift のコードを生成
- 計算イベントはNATS経由で非同期保存(TiDB障害時も計算は止めない)

## 6. データモデル(骨格)

### MySQL(pokedex-svc)
- `species` ポケモン一覧(図鑑番号、名前、フォルム)
- `species_details` ポケモンごとの情報(タイプ、種族値、特性)
- 計算に必要なため追加: `moves` 技、`items` 持ち物、`abilities` 特性、`type_chart` タイプ相性、`learnsets` 覚える技、`data_versions`

### TiDB(同一クラスタ内でサービスごとにDBを分ける)
record-svc:
- `calc_events` 端末ID、セッションID、攻撃側/防御側の個体、技、状況、ダメージ幅、日時、推薦経由か
- `favorites` お気に入り

team-svc:
- `teams` / `team_members` 構築(個体: 種族・技・持ち物・特性・性格・SP)

## 8. 決定事項(旧未決事項)

- **iOS**: SwiftUI
- **ビジュアル**: B(Liquid Glass)+C(カード/ホロ)。計算画面はB、ポケモン/構築表示はC。詳細は docs/design.md
- **構築データ**: team-svc に分離。TiDBクラスタは共有し、DB(スキーマ)をサービスごとに分ける。record-svc は個体を参照せず、計算時点の個体スナップショットを保存する
- **対戦形式**: シングル優先。ダブルは後続Phase
  - engine の入力モデルには最初から `format`(single/double)を持たせ、ダブル固有の補正(全体技0.75倍、味方の特性・てだすけ等)を後から追加できる構造にする
- **逆算の持ち物候補**: ハードコードせず、マスタの「ダメージ補正を持つ持ち物」かつ「現行レギュレーションで使用可能」から自動抽出(v1 のレギュレーションは M-C。レギュレーションはデータとして持ち、直書きしない)。既定は次の分類
  - 防御側: なし / 防御・特防を上げる持ち物(該当があれば) / 半減きのみ(該当タイプのみ)
  - 攻撃側: なし / 威力・ダメージ倍率系 / タイプ強化系
  - こだわりハチマキ・こだわりメガネ・とつげきチョッキ・しんかのきせきは現行の M-C に存在しないため対象外。別レギュレーションで追加されれば、マスタの差し替えだけで候補に復活する(ADR-0002)
- **ポケモン画像**: アプリに同梱しない。画像を用意すれば表示できる枠組みを作る
  - キー: `{図鑑番号4桁}-{フォルム3桁}`(例 `0445-000`)。画像が無ければタイプ色のエンブレムにフォールバック
  - 形式: WebP、2サイズ(サムネ128px ≤20KB / 詳細512px ≤100KB)
  - 配置: MinIO に置き、gateway の `/assets/` から配信。`manifest.json`(キー→ハッシュ付きURL)で管理し、長期キャッシュ
  - クライアント: 画面に見えている分だけ遅延読み込み。iOSはディスクキャッシュ、Webはブラウザキャッシュ
  - 取込: `make assets` で手元の画像フォルダを変換・アップロード
- **グラフィック・演出の方針**: 重い演出は作らない
  - 3Dモデル・常時動くアニメーション・動画は使わない
  - 動きは操作したときだけ(ダメージバー、確定数バッジ、攻守入れ替え)
  - ホロ効果は選択中の1枚のカードだけ
  - OSの「視差効果を減らす」設定に従い、演出を止める
- **TiDB**: 開発時は `tiup playground`、k3d上は TiDB Operator の最小構成(PD/TiKV/TiDB 各1台、リソース上限を設定)
