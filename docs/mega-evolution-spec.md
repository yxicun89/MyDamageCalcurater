# メガシンカの入力仕様(名前で選ぶ・メガストーンを自動で固定)

- 状態: 仕様(2026-10-03 ユーザー要望)。実装は各レーンが受け取る。追跡は issue #515
- 担当: データレーン(名前の生成と検索)→ Web レーン・iOS レーン(入力 UI)。API は別 issue で対応済み・対応中(後述)
- 関連: ADR-0002 の決定 10、issue #315(API の検証)・#505(wasmapi の検証)・#506(PR)

## 1. 要望(ユーザーの言葉の要約)

- 種族名の入力欄に「メガルカリオ」と入力すると、メガシンカ後のポケモンが選ばれる。
- 持ち物は、そのメガストーンに**自動で入り、他の持ち物は選べない**。
- 「メガストーンを持ち物として選ぶ」のではなく、「メガシンカ後のポケモンを入力すると、持ち物が自動でメガストーンになる」仕様にしたい。

## 2. すでに決まっていること(再決定しない)

- **ADR-0002 決定 10(回答済み)**: メガシンカ後の姿を**別のポケモンとして登録**する。そのポケモンを選ぶと持ち物にメガストーンが自動で入り、**変更できない**(固定)。
- **マスタに必要な項目は既にある**(公開 API `MasterSpecies` / `SpeciesDetail`。`api/openapi.yaml`):
  - `isMega: boolean`
  - `baseSpeciesKey: string | null`(メガシンカ前の種族キー。メガでなければ null)
  - `requiredItemId: string | null`(メガシンカに要る持ち物の ID。メガでなければ null)
- **メガ種族の判定**: importer は Showdown のフォーム名が `Mega` で始まるものをメガとする(`services/pokedex/importer/convert_species.go`)。基本種は `baseSpeciesKey`、メガストーンは `requiredItemId` に入る。
- **API の検証**: メガ種族に `requiredItemId` 以外の持ち物を持たせた計算は 400 `invalid_input`(issue #315・PR #506。calc-svc)。オフライン計算(`engine/wasmapi`)の同じ検証は issue #505。**UI はこの検証に当たらない入力だけを送れるようにする**(下記 §4)。

## 3. 足りないもの

### 3-1. 日本語名で見つけられない(データ)

取得済みの PokeAPI のデータでは、メガ種族の日本語名が空になっている(例: `data/generated/pokeapi/*/snapshot.json` の `forms` の `lucario-mega` は `names: {"ja-Hrkt": "", "ja": ""}`)。ADR-0002 の「日本語名の欠落」にも、新規のメガ石・メガフォーム名の欠落が記載されている。
importer は日本語名を `resolveJaName`(上書き → PokeAPI の言語 → 英語名)で決めており、メガは英語名にフォールバックしている可能性が高い。そのため「メガルカリオ」と入力しても検索に当たらない。**実データで、メガ種族の `nameJa` が何になっているかを最初に確認すること**。

### 3-2. 入力 UI がメガを特別扱いしていない(Web・iOS)

Web・iOS とも、種族を選んだあとの持ち物は独立した選択になっている。`isMega` / `requiredItemId` を UI で使っている箇所はない(Web の `web/src/master/exportSnapshot.ts` は項目を持つだけ)。

## 4. 仕様

### 4-1. データレーン: メガ種族の日本語名

- メガ種族の `nameJa` を、**基本種の日本語名から機械的に作る**(クライアントで組み立てない。検索・並び・表示を全クライアントでそろえるため)。
  - 形: `メガ` + 基本種の日本語名。例: メガルカリオ、メガガブリアス。
  - 同じ基本種に複数のメガがあるとき(メガシンカが X・Y・Z など)は、末尾に識別子を付ける。例: メガリザードンX、メガリザードンY、メガルカリオZ。識別子は Showdown のフォーム名(`Mega-X` など)から導く。
  - 上流(上書き設定・PokeAPI)に日本語名があるときは**それを優先**し、無いときだけ生成する。
  - 名前の表を直書きしない(基本種名とフォーム識別子から導く。CLAUDE.md のハードコード禁止)。
- `name_ja_source` に生成したことが分かる値を足す(既存は上書き・PokeAPI・`fallback_en` の別がある)。importer の report に、生成した件数を出す。
- メガストーン(持ち物)の日本語名の欠落も、同じ仕組みで確認する。メガストーンは `nameJa` の末尾が「ナイト」「ジュエル」など固有なので、生成は不要で、欠落は上書き設定(`data/importer/overrides`)で扱ってよい。生成できない場合は欠落を一覧で報告するだけでもよい。
- **実データを Git にコミットしない**(CLAUDE.md。生成した名前も `data/generated/` 側。テストは架空データ)。
- 実データの dry-run: `cd services && go run ./pokedex/cmd/import -data ../data -dry-run` が exit 0・blockers: none。

### 4-2. データレーン: 検索

`GET /api/pokedex/species?q=...`(`searchSpecies`)の挙動を決めて ADR に書く。既定案:

| 入力 | 返すもの |
|---|---|
| `メガルカリオ` | メガルカリオ |
| `メガ` | 全メガ種族 |
| `ルカリオ` | ルカリオ(基本種)とメガルカリオの両方 |
| `ルカリオ` で基本種を先に並べる | 並びは図鑑番号・フォーム番号の昇順(既存の決定的な並びのまま) |

- オフライン(Web の WASM・マスタのスナップショット)の検索でも同じ結果になること。検索ロジックが API とクライアントで二重にある場合は、両方に同じテストを置く。
- レギュレーションで使えないメガは、既存の使用可能集合の規則のまま検索に出ない。

### 4-3. Web レーン・iOS レーン: 持ち物の自動固定

対象画面: 計算・逆算・判定・構築の編集(自分側・相手側の個体を選ぶすべての場所)。

- **メガ種族を選ぶ**(`isMega` が true): 持ち物を `requiredItemId` に自動で設定する。持ち物の選択欄は**操作できない状態(固定)**にし、選ばれているメガストーンの名前を見せる。固定の理由を日本語で添える(例: 「メガシンカ: メガストーンを持ちます」)。
- **メガでない種族に変える**: 固定を解除し、持ち物は**未選択に戻す**(メガストーンを残さない)。
- 持ち物の選択肢に、メガストーンを**単独の持ち物としては出さない**(メガ種族を選んだときだけ入る)。マスタ上のメガストーンは `requiredItemId` から参照されている持ち物として判別できる。判別の方法は各レーンが決める(例: いずれかのメガ種族の `requiredItemId` に現れる ID の集合)。
- **逆算の持ち物候補**: メガ種族では持ち物候補を探索しない(固定のため)。
- **構築(保存済みのデータ)**: メガ種族に `requiredItemId` 以外の持ち物が入った古い保存データが読み込まれたときの扱いを決める。既定案: 読み込み時に `requiredItemId` へ直す(他の持ち物を黙って使い続けない)。直したことを画面に出す。
- 送れない入力は UI から出ない(API の 400 は最後の安全網。UI がそれを見せる必要はない)。
- a11y: 固定の理由を、見える文言と、操作できない欄の説明(`aria-describedby` / Web、accessibility hint / iOS)の両方で伝える。
- iOS の文言は Web の `ja.ts` と同じ語にそろえる。

### 4-4. 対象外

- 同じ個体で通常とメガを切り替える UI(メガシンカ前後の切り替えボタン)。切り替えは種族の選び直しとする。
- ダメージ計算の式(メガ種族の種族値・特性はマスタのまま。engine は変えない)。
- メガシンカの発動条件・ターンの扱い(対戦の進行はこのアプリの範囲外)。

## 5. 受け入れ条件

1. 日本語名: 架空のメガ種族(X・Y の2形態・上流に日本語名があるもの・基本種名が無いもの)で、名前の生成がテーブル駆動テストで決まった値になる。実データの dry-run が通り、メガ種族の `nameJa` が英語名フォールバックでなくなる(report に件数)。
2. 検索: 上の表の入力で、期待する種族が返る(API とオフラインの両方)。
3. UI: メガ種族を選ぶと持ち物が `requiredItemId` になり操作できない。メガ以外に変えると未選択に戻り操作できる。メガストーンが単独の持ち物の選択肢に出ない。Web は Testing Library と Playwright、iOS は XCTest と XCUITest(モック強制)で確かめる。
4. 古い構築データ: メガ種族+別の持ち物の保存データが、読み込み時に直る(または決めた扱いになる)。
5. 回帰: `make test`・`make test-golden`(engine 不変)・`make web-k3d-e2e`・`make ios-test` が成功する。

## 6. 進め方(推奨順)

1. **データレーン**: §4-1 → §4-2。実データで名前を確認し、ADR(データ帯 0100〜)に生成規則と検索の仕様を書く。
2. **Web レーン・iOS レーン**: §4-3。`isMega` / `requiredItemId` は公開 API に既にあるので、1 と並行して進められる(名前の検索だけが 1 に依存する)。
3. API・wasmapi の検証(#506・#505)は別 issue で進行中。UI 側は依存しない。

## 7. 未決の点(既定案で進めてよい)

| 点 | 既定案 |
|---|---|
| X・Y・Z の識別子の取り方 | Showdown のフォーム名(`Mega-X` → `X`)をそのまま末尾に付ける |
| 古い構築データの扱い | 読み込み時に `requiredItemId` へ直し、直したことを表示する |
| `q=ルカリオ` で基本種とメガを両方出すか | 両方出す(基本種が先。図鑑番号・フォーム番号の昇順) |
