# ADR-0609: 素早さ(Web)の「自分の周り」パネル(G-04)

- 状態: 採用(2026-10-11。docs/usability-round3.md の G-04。ユーザー要望「素早さ表は、スクロールしないと見えない・折りたたんでいて、自分より上と下に誰がいるか分かりにくい」)
- 日付: 2026-10-11
- 関連: ADR-0608(仮想スクロール表と位置マーカー)・ADR-0607(トリックルーム = 昇順の表)・ADR-0604(素早さ画面)・F-13(やさしい言葉)・G-05(ビジュアル刷新。方針は docs/design.md に後から入る)
- 範囲: Web のみ。iOS は後続 PR(同じ切り出しの考え方で別 ADR か追記)。

## 背景
ADR-0608 の表は、全体を見るには適しているが、自分の位置は「スクロールして探す」か「自分の位置へ移動」ボタンを押さないと周りが見えない。知りたいのは「自分のすぐ上と下に誰がいるか」で、全体の表ではない。

## 決定
1. **新しい「自分の周り」パネルを足す**。ADR-0608 の表は全体を見る用として**そのまま残し、壊さない**(行 24px 固定などの定数契約・仮想スクロール・位置マーカーは変更しない)。
2. **置き場所は自分の入力/結果のカード(`.speed-self`)の中、結果の近く**。常時表示で、折りたたみ(`details`)にせず、表のスクロール領域の外に置く。これにより表のスクロール位置に関係なく、スクロールなしで見える。
3. **表示内容**: 中央に自分(「自分」バッジ・強調。同速の段があればその面々を並べ、無ければ「ここに自分が入ります」)、その前後に直近 N 段(既定 N=3。`DEFAULT_NEIGHBOR_STEPS`)。各段は実数値と代表ポケモン名(多ければ「ほか n 体」)。端は「これより速い(遅い)ポケモンは計 X 体」の合計行(X は片側の全体。端で空のときは 0 体)。
4. **トリックルーム**: 表の並びが昇順なので、速い/遅いの語は使わず「先に動く側/後に動く側」で見出しと合計行を言う(ADR-0607)。切り出しは「表の並びで自分より前 = 先に動く側」で決めるため、通常/トリックルームで分岐する計算を持たない。
5. **素早さは計算し直さない**(ADR-0608 §3)。位置は、既に読み込んだ tiers の実数値と自分の実数値(position の結果)の直接比較だけで決める。新しい API は追加しない。
6. **構造**: 切り出しは純粋関数 `buildNeighborhood`(`web/src/speed/speedNeighborhood.ts`。DOM を知らない)、描画は `SpeedNeighborhood`(`SpeedNeighborhood.tsx`)に分ける。見た目は既存のデザイントークンだけを使い、G-05 の方針(docs/design.md)が入ったら CSS とマークアップの見た目だけを差し替えられるよう、ロジックと見た目を分離する(テストは `data-testid`・role・文言で見て、色やクラスに依存しない)。
7. **a11y**: 見出し(自分の周り)・先に動く側/後に動く側の名前付きリスト(`ul`/`li`)・region の名前。色だけに頼らず、「自分」バッジと矢印(↑ ↓)の文字を持つ。常時動くアニメーションは無し。
8. **文言**は `web/src/i18n/speed.ts`(`speedScreenText.neighborhood*`)に、F-13 のやさしい言葉で置く。

## 選ばなかった案
- **A. ADR-0608 の表の自分の行の周りを常に画面中央に固定する(表のスクロールを自動で動かす)**: 閲覧中のスクロールが勝手に動く・全体を見たい操作と衝突する・仮想スクロールの定数契約に触れる。
- **B. 表の折りたたみ/展開式にする**: 要望の「折りたたんでいて分かりにくい」をそのまま再現するので不可。
- **C. 自分の入力カードの結果(同速・件数)に前後を足すだけ**: 件数(faster/slower)は全 6 行基準で表示中の tiers と一致しない(ADR-0608 の critic 指摘)ので、表示用の実数値の並びは tiers から作る必要がある。結果カードの既存表示は変えない。
- **D. サーバー(speed-svc)に近傍 API を足す**: 既に読み込んだ tiers で足りる。API 契約の変更・往復を増やす利点が無い。
- **E. 前後の段数を可変 UI にする**: 初期は固定(既定 3)。必要になったら足す(関数は `steps` を受け取る)。

## 結果・今後
- iOS は後続 PR。切り出し規則(直近 N 段・合計・トリックルームの語)はここを正にそろえる。
- G-05 で見た目が変わるときは `SpeedNeighborhood` の描画とスタイルだけを触る。`buildNeighborhood` の契約は保つ。
