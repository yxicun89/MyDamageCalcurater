# ADR-0229: 構築名を入力で省略できるようにし、サーバーが既定名を補う(F-08)

- 状態: 提案(2026-10-04。spec-writer 工程。実装と critic レビューはこの後)
- 日付: 2026-10-04
- レーン: API(team-svc の契約)。依頼元はダメージ計算(ec)レーンの取りまとめ
- 関連: ADR-0213(team-svc の構築 CRUD。§2 の PUT の意味・§3 の検証・AC-T2 をこの ADR で一部置き換える)、
  ADR-0209 §3(自由入力をログに出さない)、docs/usability-round2.md F-08、
  docs/ai-shared/decisions/2026-10-04-api-favorite-calc-team-name.md(Web・iOS への依頼)

## 背景

利用者の動作確認(usability-round2 F-08)の要望: 「構築名はいらない」。Web・iOS は構築画面を作り直し、構築名の入力欄を
廃止する予定。ところが ADR-0213 の契約では `TeamInput.name` が必須(前後の空白を除いて1〜50文字)で、名前の欄が無い画面は
保存のたびに何かしらの名前を自前で作って送る必要がある(画面ごとに既定名がばらつく)。

一方、応答の `Team.name` の型(必須の string)を変えると、既存の Web(構築の一覧・編集)と iOS の生成型・表示が壊れる。

## 決定

### 1. 入力では `name` を省略可・nullable にし、未設定ならサーバーが既定名「名称未設定」を入れて保存する

- `TeamInput.name`: `required` から外し、`nullable: true`・`maxLength: 50`(`minLength` は外す)。
  **省略・null・空文字・空白だけ**(前後の空白を除いて0文字。全角空白も空白)は「未設定」とし、サーバーが既定名
  **「名称未設定」** を補ってから保存する。
- 応答の `Team.name` は**変えない**(必須の string・1〜50文字)。既定名もこの範囲に入るので、応答は常に表示できる名前を持つ。
  クライアントの生成型・既存の表示はそのまま動く。
- 名前を送る従来の要求は従来どおり(前後の空白を除いて保存・コードポイントで50文字まで・51文字は 400 `invalid_input`)。
- 利用者が既定名と同じ文字列を明示しても区別しない(どちらも「名称未設定」として保存する)。区別したい要望は今は無く、
  区別には DB に「未設定」フラグの列が要る(migration)。
- DB(`teams.name NOT NULL`)・store は変えない。補うのは httpapi の入口(検証の直後)。既定名は名前付きの定数1つに置く。

**既定名をサーバーで補う理由**(クライアントが空文字を送り、応答も空にする案との比較):

- 応答の `Team.name` が `minLength: 1` のまま保てる(型も制約も変えない)。空を返すと、名前を必須として扱う既存の
  クライアント(iOS の `TeamValidator`・Web の構築名の検証)が、取得した構築をそのまま保存し直せなくなる。
- 既定名が画面ごとにばらつかない(Web と iOS で同じ構築が同じ名前で見える)。
- 画面の文言は日本語だけ(多言語化の予定が無い)なので、サーバーが日本語の既定名を持つ欠点は小さい。

### 2. `updateTeam`(丸ごと置換)で `name` を省いたら既定名に置き換える(前の名前を残さない)

ADR-0213 §2 は PUT を「送った内容がそのまま保存後の状態になる」と定め、`members` の省略も「メンバーなし」への置換とした。
`name` も同じ規則に揃え、省略・空は「名称未設定」への置換にする(部分更新と読まない)。名前の欄を持つ旧い画面は
常に名前を送るので影響を受けない。名前の欄を持たない新しい画面は、保存のたびに名前が既定名になる(名前を持たない
画面としてそれが正しい)。

### 3. ADR-0213 の受け入れ条件の置き換え

ADR-0213 AC-T2 の「名前1〜50文字」は「名前は0〜50文字(前後の空白を除く)。0文字・省略・null は既定名」に置き換える。
既存テスト `TestCreateTeamValidatesInput` の「名前が空」「名前が空白だけ」の2ケース(400 を期待)は、仕様変更のため
既定名で保存されるテスト(`team_name_default_test.go`)へ移した。これは検証を弱めたのではなく、必須→省略可の仕様変更
(ユーザー要望 F-08)である。上限(51文字で 400)は変えず、既存テストが引き続き固定する。

### 4. ログ・冪等・端末分離は変えない

構築名は利用者の自由入力なのでログに出さない(ADR-0209 §3)。既定名も「構築名」なので同じく出さない
(名前の出どころで規則を分けない)。作成・置換・削除・全削除・端末分離・上限100件(ADR-0213 §2)は変えない。

### 5. クライアントへの依頼(Web: web-cf・iOS: ios-6f)

詳細は docs/ai-shared/decisions/2026-10-04-api-favorite-calc-team-name.md。要点: 構築名の入力欄を廃止する画面は、
`createTeam` / `updateTeam` で `name` を**送らない**(空文字や自前の既定名を作らない)。表示は応答の `Team.name` を使う
(「名称未設定」がそのまま表示される)。Web の生成型では `TeamInput.name` が `string | null | undefined` になる
(既存のテストの偽クライアントは `name ?? "名称未設定"` で応答を組み立てるよう追従済み)。iOS は構築をローカルに保存しており
team-svc の `TeamInput` を使っていないので、今回の変更で直すコードは無い(同期を作るときにこの規則に従う)。

## 受け入れ条件

- **AC-N1** 作成で `name` を省略・null・空文字・空白だけ(半角・全角・改行とタブ)にしても 201 で、応答・取得・一覧の `name` は
  「名称未設定」。メンバーは落ちない。
- **AC-N2** `updateTeam` で `name` を省略・空・null にすると、前の名前を残さず「名称未設定」に置き換わる(`createdAt` は不変)。
- **AC-N3** 名前を送る従来の要求は従来どおり(前後の空白を除く・50文字ちょうどは通る・51文字は 400 `invalid_input` で行を作らない)。
  既定名と同じ文字列を明示しても保存できる。
- **AC-N4** 既定名は契約の `Team.name`(1〜50文字)を満たし、契約の `TeamInput.name` の説明に書かれている。
- **AC-N5** 契約: `TeamInput.name` は required に無く nullable・minLength 0・maxLength 50。`Team.name` は必須の string
  (null 不可・minLength 1)のまま。名前なしの作成(201)・置換(200)の要求と応答が契約どおり。Web・iOS の生成型で
  `TeamInput.name` は省略可、`Team.name` は必ずある文字列。
- **AC-N6** 名前を省略した要求でも、構築名(既定名を含む)をログに出さない。

## 却下した案

- **応答の `Team.name` も任意(または空文字可)にする**: §1。既存クライアントの生成型・検証が壊れる。
- **クライアントが既定名を作って送る(契約は変えない)**: Web と iOS で既定名がばらつき、名前の欄が無い画面にも検証が残る。
- **「未設定」フラグの列を足して、既定名と明示の同名を区別する**: migration が要り、区別する要望が無い。
- **PUT で `name` を省いたら前の名前を残す**: ADR-0213 §2 の PUT の意味(丸ごと置換)に部分更新を持ち込む。

## 未決事項

  テストの定数を同時に変える(保存済みの行の名前は変えない)。
