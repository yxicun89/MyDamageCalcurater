# ADR-0530: iOS の配色を「K. 空色と白」に差し替える — G-05 / I-ios-15

- 状態: 採用(2026-10-11。ユーザー決定「配色は K. 空色と白」。ec レーン経由)
- 関連: ADR-0334(ポップ配色)、ADR-0521(iOS の共通の部品)、ADR-0501「G-05 配色 K」章、docs/ai-shared/decisions/2026-10-11-ios-palette-sky-white.md(値の表)

## 決定

1. `PokeCalcDesign` の色トークンの**値だけ**を差し替える。キー名・API・画面コードは変えない(画面は色を直接書かない規則)。
2. 背景: ベース `bgBase`・`bgGradientStart/End` を淡い空色にし、グラデーションは名前を残したままほぼ単色(差はわずか)にする。
   カード `surfaceCard` は白、ダークは紺の面。
3. 主色: #2F80ED 系だが、そのままでは白文字に 3.87:1 で 4.5:1 に届かないため、同じ青系で明度を下げた #1D66D0(ダーク #7DB4FF)にする。
4. タイプ色: 彩度を 0.95 倍。かくとうだけは 0.95 倍だと文字が黒→白に反転して「文字色表」が変わるため、明度を少し上げて黒を保つ。
5. 影: ライトは青みの #143C78 12%、ダークは黒 45%。
6. Web の `tokens.css`・design.md の表は未反映(Web レーンの作業)。値の表は decisions に残し、突き合わせられるようにする。

7. 追記(2026-10-11): 耐性用に水色〜シアン系の `resist`(文字・枠・アイコン)/`resistSoft`(背景)を追加(ライト 0A7080/DDF4F8・ダーク 5CD3E3/0C2E36)。弱点は赤の `danger` のまま。既存画面の緑 `success` 使用は未変更(構築のバランス節で使う)。

## 理由

コントラスト検査は弱めない。検査に通る色を値の調整で選んだ(推測でなく `PopPaletteTests` の組と WCAG 計算で確認)。

## 影響

画面・UITest は変更なし。DesignTokenTests / PopPaletteTests の期待値だけ新値に更新(下の ADR-0501 章の表)。
