# ADR-0710: 素早さに反映した補正と、反映していない入力を判定の応答に返す(第1段)

- 状態: 採用(2026-10-02。判定レーンの判断。issue #235。範囲は「全て反映」でユーザー決定。第1段のみ実装)
- 日付: 2026-10-02
- 関連: ADR-0701 §2(素早さの補正はこだわりスカーフのみ)、ADR-0702 §2(追い風)、ADR-0708(未対応の印を方向ごとに必須配列で返す前例)、
  ADR-0700 §4(欠けた欄を 0 で埋めない)

## 背景
素早さの補正は追い風とこだわりスカーフだけで、`abilityId`・`itemId`・`field.weather` は calc-svc へ転送するだけで素早さには掛からない。
しかも応答からその旨が分からず、「素早さを上げる特性・天候」を指定した利用者に、反映済みに見える値が届く。

## 決定(第1段。上流・マスタは変えない)
`Matchup` に必須の配列を 4 つ足す(印が無いときは空配列。null・欠落にしない。ADR-0708 §3 と同じ)。

| 欄 | 意味 | 値 |
|---|---|---|
| `attackerSpeedApplied` / `defenderSpeedApplied` | 素早さの計算に**実際に効かせた**補正 | `rank`(素早さランク≠0)→`tailwind`→`choiceScarf` の順 |
| `attackerSpeedIgnored` / `defenderSpeedIgnored` | 指定されたが**反映していない**入力 | `abilityId`(特性が指定)→`itemId`(スカーフ以外の持ち物が指定)→`fieldWeather`(天候が none 以外**かつ**特性も指定) の順 |

- 「反映していない」は「素早さに影響する」とは限らない。judge は特性・持ち物の素早さ補正のデータを持たないので、**指定の有無**で印を付ける
  (影響しない特性でも `abilityId` が入る)。空配列は「素早さに影響する要素が無い」ことの保証になる。
- 天候だけ(特性なし)では印を付けない: 天候は特性が無ければ素早さを変えないため(ノイズにしない)。
- 状態異常(麻痺など)は入力に無いので、この欄にも現れない(契約の description に明記)。
- 値の enum は `SpeedFactor` / `SpeedIgnoredInput` として契約に置く。実数値の計算は変えない(既存の応答の数値は不変)。
- Web の判定画面は、空でない欄だけ「自分/相手の素早さに反映: …」「…は反映していません」の行を出す。

## 第2段(未実施。データレーンへの依頼として DECISIONS.md に記録)
素早さ補正を持つ特性(天候依存・状態依存)・持ち物を、マスタの正規化データ(balance の `abilities` read model の `effects` と同じ流儀)で持ち、
judge は ID の switch を持たずにデータから反映する。反映できた要素は `*SpeedApplied` に新しい値を足し、`*SpeedIgnored` から外す。
範囲は「全て反映」(ユーザー決定 2026-10-02。不要なら指摘される)。状態異常(麻痺)は入力欄(`status`)の追加も伴う。

## 却下した案
- 無視した入力を応答に出さず、契約の description だけで済ませる: 利用者の画面からは分からないまま。
- 特性・持ち物の ID を judge に直書きして反映する: ID の switch を持たない方針(設計書 §6)に反し、データレーンの責務を侵す。
