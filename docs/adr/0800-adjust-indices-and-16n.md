# ADR-0800: 調整の指数(火力指数・耐久指数)と HP の 16n / 16n-1 ライン

- 状態: 採用(2026-10-01。§1 はユーザー決定・回答。§2 以降はダメージ計算レーンの判断)
- 日付: 2026-10-01
- レーン: ダメージ計算(ADR 帯 `0800〜` を調整機能に割り当てる)
- 関連: docs/plan.md「AJ: 調整」、ADR-0004(4096 基準・五捨五超入)、ADR-0009(入力の作り方の型)、
  ADR-0010(逆算。総当たりの前例)、ADR-0117(入力の値域検査・補正値の範囲)、
  CLAUDE.md 絶対ルール2(engine は純粋)・ドメイン規約(SP・実数値の式・ハードコード禁止)

## 背景

「1つのアプリで調整まで完結」させるため、**自分の SP を決める**機能を足す(plan.md AJ)。既存の逆算(ADR-0010。
観測から相手の SP を推定)・判定(SP 固定での勝敗)とは向きが違う。その土台として、調整で通常使う
3つの量を engine に定義する。

1. 火力指数(攻撃側の強さを1つの数にしたもの)
2. 耐久指数(防御側の硬さを1つの数にしたもの)
3. HP の 16n / 16n-1 ライン(定数ダメージ・回復の端数を有利にする HP 実数値)

## 決定

### 1. ユーザー決定・回答(2026-10-01)

- 「16n」は **HP 実数値の 16n / 16n-1**(8n などは対象外)。
- 探索は **engine 内の総当たり**(逆算と同じ。WASM でも動かす)。
- 画面は **新タブ「調整」** に機能 2・3・4 をまとめる。
- 効率の基準は **「目標を満たす最小 SP」と「指数最大」の両方** を返す。

### 2. 火力指数

```
火力指数 = floor(攻撃実数値 × 威力 × 補正 / 4096)
```

- 攻撃実数値は技の分類で決まる: `physical` → A、`special` → C。`status` は指数を持たないので拒否する。
- 実数値は `RealStats`(SP と性格)で求め、**ランク補正は含めない**。指数は「育成で決まる強さ」を比べるための量で、
  戦闘中の一時補正は呼び出し側が `補正` に含めて渡す。
- `補正` は 4096 基準の整数 1 個(×1.0 = 4096)。タイプ一致・持ち物・特性・天候などは**呼び出し側が掛け合わせて渡す**。
  engine は技・持ち物・特性を直に参照しない(マスタのハードコード禁止。ADR-0005 / ADR-0013 と同じ考え方)。
  範囲は ADR-0117 と同じ `MinEffectModifier..MaxEffectModifier`(0 は拒否)。
- 威力は 1 以上。上限は `math.MaxInt32`(実数値 ≤ 337・補正 ≤ 2^21 で積が 64 bit 整数に収まる値。WASM の Go の int も 64 bit)。
- 丸めは最後に1回だけの floor。指数は比較用の量で、ダメージ式の丸め(ADR-0004)を再現するものではない。

**通説との照合**: 国内の育成論で使われる「火力指数 = 攻撃実数値 × 技威力 × 補正(タイプ一致 1.5・持ち物など)」に一致させた。
威力を含めない流儀(A × 補正)もあるが、技の威力差で同じ A の価値が変わることを1つの数で比べられるよう、
plan.md の要望(「攻撃実数値 × 威力ベース」)どおり威力を含める。小数の補正は 4096 基準の整数で持ち、float にしない(CLAUDE.md)。

### 3. 耐久指数

```
物理耐久指数 = floor(H × B × 4096 / 被ダメージ補正)
特殊耐久指数 = floor(H × D × 4096 / 被ダメージ補正)
```

- H は HP 実数値、B / D は `RealStats` の実数値(ランク補正は含めない。理由は §2 と同じ)。分類は技の分類で選ぶ
  (`physical` → B、`special` → D、`status` は拒否)。
- `被ダメージ補正` は「受けるダメージの倍率」を 4096 基準で渡す(等倍 4096、半減 2048 で指数が2倍)。
  防御側の持ち物・特性・壁などを**呼び出し側が掛け合わせて渡す**。範囲は §2 と同じ。
- 丸めは最後に1回だけの floor。

**通説との照合**: 「物理耐久指数 = H × B、特殊耐久指数 = H × D」は、ダメージ式の主項が `攻撃 / 防御` に比例し、
倒すのに必要なダメージが H に比例することから、確定数の比較に H × B(D) がそのまま効くという通説に一致する。
耐久を上げる補正(防御 ×1.5 の持ち物など)は「受けるダメージ × 1/1.5」とほぼ同じなので、被ダメージ補正で割る形に一本化した。4096 基準では厳密には同値でなく近似になる(例: 21045 で 31564 と 31567)。指数は比較用なので許容する
(B に掛ける形と割る形を両方持つと、同じ補正を二重に渡す誤りを作りやすいため)。総合耐久(H×B×D/(B+D))は対象外。

### 4. HP の 16n / 16n-1 ライン

- HP 実数値 = 種族値 + `HPStatOffset`(75) + HP の SP(0〜`MaxSPPerStat`)。HP は性格補正を受けない。
- 「16」は天候・どく・やけど・たべのこし等の HP の 1/16 を単位とする効果に由来するプロトコル定数で、
  engine の `HPLineDivisor = 16` に名前を付けて1か所に置く(ADR-0009 と同じく「入力の作り方の型」でマスタではない)。
  - **16n**: `HP mod 16 == 0`(1/16 回復・1/16 を単位にする効果で、同じ量を得る最小の HP)。
  - **16n-1**: `HP mod 16 == 15`(1/16 の定数ダメージ floor(HP/16) が一段小さくなる最大の HP)。
- 報告する量(`HPLines(baseHP, hpSP)`):
  - 現在の HP 実数値と、それが属するライン(16n / 16n-1 / なし)。
  - ラインの種類ごとに、**次の**ライン(SP が現在より大きい中で最小)と**前の**ライン(SP が現在より小さい中で最大)の
    HP・SP・SP 差(次は正、前は負)。HP の SP の範囲 0〜32 に無ければ「なし」。現在の SP 自身は次・前に含めない。
- 合計 66 の制約はここでは見ない(HP 単独の量)。他の能力との配分は AJ3 が合計 66 を守って扱う。
- 入力検査: 種族値は `MinBaseStat..MaxBaseStat`(ADR-0117)、SP は 0〜`MaxSPPerStat`。外れたら `ErrInvalidAdjustInput`。

### 5. engine の公開 API(AJ1)

`engine/adjust.go` に純粋関数で置く(時刻・乱数・I/O なし)。

| 関数 | 入力 | 出力 |
|---|---|---|
| `FirepowerIndex(attacker Individual, category MoveCategory, power, modifier int) (int, error)` | 攻撃側の個体・技の分類・威力・補正 | 火力指数 |
| `BulkIndex(defender Individual, category MoveCategory, damageModifier int) (int, error)` | 防御側の個体・技の分類・被ダメージ補正 | 耐久指数 |
| `HPLines(baseHP, hpSP int) (HPLineReport, error)` | HP 種族値・HP の SP | §4 の報告 |

- 個体は `Individual.Validate` を通す(SP 各 32・合計 66・種族値の範囲など)。失敗・分類・威力・補正の不正は
  `ErrInvalidAdjustInput` で包む(`errors.Is` で判別できる)。

### 6. AJ2・AJ3 の入出力の概略(詳細は各タスクの ADR 追記で決める)

- **効率の定義**(ユーザー決定 §1): 2つの基準を両方返す。
  - **最小 SP**: 目標(確定 n 発で倒す・確定で耐える)を満たす SP の組のうち、合計 SP が最小のもの。同点は指数が大きい方、
    さらに同点は能力の固定順(H, A, B, C, D, S)で辞書順に小さい方(結果を決定的にするため)。
  - **指数最大**: 与えられた SP の残りで、§2・§3 の指数が最大になる組。同点は合計 SP が小さい方、次に上と同じ辞書順。
- **AJ2(倒せる/耐える最小 SP)**: 入力は自分・相手の個体・技・場(`CalcDamage` と同じ)、目標の発数 n、確率しきい値
  (既定 100% = 確定)。出力は「しきい値を満たす最小の A/C の SP」または「最小の H と B/D の SP の組」と、そのときの確率。
  満たせないときは「満たせない」を返す(エラーにしない)。ダメージは `CalcDamage` の合成だけで求め、独自の式を書かない(ADR-0010 §1 と同じ)。
- **AJ3(SP 配分の提案)**: 入力は固定する SP(能力ごと)と、残り SP の使い方(耐久側: H/B/D、攻撃側: S と A/C)。
  出力は最小 SP の組と指数最大の組。合計 66・各 32 を守る。探索空間は各 0〜32 の総当たりで、2能力なら 33² 通り、3能力でも 33³ ≈ 3.6 万通りで
  WASM の同期実行に収まる。

### 7. AJ2: 倒せる/耐える最小 SP の探索(追記 2026-10-02。§6 の AJ2 を具体化)

`engine/adjust_search.go` に純粋関数で置く(時刻・乱数・I/O なし)。ダメージは `CalcDamage` の合成だけで求め、
n 発の確率は既存の確定数の算出(`ko.go` の16ロールの畳み込み)と同じ定義を使う。独自のダメージ式は書かない。

| 関数 | 探索する側 | 探索する SP | 目標 |
|---|---|---|---|
| `MinSPToKO(in AdjustSearchInput) (KOSearchResult, error)` | `Attacker`(自分) | 物理 → A、特殊 → C(1能力) | `Hits` 発で `Defender` を倒す確率 ≥ しきい値 |
| `MinSPToSurvive(in AdjustSearchInput) (SurviveSearchResult, error)` | `Defender`(自分) | H と、物理 → B / 特殊 → D の組 | `Attacker` の技を `Hits` 発受けて耐える確率 ≥ しきい値 |

**入力**(`AdjustSearchInput`): `CalcDamage` と同じ `Format`・`Attacker`・`Defender`・`Move`・`Field`・`Critical`・`TypeChart`、
目標の発数 `Hits`(1..`MaxAdjustHits` = 10)、しきい値 `ThresholdPercent`(%)。

- **しきい値**: 0 は既定の `DefaultAdjustThresholdPercent` = 100(確定)。それ以外は (0, 100]。比較は `確率 >= しきい値`
  (ちょうど等しければ満たす)。確率の単位は `KOChance.ChancePercent` と同じ %(表示用の確率は float でよい。ADR-0006)。
  100 の判定は乱数の最悪側で満たすこと(倒す側: 最小ロール × n ≥ HP、耐える側: 最大ロール × n < HP)と同値になる。
- **n 発の確率**: 倒す確率 = 16ロールを独立・等確率に n 回引いた合計が HP 以上になる確率。耐える確率 = 100 − 倒す確率。
  `ComputeKO` の `Hits`(倒すのに必要な最小の発数)とは別に、**指定の `Hits` で**求める(例: 確定2発の火力で Hits=3 なら 100%)。
- **固定する SP**: 探索する能力以外の SP・性格・持ち物・特性・ランクは呼び出し側が渡した値で固定する。探索する能力の入力値は
  無視する(上書きする)。固定側の SP の合計が 66 を超える・1能力が 0..32 の外なら `ErrInvalidAdjustInput`。
- **探索の上限**: 攻撃側は `min(32, 66 − 固定の合計)`。耐久側は H・B(D) とも各 0..32 で、`H + B(D) ≤ 66 − 固定の合計`。
  固定の合計がちょうど 66 なら上限 0(0 だけを試す。エラーにしない)。
- **入力検査**(すべて `ErrInvalidAdjustInput` で包む): `Hits` の範囲外、しきい値が負・100 超・NaN・Inf、変化技・威力 0 以下
  (分類から探索する能力が決まらない/ダメージが出ない)、両側の個体の `Validate` 失敗(探索する能力の SP を除いて検査する)。
  相性表の不足は `CalcDamage` のエラー(`ErrTypeChartMissing` など)を包んで返す。

**出力**:

- `KOSearchResult`: `Stat`(A / C)、`SearchLimit`、`Feasible`、`SP`、`ChancePercent`。
  `Feasible` のとき `SP` はしきい値を満たす**最小の** SP、`ChancePercent` はそのときの倒す確率。
  満たせないとき(上限まで振っても不可・タイプ相性で無効)は `Feasible=false`、`SP = SearchLimit`、`ChancePercent` はその SP での確率
  (到達できる最大の確率)。エラーにしない。
- `SurviveSearchResult`: `Stat`(B / D)、`SearchLimit`、`Feasible`、`HPSP`、`StatSP`、`TotalSP`、`BulkIndex`、`ChancePercent`。
  `Feasible` のとき、しきい値を満たす組のうち **§6 の順**(合計 SP が小さい → 耐久指数が大きい → 能力の固定順 H, A, B, C, D, S で
  辞書順に小さい = HPSP が小さい)で最初の組。耐久指数は §3 の被ダメージ補正を等倍(4096)にした `H 実数値 × B(D) 実数値`
  (補正は全候補で共通なので順序に影響しない)。満たせないときは `Feasible=false` で、耐える確率が最大の組を同じ順で選ぶ。
  タイプ相性で無効なら (0, 0) で 100%。
- **未対応の印**: 両方の結果に `Unsupported []UnsupportedMark`(ADR-0123)を持たせ、探索中の `CalcDamage` の印を入れる。
  印は SP によらず同じ(技・場・両側の個体で決まる)で、逆算の `ReverseCandidate.Unsupported` と同じ扱い。数値は印の有無で変えない。
- **常時最大振りにしない**: 結果は常に条件を満たす最小(上の順で最初)の組で、上限まで振るのは上限でしか満たせないときだけ。

**計算量**: 攻撃側は `CalcDamage` 33 回、耐久側は最大 33² = 1089 回。n 発の確率は1回あたり O(Hits × HP × 16)。
`MaxAdjustHits` = 10 は確定数の表示で実用になる範囲を覆い、この積を WASM の同期実行に収めるための上限。

**テスト**(`engine/adjust_search_test.go`): 境界(SP0 で既に満たす/上限でも不可/ちょうど閾値/しきい値の上下/
固定 SP と合計 66/無効相性/不正入力)と、威力・発数・しきい値・性格・分類・固定 SP の表で、
16^n 通りの数え上げによる独立の総当たりと全件一致することを確かめる性質テスト。

## 結果

- 指数の式は engine の1か所(`adjust.go`)にだけ置き、Web・iOS・calc-svc は engine(WASM / API)の結果を表示する。
- 技・持ち物・特性の補正値は engine が知らないので、補正の組み立て(タイプ一致か、どの持ち物か)は AJ4 以降の境界と
  クライアントの責務になる。AJ4 でその渡し方を API 契約として決める。
- 指数は比較用で、ダメージ計算の丸めを再現しない。「倒せるか・耐えるか」は AJ2 の `CalcDamage` による探索で判定し、
  指数だけで確定数を断定しない。
