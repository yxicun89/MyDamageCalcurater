# ADR-0311: 計算・逆算画面で特性を選べるようにする(issue #272 の Web 分)

- 状態: 採用
- 日付: 2026-10-01
- レーン: Web
- 関連: issue #272、ADR-0126(engine)、ADR-0214(API 契約)、ADR-0300(Web の engine 差し替え)、ADR-0301(API 実装)、
  ADR-0123(未対応の印)

## 背景

engine(WASM)と API は、防御側・相手側の特性の候補(0〜3件)を受けて、結果が同じ特性はまとめ、違えば行・候補を
分ける(ADR-0126・ADR-0214)。Web はまだ特性を送らず、画面は攻撃側に種族の先頭の特性を黙って入れるだけなので、
無効・吸収の特性を持つ相手に対する結果が 1対1 の計算と食い違う。

## 決定

1. **攻撃側(計算)/自分(逆算)の「特性」セレクト**: 選択肢は種族の特性(マスタで解決した日本語名、スロット順。
   解決できないものは捨てる)。既定は先頭。種族を変えたら先頭に戻す。選んだ特性が `Individual.ability` に入る。
   特性が1つの種族もセレクトを無効化せず、選択肢1つで出す。
2. **防御側(計算)/相手(逆算)の「特性」セレクト**: 「おまかせ(種族の全特性)」(既定)+種族の各特性。
   - おまかせ = スロット順に先頭 `MAX_ABILITY_CANDIDATES`(3)件を `defenderAbilities`(逆算は `unknownAbilities`)に渡す。
     4件目は落とす(ADR-0214 と同じ判断。engine の上限 3 を超えると常に失敗するため)。選択肢には4件目も出し、個別なら選べる。
   - 個別選択 = その1件だけ。防御側(相手)の種族を変えたらおまかせに戻す。
   - API 実装(`createApiEngine`)は、候補が**ちょうど1件**のときだけ `defenderOverride.abilityId` /
     `unknownAbilityId` を送り、2件以上・空・未指定は省略する(省略時は calc-svc が種族の全特性を解決する。
     おまかせで4件の種族は 3 件に切り詰めた候補を送らず、サーバーの同じ既定に任せる)。
   - 候補が空(特性が1つも解決できない)のときは送らない。従来とバイト単位で同じ要求になる(後方互換)。
3. **特性の無いマスタ**(選択肢が0件)ではセレクトを出さず、従来どおり `NO_ABILITY`・候補なし。
4. **結果の表示**: 行・候補の `abilityId` / `abilityIds` は DTO に写す(特性を送らなかった応答にはフィールドが無い)。
   結果が特性で分かれた行は特性名つきの別行(React key に特性を含める)。まとめられた行(`abilityIds` が複数)は
   まとめた特性の名前を「・」区切りで並べる(`domain/abilityLabels.ts` の `abilityNamesLabel`)。名前を出すのは
   `abilityIds` があり、かつ相手(防御側)の種族の特性が2つ以上、またはまとめた特性が2つ以上のとき。特性が1つだけの
   種族、`abilityIds` の無い応答は従来どおり名前を出さない。
   「未対応の印」(ADR-0123)の表示は変えない。
5. セレクトは `screens/AbilitySelect.tsx` を計算・逆算で共有する。種族を変えたときの選択のリセットは各画面の
   種族変更ハンドラ(ドロップダウン・検索解決・攻守入れ替え)で行う。結果の古い応答を出さないよう、完了済みの計算に
   特性(攻撃側の特性・防御側の候補)も持たせて入力との一致を比べる。
6. 要求の組み立て(`domain/requests.ts`)に `selectableAbilities` / `defenderAbilityCandidates` を置き、
   画面は選択肢とリクエストの両方をここから得る(同じ定義を複数箇所に書かない)。`MAX_ABILITY_CANDIDATES` は
   `domain/requestLimits.ts` に engine の `MaxAbilityCandidates` の写しとして置く。

## 検討した案

- 防御側の既定を種族の先頭1件にする: 隠れ特性などで無効になる種族を選び忘れたとき黙って誤る(ADR-0126 の案 A/B)。不採用。
- おまかせを API でも 3 件で明示送信する: 契約上は `abilityId` が1件しか送れない。省略でサーバーの既定に任せる。

## 影響

- 特性が効く技では行・候補が増える(最大 3 倍。ADR-0208)。画面は上限を超えない。
- iOS は API の追従後に同じ表示(別レーン)。

## 追記(critic 指摘、2026-10-01)

- `selectableAbilities` は同じ特性 ID の重複を初出だけ残す(engine は候補の重複を拒否し、`<option key>` も重複するため)。
- 既知の制限: 種族の特性の一部がマスタで解決できないとき、API モードのおまかせは省略(サーバーが全特性を解決)になり、
  画面の候補数とずれて特性名を出す判定が応答とずれうる。表示が冗長になるだけで計算結果は正しい。
