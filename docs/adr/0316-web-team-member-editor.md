# ADR-0316: Web の構築ビルダー(PR-A2)— メンバー編集の形(下書き・SP の検査・種族変更・保存)

- 状態: 採用(Web レーン、2026-10-02。P5-5b の受け入れ条件とテストの正。critic レビュー後に確定)
- 日付: 2026-10-02
- レーン: Web
- 関連: ADR-0309(構築ビルダーの骨格。`usesMaster: true`・クライアント・全置換 update)、ADR-0213(team-svc の契約。
  `TeamMember`・メンバー6体・技4・SP 各0〜32 合計66・ID はマスタと照合しない)、ADR-0311(特性の選択。
  `selectableAbilities`)、ADR-0304(種族の検索欄・`capabilities`・learnset の解決 A-13)、ADR-0308(訪れたタブを
  mount し続ける)、docs/requirements.md §2「構築ビルダー」

## 背景

PR-A1 で構築の一覧・作成・名前変更・削除が入った。PR-A2 はメンバー(最大6体)の編集を足す。種族・技・持ち物・特性・
性格・SP・テラスタイプを選ばせる UI は新規で、既存の計算画面と違い「保存する」操作を持つ。

## 決定

1. **編集領域は構築の行から開く**。`[「<名前>」のメンバーを編集]` で `role="region"` の編集領域が開き、同時に1つだけ。
   開くときに API は呼ばない(一覧の `Team` に `members` が入っているため)。`[編集を閉じる]` は未保存の編集を捨てる。
2. **下書き(`MemberDraft`)を持ち、保存のときだけ API の `TeamMember` にする**(`team/teamMember.ts` の純粋関数)。
   SP は入力途中の文字列のまま持つ(範囲外・空欄を一時的に保てる)。技は常に4枠(空きは null)で、送るときに詰める。
   ニックネームは編集 UI を持たないが、**読んだ値を落とさず送り返す**(update は全置換なので落とすと消える)。
3. **保存は編集領域に1つの `[メンバーを保存]`**(パーティ全体を `update(teamId, {name, members})`)。ADR-0309 §4 の流儀
   どおり**応答を待ってから**応答の `Team` で一覧を書き換える。楽観更新はしない(失敗時の巻き戻しを持たずに済み、
   失敗したときは**下書きをそのまま残して再送できる**ことが復旧になる)。成功は `role="status"` で知らせ、領域は開いたまま。
   失敗は `role="alert"` にサーバーの `message` を日本語のまま出す。送信中はボタンを無効にして二重送信を防ぐ。
4. **SP は直接入力の6欄(H・A・B・C・D・S)**。合計と残りを常に出す(`合計 66/66(残り 0)`)。範囲外は**入力を拒否せず
   明示エラー**にする(`aria-invalid` と `role="alert"`、保存を無効化)。1文字ずつ打つ途中(例: 32 を打つ途中の 3)を
   弾かないため。空欄は 0。整数 0〜32、合計 66 以下(契約と同じ。境界 0/32/33・66/67 をテストで固定)。
   体ごとに独立に検査し、どれか1体でも問題があれば保存できない。
5. **技は4枠・候補はその種族の learnset**。他の枠で選んだ技は無効にして重複を作らせない(契約が重複不可)。
   5つ目の枠は作らない。候補の名前はマスタ(`MasterData.moves` と、オンラインでは `resolveSpecies` が運ぶ技)で解決する。
6. **種族変更**: 特性は新しい種族が持つなら保ち、持たなければ先頭(`selectableAbilities` の順)に選び直す。技は新しい
   種族の learnset にあるものだけ前に詰めて残し、他は外す。持ち物・性格・SP・テラスタイプ・ニックネームは保つ。
   新しく追加した枠は**種族未選択**で始まり、選ぶまで保存できない(理由を `role="alert"`)。
7. **種族の選び方は capabilities に従う**。`speciesList` が true なら `<select>`、false(オンライン)なら
   `SpeciesSearchField` に `masterSearch` を渡す。後者では保存済みメンバーの種族を**開いたときに1体ずつ
   `resolveSpecies`**(特性・技の実体を得るため)。解決に失敗したメンバーは alert を出し、**内容は書き換えない**
   (保存すれば元のまま送る)。マスタに無い ID(種族・技)を持つメンバーも壊さず開ける(「不明なポケモン(<key>)」
   の選択肢で現在値を保つ)。
8. **持ち物・性格・テラスタイプ**は `<select>`: 持ち物 = (なし)+`MasterData.items`、性格 = `MasterData.natures`、
   テラスタイプ = (なし)+`MasterData.typeChart.types`(表示名は `typeNameJa`)。リストをコードに直書きしない。
   新しい枠の性格の既定は、無補正(plus/minus が null)の先頭、無ければ先頭。
9. **追加・削除・並べ替え**: `[メンバーを追加]`(6体で無効+理由の表示)・各メンバーの `[<n>体目を削除]`・
   `[上へ]`/`[下へ]`(先頭の上・末尾の下は無効)。削除は下書きの操作なので確認を挟まない(保存するまで何も消えない)。
   削除後のフォーカスは `[メンバーを追加]` に移す(消えた要素にフォーカスが残らないように)。
10. **a11y**: 各メンバーは `<fieldset>`+`<legend>`(「1体目」)、SP は入れ子の fieldset(「能力ポイント(SP)」)。
    コントロールのラベルはメンバーの group の中で一意(「ポケモン」「技1」〜「技4」「持ち物」「特性」「性格」
    「テラスタイプ」「SP H」…)。エラーは `role="alert"`、保存済みの知らせは `role="status"`。
11. **状態の保持**: 編集領域は `TeamScreen` の state にあり、ADR-0308 で画面が mount され続けるため、タブを切り替えて
    戻っても未保存の下書きが残る(e2e で固定)。
12. **特性セレクトは `AbilitySelect`(ADR-0311)を再利用**するが、この画面では「おまかせ」を出さない(個体は特性を1つ
    持つ)。選択肢が0件(特性の無いマスタ)なら出さず `abilityId` は null。`abilityId` が null で選択肢が1件以上の
  メンバーは先頭に「(未選択)」(value "")を出し、開いた時点で先頭の特性で黙って埋めない(select の表示と保存値を
  ずらさない。"" は null として下書きに戻す)。種族を選び直したときは従来どおり先頭に選び直す。

## 影響

- API は変えない(`api/openapi.yaml` は P5-4 のまま。`make gen` 不要)。
- `TeamScreenProps` に `master`(必須)と `masterSearch`(任意)が加わる。ルート表の `usesMaster: true` は動かさない
  (ADR-0309 §1)。PR-A1 の既存テストは `master` を渡す形に**機械的に**直す(アサーションは変えない)。
- 追加ファイル: `team/teamMember.ts`(純粋関数)、`team/teamMemberOptions.ts`(選択肢の組み立て)、
  `team/TeamMemberEditor.tsx`(下書き・保存)、`team/TeamMemberFields.tsx`(メンバー1体の欄)、`i18n/ja.ts` の
  `teamMemberText`、`test/fakeTeamClient.ts`。
- `screens/SpeciesSearchField.tsx` に任意の `selectedName` を足した(最初から種族が決まっている欄・親が選択を
  変える欄で入力欄に名前を出す。省略時は従来どおり)。既存の呼び出し側は変えない。
- 1体の保存できない理由は、種族未選択・技の重複・SP・種族の解決失敗を**1つの `role="alert"` にまとめて**出す
  (SP 33 のように欄の範囲外と合計超過が同時に起きても alert が複数並ばない)。
- Showdown 形式の入出力(判定レーンの `team/showdownFormat.ts`)とは別ファイル。取り込んだ結果を下書きに流し込む口は
  PR-A2 では作らない(統合は取り込み側の PR で `memberToDraft` / `draftToMember` を使う)。

## 却下した案

- **各メンバーを個別に保存する**: `PATCH` が無く(ADR-0213 §2)、全置換を何度も送るだけになる。保存の単位を1つにする。
- **入力時に範囲外を黙って丸める・拒否する**: 打ち間違いが見えず、1文字ずつの入力で途中の値を弾く。明示エラーにする。
- **楽観更新**: 失敗時の巻き戻しの状態が増える。ADR-0309 の「応答で書き換える」流儀に合わせる。
- **新しい枠の種族を先頭の種族にする**: オンラインは種族の一覧が無く、オフラインと挙動が分かれる。未選択で揃える。

## 既知の制限

- 保存中は名前変更の保存・[編集を閉じる]・メンバーの保存を互いに無効にする(update は全置換で、同時送信は一方が失われる)。
- SP 欄は `type="text" inputMode="numeric"` で、整数以外の文字列(`1e` など)は 0 に丸めず明示エラーにする
  (`type="number"` は途中入力が空文字になり、0 として黙って保存されるため)。role は spinbutton ではなく textbox。
- `SpeciesSearchField` の `selectedName` は、親が値を変えたとき入力中の文字を上書きする(オンラインで解決が
  遅れて届くと、入力し直し中の文字が置き換わりうる)。修正は見送り。
- 並べ替えは上下ボタンだけ(ドラッグ&ドロップは持たない)。
- ニックネームは編集できない(保持するだけ)。
- 種族の選択肢が数百件でも `<select>` のまま(オフラインの例データ・架空マスタは少数。実マスタの規模は P5 後半で判断)。
