# ADR-0134: 逆算の整数%観測を「切り捨て」の区間 [v, v+1) で照合する

- 状態: 採用
- 日付: 2026-10-03
- 関連: ADR-0010 §R2(観測の区間モデル)・§8(限界)、plan.md ブロッカー「観測%の丸め方」、
  docs/requirements.md「調整の推定(逆算)」、docs/test-strategy.md「逆算(調整推定)のテスト」、
  api/openapi.yaml(`Observation`)、CLAUDE.md 絶対ルール2(engine は純粋)・6(テストを弱めない)・
  ドメイン規約(float で近似しない)

## 背景

ADR-0010 §R2 は、実機の相手 HP 減少の整数%表示がどう丸められているか分からなかったので、
観測 v を「切り捨て・四捨五入・切り上げのどれで作られても真値が入る」開区間 (v−1, v+1) で照合していた。
この区間は幅 2% あり、1 つのダメージが隣り合う 2 つの整数%観測と両立する(情報を半分捨てている)。
§R2 は「規則が確定したら `Matches` の1か所で狭める」としていた。

2026-10-03 にユーザーが確認した: **実機の相手 HP 減少の整数%表示は切り捨て**。

## 決定

### 1. 整数%(`Observation.Percent`)は切り捨ての区間で照合する

真のダメージ割合を p = 100·damage / maxHP(%。float にしない)、観測を v(1..100)とする。
実機の表示は min(floor(p), 100)(100% で頭打ち)。したがって v を表示する p の集合は

```
1 ≤ v ≤ 99 : v ≤ p < v+1         ⇔ 0 ≤ x < maxHP      (x = 100·damage − v·maxHP)
v = 100    : p ≥ 100             ⇔ x ≥ 0
```

- 下端は閉、上端は開。ちょうど整数になる p(例 HP200 の 90 ダメージ = 45.0%)は v=45 と両立し、v=44 とは両立しない。
- **100% の扱い**: §R2 の「HP バーは 100% で頭打ちなので上側は開ける」はそのまま。下側は 99% 超から
  **100% ちょうど以上**に狭まる(切り捨てで 100 になるのは p ≥ 100 だけ)。瀕死・過剰打点は 100% の観測と両立する。
- **0%**: 1% 未満のダメージは実機で 0% と表示されるが、`Percent` は 1..100(0 は「未指定」)なので
  0% の観測は入力できない(従来どおり。`ErrInvalidObservation` / API の `minimum: 1`)。
  1% 未満のダメージは 1..100 のどの観測とも両立しない。
- 整数演算だけで判定する(x は int。float で近似しない)。

### 2. 0.1% 精度(`PercentTenths`)と実点数(`Damage`)は変えない

ユーザーの確認は**実機の整数%表示**についてだけである。`PercentTenths` は実機が出さない精度で
(他のツールや手計算の値を入れる経路)、出所の丸めは未確認のまま。根拠なく狭めると真値を落としうるので、
ADR-0010 §R2 の開区間 (v−1, v+1)(0.1% 単位)と 100.0% の頭打ちを維持する。`Damage` は完全一致のまま。

### 3. 距離(`Distance`)は「区間までの距離」にする

開区間 (v−1, v+1) では |x|(v からの距離)を使っていたが、区間が非対称になると p ∈ (v−1, v) が
「両立しないのに距離 0」になり、`Distance == 0 ⇔ Matches` が壊れる。整数%の距離を区間の外側までの距離にする。

```
Percent(両立しないとき): gap = −x(x < 0)/ x − maxHP(x ≥ maxHP。v=100 では起きない)
                         Distance = max(1, 10·gap / maxHP)   // 0.1% 単位。下限 1 は Damage と同じ理由
PercentTenths・Damage    : ADR-0010 §R2 のまま
```

- 単位は 0.1%(最大 HP 比)のまま。観測の種類が混在しても足せる。
- 下限 1: 上端ちょうど(x = maxHP)や HP が大きいときに整数除算で 0 に落ち、「0 ⇔ 説明できる」が壊れるのを防ぐ。
- 値の粒度が 1% 刻み(旧: (|x|/maxHP)·10)から 0.1% 刻みに細かくなる。`Mismatch` の値と、
  説明できない候補どうしの順序が変わりうる(説明できる候補の判定・`Ranges` の定義は §1 だけで決まる)。

### 4. 両側(defender / attacker)で同じ

`Matches` / `Distance` は (damage, maxHP) だけを見る。defender は相手の最大 HP、attacker は自分(既知側)の
最大 HP(`DamageResult.DefenderHP`)が分母になる。表示%は「最大 HP に対する減少量」で、
残り HP% の差(100 − 残り%)ではない。HP の実数値が分かる自分側は通常 `Damage`(実点数)で入れる。

**根拠と入力の注意(critic 指摘)**: 切り捨ての対象が「減少量そのもの」であることは、ユーザーの確認(2026-10-03。
「どの数字の切り捨てか」の質問に「減少量そのもの」と回答)に基づく。したがって、実機の**残り HP% の表示から
100 − 残り% で読み替えた値**は、実質「切り上げ」になり、この区間 [v, v+1) では真値を落とすことがある。そうした値は
入力として想定しない(`Percent` には減少量の表示をそのまま入れる。HP が満タンでない相手への2発目以降も、
残り%の差ではなく減少量として読めるときだけ使う)。UI のヘルプで同じ注意を出すかは、Web の逆算画面の改善時に検討する。

### 5. 変えないもの

- API の形(`Observation` の型・範囲・エラー)。説明文だけを更新する(`make gen` で生成物の説明が変わる)。
- 表示%(`DisplayPercentRangeTenths`。ADR-0010 §3.2)。観測%とは別概念のまま。
- 計算ロジック(`CalcDamage`)。ゴールデン(`make test-golden`)・`known_diffs.yaml` に影響しない。
- 探索空間・候補の件数(性格2 × 特性 × 持ち物)・順序の規則(ADR-0010 §R1・§R3・§R4)。

## 影響

- 同じ観測で説明できる SP の範囲は旧区間の**部分集合**になる(広がらない)。切り捨てで作った観測の真値は落とさない。
  `ExactCount`・`SPCount`・`Support` は減るか変わらない。候補の件数は変わらない。
- 四捨五入・切り上げで作った整数%は実機に現れない観測になり、真値を説明できないことがある(仕様)。
- テスト: 整数%の観測は切り捨てで作る(`percentObsRoundings`)。0.1% は3規則のまま(`tenthsObsRoundings`)。
  Recall(ADR-0010 §R5)の整数%の測定は切り捨てだけになる。しきい値・シード・ケース数は変えない。
- ADR-0010 §8「表示%の丸めが仮定」の限界は、整数%について規則が確定したことで解消する。

## 却下した案

- **整数%と 0.1% の両方を切り捨てにする**: 0.1% の出所の丸めは確認していない。狭めると真値を落としうる。
- **`Distance` を旧式 (|x|/maxHP)·10 のまま、両立しないときだけ下限 10 を置く**: v からの距離のままだと、
  区間の外側との近さ(44.9% と 46.0% のどちらが 45% の観測に近いか)を区間の非対称に合わせて測れない。
- **丸め規則を入力(enum)で選べるようにする**: 実機の規則は1つに確定した。選択肢は誤入力の余地を増やすだけ。
