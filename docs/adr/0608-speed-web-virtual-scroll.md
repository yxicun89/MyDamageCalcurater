# ADR-0608: 素早さ表(Web)の仮想スクロールと、右の位置マーカーの高さ揃え(F-06)

- 状態: 採用(2026-10-04。docs/usability-round2.md の F-06。ユーザー要望「右のポケモンの素早さを選んだ物と、左側の一覧が同じ高さ」「左の素早さ一覧は長すぎるので、スクロールに合わせて周辺だけを表示する」)
- 日付: 2026-10-04
- 関連: ADR-0604(素早さ画面)・ADR-0607(トリックルーム = 昇順の表)・ADR-0323(画面レジストリ)

## 背景
左の素早さ表は全段(全ポケモン x 調整で数百段)を DOM に出していて長い。また「自分」の位置は同速の段の強調か境界線だけで、右の自分の入力・結果と離れており、表のどこにいるかが分かりにくい。

## 決定
1. **依存を足さず、小さな自前の windowing にする**(`web/src/speed/speedWindow.ts`。DOM を知らない純粋関数)。理由: 必要なのは「縦1列・高さが計算で決まる・先読み付き」だけで、数十行で書ける。ライブラリの可変高さ対応・測定機構は不要で、テストも純粋関数で書ける。依存の追加(最新の安定版を完全固定)・監査の負担を避ける。
2. **段(同速グループ)の高さは行数だけで決める**: 同速の1行 = 24px 固定(名前・調整は折り返さず省略)、段 = 行数 x 24 + 余白16 + 隙間8、境界の行 = 32。幅に依存しないので全段の offset(累積和)を先に計算でき、スクロール位置から表示範囲を二分探索で引ける。実測(ResizeObserver)で測るのはビューポートの高さだけ。以前の「行が幅で折り返す」レイアウトは廃止(段の中は縦に並べる)。
3. **自分の位置は表の1行(アンカー)として同じ座標系に入れる**: 同じ実数値の段があればその段、無ければ境界の行を挿入(トリックルームの昇順の表では、自分より速い最初の段の前。ADR-0607)。表の並び・位置は従来どおり speed-svc の tiers の実数値と自分の実数値の直接比較で決める(Web で素早さを計算し直さない)。
4. **右の位置マーカー**: 表の右隣(同じ領域内)の列に、アンカーの offset - スクロール量 の高さで、アンカーの行と同じ高さの箱として置く。左のスクロールに追従する。アンカーが画面の外にあるときは上端・下端に張り付き(`data-state=above|below`、矢印の文字)、「自分の位置へ移動」ボタンでアンカーをビューポートの中央に寄せる(アニメーションなし。操作時の即時スクロール)。右の入力カードの結果表示(実数値・件数・同速一覧)は変えない。
5. **a11y**: 描画は `ul/li` のまま。画面外の段は出さないので、各段に `aria-setsize`(段の総数)・`aria-posinset`(元の順)を付ける(境界の行は数えない)。 仮想リストなので、読み上げ(上から順に読む操作)だけでは全件に到達しにくい。これは許容し、総数は `aria-setsize` で伝え、自分の位置へはボタンで移動できる。スクロール領域は `tabindex=0`・`role=group`・名前付きで、矢印キー・PageUp/Down でスクロールできる。マーカーは見た目の補助なので `aria-hidden`(読み上げは境界の行・強調された段・右の結果が担う)。
6. 描画範囲は見えている行の前後 6 行を先読みする。絞り込み・場の状態の変更で表が読み直されると、表が作り直されスクロールは先頭に戻る(従来の「ローディング表示」と同じ挙動)。

## 要望の解釈
要望は「右のポケモンの素早さを選んだ物と、左側の一覧が同じ高さ」。実装は、**左の表の右隣の列に、左の該当行と同じ高さ・同じ高さの箱の目印を置く**方式で、右の入力カード本体(モード・ポケモン・調整・結果)は左の行の高さには置かない。
- 選ばなかった案: 右の入力カード本体を、左のスクロールに追従させて該当行の高さに置く。理由: カードは入力欄と結果で縦に長く(モードごとに項目数が変わる)、スクロールに合わせて動くと入力中に操作対象が動いて読みにくい・押しにくい。狭い画面では左右が折り返して並ばない。iOS でも同じ体験にしやすいのは、目印(行と同じ高さの印)の方。
- ユーザー確認の余地: 目印では足りず、カード本体を揃えたい場合は、`TierViewport` が持つ `markerPlacement` の位置をカード側に渡す拡張で足せる(計算は共通)。
- 注意: 実機のユーザーの意図確認は未了(PR で確認を求める)。

## 長い名前・文字拡大
行は1行固定(24px)を保つ。長い名前は `text-overflow: ellipsis` で省略し、全文を行の `title` で出す。文字を大きくした場合は、1行に収まらない分が省略されるのを許容する(行の高さは増やさない。増やすと offset の計算が崩れるため)。調整名は省略しない。

## 結果・今後
- 見た目(色・丸み・アイコン)は F-12 の基盤で整える。今回は挙動と最小限のレイアウトだけ(CSS は既存のトークンのみ)。
- 高さの定数は TS(speedWindow.ts)が正で、インラインの style で CSS に渡す。デザイン基盤で行の見た目を変えるときは、ここの高さ(1行 24px・余白・隙間)を保つこと。
- iOS は別 PR(F-06 の iOS 分)で同じ体験にする。
