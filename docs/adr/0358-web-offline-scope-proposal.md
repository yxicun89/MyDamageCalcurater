# ADR-0358: オフラインで使えるものの範囲(提案)

- 状態: **提案**(ユーザーの決定待ち。2026-10-12。ec 経由のラウンド 4 の指摘「オフライン画面がテストデータしか無く使い道が無い」への案)
- レーン: Web(iOS は同じ範囲にそろえる)
- 関連: ADR-0313(オンラインで取ったマスタを IndexedDB に保存してオフラインで使う)、ADR-0301 §4、ADR-0002(実データを Git に入れない)

## 現状(事実)

- 既定はオンライン。オフラインは WASM で計算するが、マスタは「オンラインで一度引いた分」の IndexedDB キャッシュだけ。キャッシュが空なら架空データは出さず「一度オンラインで開いてください」の案内になる(ADR-0313 §4)。
- 架空の例データ(`master/example/`)は単体テスト用で、利用者の画面には出ない(`main.tsx` は使わない)。ただし開発サーバーや、キャッシュが空の初回では、種族が引けず「使えるものが無い」体験になりうる。
- キャッシュされるのは**自分が画面で選んだ種族**(とその特性・技)だけ。種族の一覧・技の一覧・持ち物の効果データは持たない。
- 素早さ・タイプバランス・判定・構築・記録は API 専用で、オフラインでは動かない。

## 使いにくい理由(仮説)

1. 初回や、まだ選んだことのない種族はオフラインで検索しても出ない。
2. 「オフライン」を選ぶと、何が使えて何が使えないかの説明が無い。
3. 直近の入力や条件がオフラインで残らない(お気に入りは API)。

## 案

### 案 A(推奨): 「オフライン用に保存」+ 使える範囲の明示 + テストデータの除去

1. **事前保存**: オンラインのときに「オフライン用にポケモンのデータを保存」ボタン(「このアプリについて」または計算の画面の設定)を置く。押すと、種族の一覧を pokedex API(`/api/pokedex/species`)でページ取得し、各種族を `resolveSpecies` 相当で順にキャッシュへ入れる(進捗表示つき・中断可・サーバー負荷のため直列)。クラウドの追加費用は無い(既存の API 呼び出し)。実データは端末の IndexedDB だけに置き、Git・サーバーには置かない(ADR-0002)。
2. **使える範囲の表示**: オフラインに切り替えたとき、画面の上に 1 行で「保存済み: ○種族。計算・逆算・調整が使えます。素早さ・構築のバランス・判定・お気に入りはオンラインで」と出す。API 専用のタブは、押す前に理由が分かるよう無効表示 + 理由。
3. **直近の入力の保存**: 計算・逆算・調整の直近の入力(攻守のポケモン・SP・性格・技・条件)を localStorage に 1 件保存し、再訪時に復元する(オフラインでも使える。端末の中だけ)。お気に入りのオフライン保存は後続(まず直近の 1 件で効果を見る)。
4. **テストデータ前提の表示を外す**: 画面・文言に例データの名前(「テストモン」等)が出ないことを検査するテストを足す。例データは単体テストと開発専用の起動(`npm run dev:example` のような明示の入口)だけに限る。

### 案 B: 何もオフラインに残さず、オフラインを廃止する
計算は常に API(または WASM をオンラインと同じ ID で使う)にし、モード切替を無くす。最小の UI だが、電波が悪い場所で使えなくなる。

### 案 C: WASM 用の小さな実マスタを同梱する
オフライン専用に、使用可能なポケモンの最低限のデータをビルドに同梱する。ADR-0002(実データを Git・イメージに入れない)に反するので不可。

## 影響と段取り(案 A)

- 段 1: 使える範囲の 1 行表示と API 専用タブの理由表示(小)。段 2: 直近の入力の保存。段 3: 事前保存(種族の一覧 API の使い方と負荷を pokedex レーンと確認してから)。
- iOS は同じ範囲(端末に保存済みの種族で計算)を SwiftData / ファイルで持つ。範囲の言い方をそろえる。
- 決定待ちの点: (a) 事前保存を作るか、(b) 直近の入力の保存の範囲(1 件か、お気に入りまで)、(c) 案 B(廃止)にするか。
