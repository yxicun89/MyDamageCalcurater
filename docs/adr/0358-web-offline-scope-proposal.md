# ADR-0358: オフラインで使えるものの範囲(提案)

- 状態: **承認(案 A、ユーザー決定 2026-10-12、段 1・2・3・4 実装済み)**。元は ec 経由のラウンド 4 の指摘「オフライン画面がテストデータしか無く使い道が無い」への提案
- レーン: Web(iOS は同じ範囲にそろえる)
- 関連: ADR-0313(オンラインで取ったマスタを IndexedDB に保存してオフラインで使う)、ADR-0301 §4、ADR-0002(実データを Git に入れない)

## 現状(事実)

- 既定はオンライン。オフラインは WASM で計算するが、マスタは「オンラインで一度引いた分」の IndexedDB キャッシュだけ。キャッシュが空なら架空データは出さず「一度オンラインで開いてください」の案内になる(ADR-0313 §4)。
- 架空の例データ(`master/example/`)は単体テスト用で、利用者の画面には出ない(`main.tsx` は使わない)。ただし開発サーバーや、キャッシュが空の初回では、種族が引けず「使えるものが無い」体験になりうる。
- キャッシュされるのは**自分が画面で選んだ種族**(とその特性・技)だけ。種族の一覧・技の一覧・持ち物の効果データは持たない。
- 素早さ・タイプバランス・判定・構築・記録は API 専用で、オフラインでは動かない。

## 使いにくい理由(仮説)

1. 初回や、まだ選んだことのない種族はオフラインで検索しても出ない。
2. 「オフライン」を選ぶと、何が使えて何が使えないかの説明が無い。
3. 直近の入力や条件がオフラインで残らない(お気に入りは API)。

## 案

### 案 A(推奨): 「オフライン用に保存」+ 使える範囲の明示 + テストデータの除去

1. **事前保存**: オンラインのときに「オフライン用にポケモンのデータを保存」ボタン(「このアプリについて」または計算の画面の設定)を置く。押すと、種族の一覧を pokedex API(`/api/pokedex/species`)でページ取得し、各種族を `resolveSpecies` 相当で順にキャッシュへ入れる(進捗表示つき・中断可・サーバー負荷のため直列)。クラウドの追加費用は無い(既存の API 呼び出し)。実データは端末の IndexedDB だけに置き、Git・サーバーには置かない(ADR-0002)。
2. **使える範囲の表示**: オフラインに切り替えたとき、画面の上に 1 行で「保存済み: ○種族。計算・逆算・調整が使えます。素早さ・構築のバランス・判定・お気に入りはオンラインで」と出す。API 専用のタブは、押す前に理由が分かるよう無効表示 + 理由。
3. **直近の入力の保存**: 計算・逆算・調整の直近の入力(攻守のポケモン・SP・性格・技・条件)を localStorage に 1 件保存し、再訪時に復元する(オフラインでも使える。端末の中だけ)。お気に入りのオフライン保存は後続(まず直近の 1 件で効果を見る)。
4. **テストデータ前提の表示を外す**: 画面・文言に例データの名前(「テストモン」等)が出ないことを検査するテストを足す。例データは単体テストと開発専用の起動(`npm run dev:example` のような明示の入口)だけに限る。

### 案 B: 何もオフラインに残さず、オフラインを廃止する
計算は常に API(または WASM をオンラインと同じ ID で使う)にし、モード切替を無くす。最小の UI だが、電波が悪い場所で使えなくなる。

### 案 C: WASM 用の小さな実マスタを同梱する
オフライン専用に、使用可能なポケモンの最低限のデータをビルドに同梱する。ADR-0002(実データを Git・イメージに入れない)に反するので不可。

## 影響と段取り(案 A)

- 段 1: 使える範囲の 1 行表示と API 専用タブの理由表示(小)。段 2: 直近の入力の保存。段 3: 事前保存(種族の一覧 API の使い方と負荷を pokedex レーンと確認してから)。
- iOS は同じ範囲(端末に保存済みの種族で計算)を SwiftData / ファイルで持つ。範囲の言い方をそろえる。
- 決定待ちの点: (a) 事前保存を作るか、(b) 直近の入力の保存の範囲(1 件か、お気に入りまで)、(c) 案 B(廃止)にするか。

## 決定と実装(2026-10-12。案 A を承認。段 1・2・4 を実装、段 3 は別 PR)

決定待ちの点: (a) 事前保存は作る(段 3。別 PR で pokedex レーンと種族一覧 API の使い方・負荷を確認してから)、(b) 直近の入力の保存は 1 件(お気に入りのオフライン保存は後続)、(c) 案 B(廃止)にはしない。

### 段 1: 使える範囲の 1 行と API 専用タブの理由
- オフラインのとき画面の上に 1 行(role=note)。「保存済み: ○匹。計算・逆算が使えます。素早さ・構築・お気に入り・調整はオンラインで」。保存済みの数は `MasterCacheStore` の `record.species` のキー数(`countSavedSpecies`。未保存・読めない・壊れた・版違いは 0 →「保存済みのポケモンはまだありません。オンラインで一度開くと保存されます。…」)。文言は `web/src/i18n/offlineScope.ts`(UI に「種族」は使わない。用語集)。
- 提案文の「調整」は、実装では**オンライン側**に置いた。調整は API 専用(`adjustClient`)で、計算・逆算だけが端末の WASM で動くため。判定は廃止済み(CB-7)なので入れない。
- API 専用の画面は画面の登録に `onlineOnly: true`(adjust・speed・team・favorites・balance)。オフライン中のこれらのタブには「オンラインのみ」を添え(`aria-describedby`。タブの名前は変えない)、控えめな見た目にする(トークンのみ)。
- **押せなくはしていない(提案文からの変更)**: ADR-0411 により、調整・構築の API 専用画面は計算する場所に関係なくオンラインのマスタで開ける。お気に入りはオフラインで開くと案内を出す(テストで保護)。押せなくすると既存の挙動・テストと矛盾するため、「見て分かる + 押せば案内」にとどめた。

### 段 2: 直近の計算入力の保存(範囲)
- **計算画面の主要入力だけ**。内容はお気に入りの作成本文(`FavoriteInput`: 攻撃側の種族・性格・SP・持ち物・特性・ランク・状態、防御側、技、場の条件、対戦の状態)で、復元もお気に入りの復元(`restoreFavoriteInputs`)を使い回す。`localStorage` の `pokecalc.lastCalcInput` に版つき(`schemaVersion: 1`)で 1 件を上書き。入力が揃っている(攻撃側が決まり SP・性格が正しい)ときだけ保存し、空で上書きしない。
- 復元はページを開いたとき(mount)だけ。お気に入りの復元要求があればそちらを優先。計算する場所を切り替えたあとに画面が作り直されるときは戻さない(ADR-0308 決定 3 の維持)。案内(status / alert)は出さない。今のマスタに無い種族があれば入力全体を捨てる(種族の無い持ち物・技だけが残る中途半端な状態にしない)。技・持ち物だけが無いときは引けた分だけ戻す。壊れた値・版違い・使えないストレージは無いものとして扱う。
- **逆算の入力・調整の入力・お気に入りの一覧は対象外**(後続。効果を見てから)。
- **ADR-0308 決定 4 の一部変更**: 「入力はストレージに書かない」を「計算画面の直近の 1 件だけ `localStorage` に書く(`sessionStorage` には書かない)」に改めた。`App.tabPersistence.test.tsx` の該当 1 件はこの変更に合わせて書き換えた(削除でも弱体化でもなく、新しい決定の検査に置き換え)。

### 段 4: テストデータ前提の除去
- 利用者の画面に例データの名前が出ないことを `master/exampleIsolation.test.ts` で検査する: 文言資源(i18n)に例データの名前が無い / 例データを読む本番コードは `App.tsx` の既定の取得口だけ / 本番の入口 `main.tsx` は使わない / `dev:example` 相当の npm script は作らない(現状維持)。

### 段 3 実装: オフライン用にポケモンのデータを保存(I-web-31)
- 置き場所: 「このアプリについて」の「オフライン用のデータ」節。ボタン「オフライン用にポケモンのデータを保存」は計算する場所がサーバーのときだけ押せる(オフラインでは無効にして理由を出す)。
- 一覧の取得: `GET /api/pokedex/species` は limit 上限 200・ページング無しなので、日本語名の前方一致(q)をカタカナの頭文字(清音・濁音・半濁音・ヴ、約 80 回)ごとに引き、key で重複排除する。上限(200)に達した頭文字は次の 1 文字で再分割する(最大 3 文字)。`searchSpecies` に任意の `limit` 引数を足しただけで、新しい API・openapi の変更はない。
- 保存: 各ポケモンを `resolveSpecies` で解決する。結果は既存の `createCachingMasterSource` が IndexedDB へ保存する(新しい保存経路を作らない)。保存済み(`record.species` のキー)は飛ばすので、中断・失敗の後は続きから再開できる。実データは端末の IndexedDB だけに置く(Git・サーバーに置かない。ADR-0002)。
- 負荷の根拠: **直列(同時 1 件)**。1 回の保存で増える要求は、一覧が約 80 回 + ポケモンごとに詳細 1 回と技の batch 1〜数回(実データ約 349 匹)。すべて既存の公開 API の GET で、保存済みは再度引かない。追加の費用・インフラはない。
- 進捗・中断・失敗: 「保存中 12 / 349」を `role=status`(polite)に出し、読み上げは 10 件ごとに間引く。中断ボタン(AbortController)。失敗は握りつぶさず `role=alert` で「保存済み: ○匹。もう一度押すと続きから保存します」を出す。端末に書けない失敗(容量不足など)は、25 件ごとに実際に保存されたかを読み戻して検出し、残りをサーバーから引き続けずに止めて案内する。実行中は中断ボタン、終了後は開始ボタンへフォーカスを移す。
- 既知の限界: 日本語名の頭文字がカタカナ以外のポケモンは一覧に入らない(現行のマスタには無い想定。増えたら頭文字を足す)。オフラインの「保存済み: ○匹」は表示のたびに読み直すので、保存後にオフラインへ切り替えれば最新になる(保存の完了時にも取り直す)。
