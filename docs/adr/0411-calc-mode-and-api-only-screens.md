# ADR-0411: 計算モードの意味(ダメージ計算の実行場所)と、API 専用画面のマスタ(issue #276)

- 状態: 採用(2026-10-02。ユーザー決定)
- 日付: 2026-10-02
- 関連: ADR-0301 §4(計算モード)、ADR-0304(オンラインの MasterSource)、ADR-0303(balance)、ADR-0705(judge)、issue #276・#210

## 背景
既定の計算モードはオフライン(WASM)で、そのとき App が画面へ渡すマスタは架空の例データになる。タイプバランスは例データの ID
(`9001-000`・`example-ability-none` など)を balance API へ送って 422 になり、応答の英語の内部メッセージ(`unknown abilityId: ...`)が
そのまま画面に出ていた。

## 決定
1. ヘッダーの切替が決めるのは「ダメージ計算を実行する場所」(オフライン = ブラウザの WASM / オンライン = API)だけ。全画面のデータの出どころではない。
   ラジオグループの名前を「計算モード」から「ダメージ計算の実行場所」に改める(選択肢の名前「オフライン(WASM)」「オンライン(API)」は変えない)。
2. API 専用の画面(タイプバランス・判定。素早さはマスタを使わない)は、計算モードに関係なく常にオンラインのマスタを使う。サーバーが
   知っている ID だけが通るため。`app/withOnlineMaster.tsx` が画面を包み、画面を開いたときにオンラインの取得口から1回読む。
   読めなければ日本語の案内と「再試行」を出し、オフラインの架空データへは落とさない(ADR-0301 §4 と同じ、自動フォールバックなし)。
   計算・逆算・構築の画面は従来どおりモードに従う。
3. balance の応答の `message`(英語の内部メッセージ)は画面に出さない。エラーコード(ErrorCode と Web 側の `balance_unavailable`)から
   `i18n/ja.ts` の `balanceErrorText` を引いて日本語の文言を出す。未知のコードは汎用の文言。
4. 判定画面は見出しをコードから日本語で出す既存の作り(JUDGE_ERROR_HEADINGS)のため、エラー文言はここでは変えない(補助行にサーバーの
   message が出る点は残る。別 issue 候補)。契約・生成物は変更しない。

## 結果
- オフラインのままでもタイプバランス・判定の選択肢はオンラインのマスタになる。オンラインのマスタが読めないときは API 専用画面だけが案内を出す。
- 既存テストのうち、balance のエラーが英語の message をそのまま出すことを確かめていた2件は、コードに対応する日本語の文言を確かめる形に変えた(意図の変更)。
