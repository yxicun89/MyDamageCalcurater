# ADR-0536: iOS の見た目の作り直し 第 1 弾(このアプリについて・お気に入り・履歴・お気に入りから読み込む)

- 状態: 採用(2026-10-12。仕様とテスト先行。実装は plan `I-ios-22`)
- 関連: ADR-0339(Web の方針 G-05)、ADR-0344(共通の部品)、ADR-0348(Web のお気に入り・履歴)、ADR-0349(Web のこのアプリについて)、
  ADR-0501 追記章「G-05 このアプリについて・お気に入り・履歴」、docs/design.md「見た目の作り直し方針(G-05)」「iOS の追い方(G-05)」、
  docs/ai-shared/decisions/2026-10-11-web-visual-policy-g05.md・web-g05-components.md・web-g05-about.md・web-g05-favorites.md
- 担当: iOS(`ios/PokeCalc` の 4 画面と `PokeCalcCore` の文言、`PokeCalcDesign` のシンボル名)

## 背景

docs/design.md「文を減らす決まり」は、画面の文字を「名前 / 短いラベル / 数値・結果 / 状態の一言」の 4 種にし、補足は 1 カード 1 行まで、
説明は「説明」ボタンの奥(1 段)に置く。Web は G-05 でこれを適用した。iOS は同じ方針を追う(「iOS の追い方(G-05)」の表)。
第 1 弾は、文の説明が多い順に「お気に入り・履歴」(記録タブ)と、その導線(計算画面の「お気に入りから読み込む」・「お気に入りに追加」・復元の案内)、
および例外の画面「このアプリについて」。他の画面(計算・逆算・調整・構築・素早さ)は後続の弾。

## 決定

1. **文の整理**(「現状の洗い出し」は ADR-0501 追記章の表)。文を置いてよい場所(エラー・取り消せない操作の確認・このアプリについて)は文のまま。
   空の状態は一言(旧: 追加のしかたの 2 文目を外す)。上限の文(`limitNote`)は件数の数値(`3/100件`)に。旧お気に入りの案内は短い印(`個体だけ(計算の条件なし)`)に。
   補足の文(履歴の注記・読み込みシートの注記・復元の限界)は「説明」ボタン(`CommonPartsText.help`)の奥に移す。文そのものは変えない。
2. **共通の部品の語**: `CommonPartsText`(`PokeCalcCore`)に `help` = 「説明」、`close` = 「閉じる」(docs/glossary.md「共通の部品の語」)。
   お気に入り・履歴の行の見える文字は「使う」「削除」(Web の `useShort`/`deleteShort`)。読み上げ名は従来どおり「「X」を計算に使う」、「「X」を削除」(見える文字を含む)。
3. **アイコン**: `PopSymbolNames`(`PokeCalcDesign`。テストできるよう Kit に置く)に Web の追加アイコンの割り当てを持つ。
   `PopSymbol`(アプリ)は同じ値を参照する。割り当て: close = `xmark`、open = `chevron.down`、history = `clock.arrow.circlepath`(既存)、
   help = `questionmark.circle`、up = `arrow.up`、down = `arrow.down`、minus = `minus`。View に SF Symbols の名前を直書きしない(`PopSymbol` 経由)。
4. **空の状態**は `ContentUnavailableView`(アイコン・一言・行動のボタン)。行動のボタンは「計算へ」(ダメージタブの計算へ移る)を
   お気に入り・計算履歴の空にだけ置く(よく計算する相手の空はアイコン + 一言のみ。3 つ並べて「計算へ」を出さないため)。シート(お気に入りを選ぶ)の空は「閉じる」。
5. **読み込み中は静止した表示**: `ProgressView`(回り続ける)を使わず、`PopNoticeView(.loading)`(静止したアイコン + 一言)にする(常時アニメ無し)。
6. **お気に入りの行**は 1 つのボタン(行全体を押すと計算に使う。識別子 `favoriteUseButton-<id>` を行のボタンに付ける)+ 末尾の「削除」。
   削除は 2 段階(確認の文 → 「削除する」/「やめる」)。確定は `.sensoryFeedback(.warning)`。calc の無い旧お気に入りは行を押せず、印だけ出す。
7. **このアプリについて**: 文面は変えない(例外)。3 節(非公式表示・データの出典・データの扱い)はカード + 見出し(注意・情報・丸の i のアイコン)。
   データの扱いの説明は 1 文ずつの箇条(`DeviceDataText.explanationBullets`。既存 3 要素を句点で分ける。文面・順序は不変)。
   削除の確認は見出しに注意アイコン、「削除する」にごみ箱アイコン、初期の VoiceOver フォーカスは「キャンセル」。
8. **お気に入りを選ぶシート**: 閉じるはアイコンだけ(36pt 以上・読み上げ「閉じる」)。行はポケモンの画像かエンブレム + 名前 + 副の情報。入口は短い名前(`攻撃側のお気に入り`)。
9. 守る決まり(ソース検査 `G05ScreenSourceRulesTests` が 4 つの View ファイルで見る): `ProgressView(`・`repeatForever`・`lineLimit`・`minimumScaleFactor`・
   色のリテラル/システム色・SF Symbols 名の直書きを使わない。パレット K のトークン(`PokeCalcDesign`)だけ。タップは 36pt 以上。視差効果を減らすでは演出を 0 秒(今の `PillButtonStyle` のまま)。

## 採らなかった案

- 削除を 1 段階のまま(現状): Web は取り消せない操作として 2 段階。方針の「取り消せない操作の確認」に合わせる。お気に入りは再追加できるが、100 件の上限があるため確認を置く。
- 補足の文を `caption` で 1 行に短くする案: 履歴の注記・復元の限界は 2 文の説明で、1 行にすると意味が欠ける。説明ボタンの奥が方針どおり。
- 「計算へ」を 3 つの空の状態すべてに置く案: 初回起動で同じボタンが 3 つ並ぶ。
