# ADR-0357: 能力ランクの入力をメーターにする

- 状態: 採用(2026-10-11。ユーザー要望のラウンド 4。ec 経由)
- 担当: Web(iOS は同じ見た目・色の意味・段数に揃える。`docs/ai-shared/decisions/2026-10-11-web-rank-meter.md`)

## 背景

ランク(-6〜+6)は、バトンタッチ・つるぎのまい等で「いまの段階」を手で入れる値で、数字より位置で見たい。
これまでは計算の「詳細」が − / + と文字、素早さが数値欄 + 増減ボタン、判定が 5 つの文字欄だった。

## 決定

1. **13 段のメーター**(`web/src/ui/RankMeter.tsx`)。左 6 = 下降・中央 = 0・右 6 = 上昇。範囲外の値は作れない。
2. **操作**: メーターのタップ / ドラッグ(横位置から最も近い段)、− / + ボタン、矢印キー(←↓ = -1、→↑ = +1)、PageUp / PageDown = ±3、Home / End = 両端。
3. **色**: 上昇 = `brand.primary`(空色系)、下降 = `warning`(橙系)、0 = `text.primary` の太い目印。
   赤は弱点・危険の意味と紛れるため使わない。耐性の `matchup.resist`(水色)とも区別するため、メーターの下降には使わない。
   色だけに頼らず、値を符号付きの文字(`+2` / `-3` / `±0`)でも出す。段の枠は `text.secondary`(AA)。
4. **読み上げ**: `role="slider"`、`aria-valuemin=-6` `aria-valuemax=6` `aria-valuenow`、`aria-valuetext="攻撃 +2"`(ステータス名 + 符号付きの数。0 は「±0」)。− / + は「<欄の名前>を上げる / 下げる」。
5. **適用範囲**: 計算の「詳細」(攻撃側・防御側)、素早さの自分のランク、判定の 5 欄。値は従来どおり -6〜+6 の整数で、API・要求の形は変えない。
6. 押せる範囲は 44px。横ドラッグのため `touch-action: pan-y`。常時アニメーションなし。

## 検査の付け替え(CLAUDE.md 絶対ルール 6)

数値欄からメーターになり、範囲外の値を作れなくなったため、「範囲外を入力するとエラー」を検査していたテストを
「両端で止まり、範囲外を送らない」に付け替えた(SpeedScreen.test / SpeedScreen.g05.test / JudgeScreen.test。理由は各テストのコメント)。
`judgeValidation` の範囲検査と関連テスト、素早さの `validateSelf` のランク検査は、状態が外から壊れたときの防御として残す(通常の操作では到達しない)。判定のメーターは誤り(`aria-invalid`・`aria-describedby`)を受けられる。

## 影響

Web: 計算・素早さ・判定の画面、`components.css`、i18n(`uiText.rank*Suffix`、`rankStatNameJa`)。API・engine の変更なし。
