# ADR-0339: 見た目の作り直し方針(文で説明しない UI)— G-05 / I-web-13

- 状態: 採用(2026-10-11。方針だけ。実装は I-web-13 の画面ごとの PR)
- 関連: docs/usability-round3.md G-05(G-01・G-04・G-06 も従う)、docs/design.md「見た目の作り直し方針(G-05)」、
  ADR-0334・0336(ポップ配色と共通の部品)、ADR-0337(用語集)、ADR-0325・0808(画像とエンブレム)、ADR-0521(iOS の共通の部品)、
  docs/plan/improvements/web.md I-web-13

## 背景

使用感フィードバック第 3 回(G-05)で、ユーザーから「今の画面は文で『ここに何がある』と説明している。
ボタン・アイコン・カード・色・動き(操作時のみ)で分かる、今のアプリ・ゲームのような UI に作り直したい」と要望があった。
F-12(ADR-0334・0336)で色と部品の土台はできたが、各画面はまだ select・ラジオ + ラベル・説明の文が中心のまま。
G-05 は Web が先に方針を決め、iOS・他レーン(G-01 技の選択肢・G-06 画像)はそれに従う。

## 決定

1. **文を減らす決まり**: 画面の文字は「名前・短いラベル・数値と結果・状態の一言」の 4 種類にする。文はエラー・空の状態・取り消せない確認・
   単位が分からない数値欄の説明・「このアプリについて」だけに置き、1 つの節の補足は 1 行を 1 つまで。説明が要るときは「説明」ボタンで 1 段だけ開く。
   「入力のラベル」(見えるラベル)は残す。
2. **アイコン**: 自作の線画(`Icon.tsx`)。アイコン + 短いラベルを基本にし、アイコンだけは広く通じる操作が繰り返し並ぶときだけ。
   アイコンだけの部品は読み上げ用の名前を必ず持つ。技の分類(ぶつり・とくしゅ・へんか)は自作アイコン、タイプはタイプバッジ(狭い場所はタイプ色の丸 + 名前)。
   公式のアイコンは使わない。ポケモン画像は ADR-0808、無ければエンブレム。
3. **部品**: 今の `.ui-*` を使い続け、ポケモンカード・タイル・区切りボタン・増減ボタン・ピッカー(下から出るシート / カードの下の面)・説明ボタンを足す。
   select は文字だけの短い選択肢に限って残す。タブは下の固定ナビにしない(画面が 5 つを超える)。
4. **画面ごとの方向**: docs/design.md の表(計算・逆算・調整・構築・タイプバランス・素早さ・お気に入りと計算履歴・このアプリ)。
5. **動き**: 操作への反応だけ。常時の動き(回る読み込みを含む)は置かない。視差効果を減らすで 0。触覚は iOS だけ。
6. **見やすさ**: 押せる範囲 24px 以上(主な操作は 44px 目安)、文字 4.5:1・部品 3:1、色はトークンだけ。今のコントラストの検査は残し、新しい組は足す。
7. **iOS**: 同じ方針を SwiftUI の部品で追う(design.md「iOS の追い方(G-05)」)。

## 理由

- アイコンだけで通じるものは少ないという調査(NN/g)から、「文を消してアイコンだけ」ではなく「文を短いラベル + アイコンに置き換える」にした。
- 2〜4 択の排他は区切りボタン、多い選択肢はチップ、長い一覧はシート(Material 3・Apple HIG の部品の使い分け)。選択肢そのものを見せると説明の文が要らない。
- 段階的に出すのは 1 段まで(段が深いと迷う)。
- 土台(トークン・部品・コントラストの検査・常時アニメーション禁止)は変えないので、既存のテストを弱めずに画面ごとに進められる。

## 影響

- Web: I-web-13 として画面ごとに PR を分ける(共通の部品 → 計算 → 逆算 → 構築 → 素早さ → タイプバランス → お気に入り → 調整 → このアプリ)。
  CSS の予算(30KB gzip)を守る。G-01(技の選択肢)は計算・逆算の PR でピッカーを使う。
- iOS: `docs/ai-shared/decisions/2026-10-11-web-visual-policy-g05.md` で連絡。
- API・engine・トークンの値は変えない。新しいトークン(シートの出入りの時間など)は実装の PR で design.md の表と一緒に足す。

## 未決

- なし(既定案で進める。技の分類のアイコンの形・ピッカーの細部は実装の PR で決め、ユーザーの動作確認で直す)。
