# ADR-0525: iOS の調整「目標から振り方を決める」(F-11 / I-ios-10)

- 状態: 採用(2026-10-11。実装済み)
- 日付: 2026-10-11
- レーン: iOS
- 関連: docs/usability-round2.md F-11、ADR-0331(Web の画面・文言・検査の正)、ADR-0177(engine の探索と calc-svc)、ADR-0250(調整 API)、
  ADR-0502(iOS の調整画面)、ADR-0509(メガ固定)、ADR-0521(ポップ部品)、`api/openapi.yaml` の `adjustGoals`

## 背景

調整で「このポケモンのこの技を耐えたい」「このポケモンの素早さを上回りたい」を数値だけで入れるのは手間、というユーザー要望(原文 16)。
Web は ADR-0331(段階 A)と ADR-0177(段階 B。`ADJUST_GOALS_ENABLED`)で、「相手を選んで目標の種類を選ぶ」モードを先頭に足した。
契約 `POST /api/calc/adjust/goals`(`adjustGoals`)は main にある。iOS は同じ語・流れで追従する(ADR-0331 §8)。

## 決定

### 1. 追加として入れる(置き換えない)

「調整の内容」の先頭に **「目標から振り方を決める」**(`adjustMode-goals`)を足す。従来の5つのモードと挙動・識別子・テストは変えない。
`AdjustMode` の enum は増やさない(`AdjustViewModel.isGoalsMode` を別に持つ)。5つの `allCases` を前提にした既存テストを変えずに済み、
従来のモードを選ぶと目標方式を外れる(`selectMode`)。Web は radio group の先頭に同じ語で置く(Web も置き換えではなく追加。差はない)。

### 2. 境界・契約

- **別プロトコル `AdjustGoalsService`**(`FavoritesService` 等と同じ流儀)。`AdjustService` に混ぜない(既存の準拠型・スタブを変えない)。
  実装は `APIPokeCalcService` の拡張(`APIPokeCalcService+AdjustGoals.swift`)と `MockAdjustGoalsService`。`AdjustFeature` が登録し、
  画面は無ければ従来の調整だけを出す(サービスは必須にしない)。
- ドメイン型は生成型の写し(`AdjustGoalInput`・`AdjustGoalsRequest`・`AdjustGoalsPlan`・`AdjustGoalOutcome`・`AdjustGoalsResult`)。nil は「キーを送らない」。
  `ceiling` は送らない(各能力 32。Web と同じ)。
- 要求の件数上限は `RequestLimits.maxAdjustGoals`(= 契約の `AdjustGoalsRequest.goals.maxItems` 6)。`make ios-check-request-limits` が契約と照合する。

### 3. 画面(ADR-0331 §5 と同じ語・欄)

- 目標のカード(「目標 n」)を追加順に並べ、「目標を追加」で足す(6 件で無効 + 「目標は 6 つまでです」)。外すと番号を詰める。目標が無い間は「目標を追加してください」。
- カードの欄: 種類(素早さを上回る〈既定〉・この技を耐える・この技で倒す)/相手のポケモン(検索シート)/相手の振り方/
  素早さ = 先に使う技(任意。説明文つき)/耐える = 相手の技 + 発数・確率/倒す = 自分の技 + 発数・確率/外す。
- 相手の振り方: 素早さ = 最速〈既定〉・準速・無振り(`AdjustSpeedPreset`。性格はマスタから規則で引き、無ければ別の性格で代えずに違反)/
  耐える = 攻撃側プリセット〈既定は特化〉(A/C は相手の技の分類)/倒す = 防御側プリセット〈既定は無振り〉(HB/HD は自分の技の分類)。
- 種類を変えたら相手は保ち、振り方・技・発数・確率は新しい種類の既定に戻す。相手を変えたら、新しい相手が覚えない技の選択は外す。
- **選択は sheet とチップ**(Menu 不使用): 種類は縦の選択肢、振り方・確率はピル、技は一覧の sheet(`adjustGoalMoveSheet`。先頭に「未選択」〈先に使う技は「使わない」〉)、
  発数は − / + のボタン。確率のピルは非 Lazy の折り返しレイアウト(`LazyVGrid` は画面外の子を作らず、AX5 の検査・巡回で引けなくなるため)。
  タップは 36pt 以上、`lineLimit` は使わない。
- accessible name は「目標 n の<見えるラベル>」(見える語を含む)。識別子の n は画面上の位置(1 始まり)。

### 4. 送信・検査・結果

- 「調整する」で `indices`(今の振り方)と `adjustGoals` を**並行して**呼び、両方そろってから出す(従来のモードと同じ)。最新の送信だけを反映し、古い応答で上書きしない
  (`LatestTaskRunner` + 世代番号)。入力・目標はエラーでも消さない。
- 検査の順(ADR-0331 §6 と同じ): 自分のポケモン・性格 → 固定 SP → 目標が 0 件 → 目標ごとに 相手 → 技 → 性格。違反は最初の1つだけ、API は呼ばない。
  文言は「目標 n: …」。
- 要求: `outspeed` は相手の個体だけ(先に使う技を選んだときだけ `moveId`)。`survive` は `moveId`(相手の技)+ `hits`、`ko` は `moveId`(自分の技)+ `hits`。
  `thresholdPercent` は 100 以外のときだけ。自分がメガならストーン(既存の固定)、**相手がメガ種族ならストーン**を持たせる(引けなければ送らない。ADR-0331 §1)。
- 結果: 「目標をすべて満たす振り方」/満たせないとき「目標に一番近い振り方」+「すべての目標は満たせませんでした」。能力ポイント・合計・実数値・残り。
  目標ごとの結果は**送信した時点の名前**(相手・振り方・技)から作る(送信後に入力を変えても文は変わらない)。文は Web の `outspeedOutcome`/`surviveOutcome`/`koOutcome` と同じ語
  (先に使う技のランク変化の前置きも同じ)。確率は 0.1% 単位の切り捨て。未対応の印は結果の上に1回。

### 5. 機能なしのとき(iOS 独自)

`ADJUST_GOALS_ENABLED` は Web の定数で、calc は目標 API のルートを常に登録している。404 `not_found` が返るのは、目標 API を追加する前の古い版のサーバー(gateway か calc にルートが無い)に当たったときで、契約の `default` として返る。この状態は画面を開き直すまで戻らない(ViewModel の寿命の間)。
その場合 **`goalsUnavailable` を立てて目標方式を引っ込め、従来の調整に戻し、「目標から振り方を決める機能は今は使えません。ほかの調整の内容をお使いください」を出す**。
入力は消さず、従来の調整はそのまま使える(絶対ルール5)。通信失敗・503(`master_unavailable` 等)は一時的な失敗なので、目標方式のまま日本語のエラーだけを出す
(`AdjustGoalsAvailability`)。`not_implemented`(501)は契約の `ErrorCode` に無く、受け取ると生成クライアントが decode エラーにするため判定に含めない。
Web にはこの案内が無い(Web は有効なサーバーを前提に定数で出している)。差として記録する。

### 6. モック・テスト

- `MockAdjustGoalsService`: 架空データ(9001〜9004)を要求の形に合わせて返すだけで探索・素早さの比較はしない。環境変数 `POKECALC_MOCK_ADJUST_GOALS` =
  未設定(すべて満たす)/`infeasible`(先頭の目標だけ満たせない)/`unavailable`(404)/`fail`(503)。モックの性格に「素早さ上昇」を1件足した(最速のプリセット用)。
- 単体: ViewModel(追加・削除・上限・種類の切り替え・検査の順・要求の組み立て・メガ・結果・機能なし・古い応答)、API 写像(パス・ヘッダー・本文・応答・エラー code)、
  モック、文言、素早さのプリセット。XCUITest: 代表シナリオ(素早さ + 倒す → 結果・外して番号が詰まる/耐える・発数・確率)・上限・満たせない・機能なし・一時失敗・AX5 の横あふれ。

## 却下した案

- `AdjustMode` に `goals` を足す: 5つの `allCases` を前提にした既存テスト(文言の順・全モード巡回)を書き換えることになる。別の状態にして、置き換えず追加にした。
- `AdjustService` にメソッドを足す: 既存の準拠型(テストのスタブ)が壊れる。別プロトコル。
- 機能なしを定数で隠す(Web の `ADJUST_GOALS_ENABLED`): iOS はサーバーの設定と別にビルドされるため、実際の応答で判断する。
- `LazyVGrid`・`Menu` を使う: 上記のとおり。

## 結果

- 契約・engine・services・Web は不変。iOS のみ。
- 後続: 目標の順序の入れ替え(満たせないとき前の目標を優先する。decisions/2026-10-04-calc-adjust-goals-search.md)は使用感を見て判断。F-13(文言のやさしい言い換え)で語が変わるときは Web と同時に。
