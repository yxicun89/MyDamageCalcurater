# ADR-0529: iOS のポケモン画像を各画面に出す(共通部品の一般化) — G-06

- 状態: 採用(2026-10-11)
- 関連: docs/usability-round3.md G-06、ADR-0508(`ImageCatalog`・`SpeciesImageView`。P8-1c)、ADR-0808(manifest と `/images/*`)、ADR-0810(個人利用の画像の入手)、ADR-0343(Web の同じ作業)

## 決定

1. **共通部品は既存の `SpeciesImageView` を一般化して使う**(新しい部品は作らない)。`fallback` を差し替えられる形にし、
   直径も指定できる。既定は従来どおり直径 40 のタイプ色エンブレム。素早さ系は直径 32 の `SpeedEmblem` を fallback にする。
2. **足した場所**(従来: 計算の攻撃側/防御側・検索の行・構築一覧・タイプバランスのカード・逆算と構築編集のヘッダー)に加えて、
   素早さ表の各行・素早さの相手選択シートの行・素早さ画面の選択中ポケモン・判定結果の各行(`SpeedEmblem` 経由)、
   お気に入りの行・計算履歴の行(攻撃側と防御側)・よく計算する相手の行。タイプが行に無い画面(お気に入り・履歴・相手)は中立色のエンブレム。
3. **画像のキーの出どころ**: 素早さは `pokemonId`(= 種族キー)を `SpeedEntryDisplay.speciesKey`、判定は要求の候補の speciesKey を
   `JudgeMatchupDisplay.speciesKey` に持たせた(どちらも省略可。無ければエンブレムのまま)。
4. **URL の規則は Web と同じ**: `基点 URL + /images/ + manifest の相対パス`。相対パスは `.webp` で終わるものだけ(新規。従来は拡張子を見ていなかった)。
   `..`・絶対・scheme・`%` などは従来どおり画像なし。manifest は最初の引き当て時に 1 回(失敗も保持)。取れない・不正・キー無しはエンブレムで、エラーは出さない。
5. **ステイル応答**: キーが変わったら前の画像を消し、引き当ての完了時にキャンセル済みなら捨てる(`.task(id:)`)。
6. **アニメーション**: 付けない(フェードインも入れない。常時アニメ禁止・操作時のみの原則に対し、画像は表示時に一度出るだけなので素直に即時表示)。
   キャッシュは `AsyncImage` が使う `URLCache.shared` に任せる。
7. **アクセシビリティ**: エンブレムは従来どおり隠す。画像は identifier だけ付けた装飾の要素(名前は隣のテキストが読む)。XCUITest で枠を見るためで、ADR-0508 から変更なし。
8. モック: `POKECALC_MOCK_IMAGES=1` で 9001-000・9003-000 だけ架空の単色 PNG(data URL。コードで生成)。実ネットワークに出ない。

## 影響

- `api/`・`services/`・`web/` は不変。実画像・実データはコミットしない。
- 既存テストの期待値は変えていない。`.webp` 以外の相対パスを画像なしにしたのは新規の規則(`ImageURLWebpOnlyTests`)。
