# ADR-0355: 配色を「空色と白」にする(K 案)— ADR-0334 の値の置き換え

- 状態: 採用(2026-10-11。ユーザー決定。ec レーン経由)
- 関連: ADR-0334(ポップ配色のトークン名・組み合わせ表。**名前と表の構造は変えない**)、ADR-0300 §4(iOS と同じ名前・同じ値)、docs/design.md「ベース」「タイプ色」「タイプバッジ」「ポップ配色」

## 背景

ユーザーが現行の配色(青 + 黄 + クリームから水色へのグラデーション)を「気持ち悪い」と評し、5 案から「K. 空色と白」を選んだ。

## 決定

1. **値だけを差し替える**。トークン名・用途・コントラストの組み合わせ表(popPalette.test.ts の CONTRAST_PAIRS)・部品の CSS は変えない。
2. ライト: 背景 `#EEF6FF`、カード白、主色 `#1F68D8`(指定の `#2F80ED` 系は白に対して 3.87:1 で AA に届かないため、同じ色相で明度だけ下げて 5.21:1)、
   文字 `#14243A`(濃い紺)、補足 `#4A5A70`、表の見出し・ゼブラ・ホバーも空色寄りに。
3. ダーク: 紺寄りの暗色(背景 `#0B1320`、カード `#16202F`、文字 `#EAF1FB`、補足 `#A3B1C6`、フォーカス・主色 `#7FB0FF`)。
4. **背景のグラデーションは単色寄りにする**: 名前(`bg.gradient-start/end`)は iOS と共有し検査が参照するため残し、値の差をごく小さくした(`#F2F8FF` → `#E6F1FD`)。
5. **タイプ色は彩度を 0.95 倍**(HSL の S だけ)。タイプバッジの文字色は規則(黒か白のうちコントラストが高い方)を再計算した結果、かくとうだけ白になった(4.60:1)。
6. `on.accent`・`brand.accent`・`success`・`warning`・`info`・`danger` の値は変えない(新しい背景に対しても全組み合わせの検査が通る)。

## 既存テストの扱い(絶対ルール 6)

`typeBadgeContrast.test.ts` の「text.primary では 4.5:1 に届かないタイプがある」は、期待する一覧を `[かくとう, どく]` から `[かくとう, どく, エスパー, ドラゴン]` に更新した。
text.primary の値とタイプ色が変わったための**データ依存の一覧**で、検査の主張(黒系・白系を選び分けるだけでは足りず、純黒・純白が要る)は同じか強くなる。他のテストは変更なし。

## iOS への影響

iOS の `PokeCalcDesign`(ColorToken・typeInk)を docs/design.md の同名トークンの新しい値に合わせる。
