# ADR-0348: お気に入り・計算履歴の作り直し(G-05 / I-web-13g)

- 状態: 採用(2026-10-11)
- 関連: ADR-0339(方針)・ADR-0344(共通の部品)・ADR-0327(お気に入り)・ADR-0338(計算履歴)・ADR-0333(計算に使う)

## 決めたこと

docs/design.md「画面ごとの方向」のお気に入り・計算履歴の行を実装した。方針に無かった細部を決める。

1. **行を押して使う = 使うボタンの押せる範囲を行全体へ広げる**(`::after` の全面オーバーレイ)。ボタンは 1 つのまま(Tab の停止点・読み上げ名は増えない)。
   お気に入りの削除・確認のボタンは前面(z-index)に置き、行の押下では誤って使わない。押している間にオーバーレイが縮まないよう、使うボタンの押下の縮みは止め、縮みは行の側にだけ付ける。
2. **「使う」「削除」はアイコン + 短い文字、読み上げ名は従来の長い名前**(「「X」を計算に使う」「この計算を使う」「「X」を削除」)。見える文字「使う」「削除」は名前に含まれる(WCAG 2.5.3)。
   このため ADR-0333 §2 の「見える文字 = 名前」は「見える文字は名前に含まれる」に変わった(`FavoritesScreen.restore.test.tsx` の 1 件を付け替え)。削除の 2 段階の確認は変えない。
3. **履歴の行**: 攻撃側 → 防御側は縦に並べた 2 つの画像かエンブレム(狭い幅であふれない)、結果の % は大きい数字(`font-size.title`)、その下に装飾のバー
   (計算画面と同じ意味: 最大 % の幅・100 で止まる。技のタイプが分からない(マスタを使わない)ので色は text.secondary)、日付は小さな補足。技のタイプの印は付けない(同じ理由)。
4. **空の状態は大きいアイコン(48)+ 短い一言**。文を「お気に入りはまだありません」「計算履歴はまだありません」に短くした(旧: 計算画面へ誘う 2 文目を外した)。
   **「計算へ」のボタンは付けない**: 画面に計算タブへ移る口(コールバック)が無く、足すと App・画面の定義・env の配線になる(「新しい配線なし」の条件)。後続候補。
5. 読み込み中・オフラインはアイコン + 一言の `ui-notice`、失敗は従来どおり role=alert のまま、アイコンを足した(節の中に閉じる)。「もっと見る」は下向きの山のアイコン付き。
   「攻撃側だけ…」の補足(バッジ)は旧お気に入り(calc なし)だけの 1 行として残した。

## 影響

新しい色の組は無い(装飾のバーは border.hairline の上の text.secondary、% は text.primary / surface.card で既存の検査の組)。常時動くアニメーションは無い。
既存テストの付け替えは 1 件(上の 2)。空の案内の文は定数を参照するテストばかりで、変更の影響は無かった。
