# ADR-0356: Web のナビゲーションを 4 区分のタブにする(下部固定 + 区分内の区切り)

- 状態: 採用(2026-10-11。ユーザー決定の案 B。実装は後続 PR)
- 関連: docs/ai-shared/decisions/2026-10-11-navigation-options.md(案 A/B/C と調査・根拠。iOS と共通の決定)、ADR-0300 §1(URL ルーティング)、
  ADR-0308(訪れたタブは mount したまま保持)、ADR-0323(画面の登録)、ADR-0330(hidden)、ADR-0421(タイプバランスを構築へ統合)、
  ADR-0339(G-05 の方針)、docs/design.md「共通の部品」のタブの行

## 背景

7 つの画面が横一列のタブに並び、狭い幅では横スクロールになる(issue #333)。iOS はホームに全機能が並び、移るたびにホームへ戻る。
ユーザー要望は「ホームへ戻らずに移りたい」。調査と案の比較は共通の決定記録のとおりで、案 B(関連画面をまとめた 4 区分)を採った。
右下の丸ボタンで画面を移る案(F)は、ユーザーの訂正で「機能の中の操作用」の意味になったため、画面間の移動には使わない。

## 決定

1. **4 つの区分**: ダメージ(計算・逆算・調整)・構築(タイプバランスを含む)・素早さ・記録(お気に入りと計算履歴)。判定は hidden のまま。
   「このアプリについて」は今のフッターのリンクのまま(iOS は各区分の右上のアイコン)。
2. **URL は変えない**: `/calc` `/reverse` `/adjust` `/team` `/speed` `/favorites` を残し、画面 ID から区分を導く(`defineScreen` に `group` を足す。
   区分の表示名・並びは登録側で決める)。直接開く・戻る/進む・ブックマークは今のまま(ADR-0300 §1)。
   旧 `/balance` は `/team` に置き換える(履歴を増やさない)。タイプバランスの別画面は無くなり、構築編集の中の節になる(ADR-0421)。
3. **上位のタブは 4 つ**(`role="tablist"`、名前「画面」)。ダメージ区分の中だけ、下位のタブ(`role="tablist"`、名前「ダメージの種類」。計算 / 逆算 / 調整)を
   画面の上部に置く。下位は既存の `.ui-tabs` と同じ部品で、`role="tab"` を使う既存のテスト・読み上げの作法を保つ。
   区分が 1 画面だけ(構築・素早さ・記録)のときは下位のタブを出さない。
4. **幅で置き場所だけを変える**: 狭い幅(目安 600px 未満)は上位のタブを画面の下に固定、広い幅は今の上部のまま。同じ部品で CSS だけを切り替える。
   下部固定は、セーフエリア(`env(safe-area-inset-bottom)`)・本文の下余白(固定バーに隠れない)・シート(モーダル)が前面に出ること・
   ソフトキーボードと重ならないこと(入力中は隠れてよい)を満たす。4 つなので 320px でも横スクロールが要らず、issue #333 の例外は不要になる。
   タップの的は 44px 以上。
5. **入力は全区分で保つ**: 訪れた画面は mount したまま hidden にする(ADR-0308 を区分内の下位タブにも適用)。
6. **文言**: 区分名は ダメージ / 構築 / 素早さ / 記録(用語集 docs/glossary.md に足す)。下位のタブの名前は今の 計算 / 逆算 / 調整 のまま。
   「お気に入り」は記録の中の見出しとして残す。
7. **動き**: 切り替えは操作時の押下の反応だけ(常時動くアニメーションを入れない)。

## 実装の段階(それぞれ別 PR)

1. タイプバランスのタブを外す(`hidden`)・旧 `/balance` を `/team` へ・旧テストと e2e の付け替え。
2. 区分(`group`)を登録に足し、上位 4 タブ + ダメージの下位タブ。狭い幅の下部固定。docs/design.md の「下の固定ナビにはしない」の行を改める。
3. e2e・a11y(axe)・横あふれ(320px)の検査を 4 区分に合わせる。

## 既存テストの扱い(絶対ルール 6)

タブの本数・名前・巡回順を前提にするテスト(`App.test.tsx` の Home/End、`App.masterSources.test.tsx` の一覧、`routes.test.ts`、`screenRegistry.test.ts`、e2e)は、
ユーザーが画面構成の変更を決めたために期待値が変わる。意図(巡回できる・選択とフォーカスが一致する・失敗中も選べる)は同じ入力で保ち、
変更した期待値を各 PR の本文に一覧と理由つきで書く。検査を消して通さない。

## 代替案と不採用の理由

案 A(下部 5 タブ + その他)は HIG が避けよという More に当たり、調整・お気に入りが隠れる。案 C(今のホームを残す)は要望に応えきらない。
詳細は共通の決定記録。
