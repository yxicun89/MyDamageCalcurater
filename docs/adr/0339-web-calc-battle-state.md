# ADR-0339: 計算画面の「対戦の状態」(残りHP・多段の回数)— I-web-13

- 状態: 採用(2026-10-11。ユーザー了承。データレーンが実装)
- 関連: ADR-0144(技の機構の段階3。`CalcRequest.battleState`)、ADR-0333(お気に入りから計算を開く)、ADR-0338(計算履歴)、
  ADR-0337(用語集)、docs/ai-shared/decisions/2026-10-10-data-move-mechanisms-stage3.md(最終形)

## 決定

1. **欄**: 計算画面の「詳細」の下に折りたたみ「対戦の状態」(既定は閉じる。設定中は閉じていても「(設定中)」を付ける)。中に
   「攻撃側の残りHP」(実数値。横に「/ 最大」と割合〈小数第1位・切り捨て〉)・「防御側の残りHP」(割合〈%〉。決定 4)。技の欄の下に、範囲の多段技
   (`mechanismParams.multiHit` の min < max)のときだけ「回数」(既定・min..max 回)。文言は `battleStateText`(i18n/ja.ts)。
2. **送る形**: `domain/battleState.ts` の `resolveBattleState` が1か所で決める。空・最大と同じ値(満タン)・既定の回数・範囲の多段でない技の回数は
   入れず、何も無ければ `battleState` を付けない(従来と同じ要求)。範囲外・整数でない値は欄の下に「1〜{最大}で入力してください」を出し、計算を送らない(結果も出さない)。
3. **計算の経路**: 計算画面は一括計算(`calcBulk`。5 行 × 持ち物 × 特性)で動くが、一括には `battleState` を足さない(ADR-0144)。
   そこで状態を指定したときだけ、一括の応答の各行を `battleState` つきの `calc`(1対1。WASM / `POST /api/calc`)で計算し直して行の結果を差し替える
   (`domain/battleStateRows.ts`。防御側は行の SP・性格・持ち物・特性で組む。同時に走らせるのは 4 件まで)。指定が無いときは従来どおり一括だけ。
4. **防御側の残りHPは割合(%)で入力する**(critic 指摘。計算画面は行ごとに防御側の SP が違う一括計算で、最大 HP が行ごとに違うため、
   1つの実数値は意味が揺れる)。1〜100 の**整数**(小数は受け付けない。用語集・decisions の「%で入力」に合わせ、割合は整数で足りる)。空・100 は満タンで送らない。
   行ごとの実数値への換算は `max(1, floor(行の最大HP × % / 100))`(行の最大 HP は一括の結果の `defenderHP`)。換算結果がその行の最大 HP 以上なら満タンとして
   その行には防御側を付けず、その行に付けるものが無ければ計算し直さない(一括の結果のまま)。同じ % なら H振り行も無振り行も同じ割合になる。
   **iOS も同じ規則に揃える**(decisions に明記)。要約は「防御側 HP n%」。攻撃側は実数値のまま(最大 HP = 種族値 + 75 + SP。範囲 1..最大。
   最大 HP が変わって残り HP が最大を超えたら最大に合わせて「最大HP(n)に合わせました」を出し、利用者が最大超を入力したときは丸めず誤り)。
5. **前提の表示**: 状態を指定した結果の近くに「対戦の状態: 攻撃側 HP a/A・防御側 HP d/D・n 回」(指定した項目だけ)。
6. **回数のリセット**: 回数は選んだ技に結びつけて持ち、技を変えると「既定」に戻る(攻守入れ替え・攻撃側の変更で技が変わったときも同じ)。
7. **保存・復元**: お気に入りの `calc.battleState` は計算要求そのもの(実数値)で保存する。行が特定できないので、防御側は**無振り(SP 0)の最大 HP
   (種族値 + 75)の行**に換算した実数値を保存する(`savedBattleState`。最大が満タンになる・無振りの最大 HP が分からないときは防御側を保存しない)。
   復元は逆に、保存された実数値に届く**最小の整数%**に戻す(`ceil(HP × 100 / 無振りの最大HP)`、上限 99。最大以上・最大が分からないときは空 = 満タン)。
   行が特定できないための近似で、戻した % を換算し直すと保存値以上になる(99% が上限なので最大-1 だけは 1 小さくなる)。履歴は同じ復元の経路。
   攻撃側・回数はそのまま往復する。一括・逆算・調整には付けない。
8. 常時アニメーションなし。入力は label・aria-describedby・aria-invalid、誤りは role=alert。色は tokens.css のトークンだけ。

## 逸脱

- decisions の表は防御側を実数値の入力(「%で入力」を任意の切り替え)としていたが、行ごとに最大 HP が違うため**割合を唯一の入力**にした(決定 4)。
  保存形は実数値のまま(契約どおり)で、復元は近似(決定 7)。
