# ADR-0339: 計算画面の「対戦の状態」(残りHP・多段の回数)— I-web-13

- 状態: 採用(2026-10-11。ユーザー了承。データレーンが実装)
- 関連: ADR-0144(技の機構の段階3。`CalcRequest.battleState`)、ADR-0333(お気に入りから計算を開く)、ADR-0338(計算履歴)、
  ADR-0337(用語集)、docs/ai-shared/decisions/2026-10-10-data-move-mechanisms-stage3.md(最終形)

## 決定

1. **欄**: 計算画面の「詳細」の下に折りたたみ「対戦の状態」(既定は閉じる。設定中は閉じていても「(設定中)」を付ける)。中に
   「攻撃側の残りHP」「防御側の残りHP」(実数値。横に「/ 最大」と割合〈小数第1位・切り捨て〉)。技の欄の下に、範囲の多段技
   (`mechanismParams.multiHit` の min < max)のときだけ「回数」(既定・min..max 回)。文言は `battleStateText`(i18n/ja.ts)。
2. **送る形**: `domain/battleState.ts` の `resolveBattleState` が1か所で決める。空・最大と同じ値(満タン)・既定の回数・範囲の多段でない技の回数は
   入れず、何も無ければ `battleState` を付けない(従来と同じ要求)。範囲外・整数でない値は欄の下に「1〜{最大}で入力してください」を出し、計算を送らない(結果も出さない)。
3. **計算の経路**: 計算画面は一括計算(`calcBulk`。5 行 × 持ち物 × 特性)で動くが、一括には `battleState` を足さない(ADR-0144)。
   そこで状態を指定したときだけ、一括の応答の各行を `battleState` つきの `calc`(1対1。WASM / `POST /api/calc`)で計算し直して行の結果を差し替える
   (`domain/battleStateRows.ts`。防御側は行の SP・性格・持ち物・特性で組む)。指定が無いときは従来どおり一括だけ。
4. **最大 HP**: 攻撃側は 種族値 + 75 + SP(画面の入力)。防御側は行ごとに SP が違うため、どの行にも当てはまる無振り(SP 0)の最大 HP(種族値 + 75)を
   欄の上限にする(decisions の表の逸脱。行ごとの最大 HP は結果の `defenderHP` にあるが、入力は 1 つなので最小に揃えた)。
   最大 HP が変わって(種族・SP の変更)残り HP が最大を超えたら、最大に合わせて「最大HP({n})に合わせました」を出す。利用者が最大を超えて入力したときは丸めず誤りにする。
5. **前提の表示**: 状態を指定した結果の近くに「対戦の状態: 攻撃側 HP a/A・防御側 HP d/D・n 回」(指定した項目だけ)。
6. **回数のリセット**: 回数は選んだ技に結びつけて持ち、技を変えると「既定」に戻る(攻守入れ替え・攻撃側の変更で技が変わったときも同じ)。
7. **保存・復元**: お気に入りの `calc.battleState` に指定した項目だけ保存し、お気に入り・計算履歴から開くと欄と回数に戻す(`favoriteCalc.ts`。履歴は同じ復元の経路)。
   一括・逆算・調整には付けない。
8. 常時アニメーションなし。入力は label・aria-describedby・aria-invalid、誤りは role=alert。色は tokens.css のトークンだけ。

## 逸脱

- 防御側の上限は無振りの最大 HP(決定 4)。decisions の「%で入力」の切り替えは入れていない(任意とされていたため。割合の表示は横に出す)。
