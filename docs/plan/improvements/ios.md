## I-ios-1: 計算画面の動作確認の要望(ユーザー 2026-10-04。データレーン経由。Web と表示・順序を揃える)
要望(Web の計算画面に出されたもの。iOS の計算画面にも当てはまるかを確認した結果を併記する):
1. **攻撃側の能力ポイントにプリセットに加えて数値入力(SP 0〜32)+性格補正の選択**。iOS は攻撃側が「無振り/特化/振り」のプリセットのみ(`AttackerPreset`)で、SP の直接入力・性格の選択は計算画面に無い(構築から呼ぶ場合だけ SP・性格が入る)。→ **当てはまる**。design.md「数値の直接入力は『詳細』を開いたときだけ」に沿って、「詳細」(または攻撃側カード)に SP(0〜32。`SPLimits`)と性格補正(+/−/無補正の選択。性格の ID ではなく補正方向で足りるか Web の決定を確認)を足す。送信は既存の `Individual`(`natureId`・`sp`)。
2. **技の選択肢をダメージを与える技(物理・特殊)に絞る**。iOS の `moveOptions` は learnset との交差で、変化技も含む(計算画面の既定の技は「最初の非変化技」)。→ **当てはまる**。計算・逆算・判定の技ピッカーで `category != .status` に絞る(変化技を計算させない)。構築の技選択(4 技)は絞らない(構築は変化技も持つ)。
3. **入力の順を「技 → その技の攻撃/特攻(両方の入力を常に出し、選んだ技が使う方を強調)→ 計算」**。iOS は攻撃側カードに種族・持ち物があり、技は別の行、ランクは「詳細」(技の分類で A/C のどちらか1つ)。→ **当てはまるが、画面構成の変更が大きい**。Web の最終形(順序・強調の見せ方)が決まってから揃える(先に Web の決定を `docs/ai-shared/decisions/` で確認)。
4. **メガストーンの表示名を正式名称(例: リザードナイトX)に**(データレーンがマスタで直す)。iOS はメガ種族の持ち物を「<基本種>のメガストーン」の組み立てで日本語化している(ADR-0509 §6。マスタの `nameJa` が英語のことがあったため)。→ マスタが正式名称になったら、**マスタの `nameJa` をそのまま使う**よう戻し、組み立てを外す(データレーンのマスタ更新後に確認)。

進め方: 2 → 1 → (4 はマスタ更新後) → 3(Web の決定後)。2 と 1 は iOS 単独で着手できる。
