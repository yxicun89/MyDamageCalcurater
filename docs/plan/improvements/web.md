## 2026-10-04 ユーザーの動作確認の要望(データレーン 01 経由。ダメージ計算画面)
ユーザーの言葉の要約: 「この努力値の場合どれくらいか」が分からないので、能力ポイント(SP)を自分で入力し、性格補正も選びたい。桁の丸め方は今のままでよい(好評)。
技はダメージを与えるものだけにし、入力は「技を選ぶ → その技の分類の攻撃/特攻をプリセットか数値+性格で決める → 計算」の順にしたい。
ユーザーは既定案(A)で進めてよいと言っている。

- [x] **I-web-1(PR-2)**: 攻撃側の能力ポイントに、今の「無振り・特化・全振り」に加えて SP の数値入力(0〜32)と性格補正(上昇・補正なし・下降)を足す。丸め方(4096 基準・五捨五超入)は変えない。
- [x] **I-web-2(PR-1)**: 技の選択肢を、ダメージを与える技(物理・特殊)に絞る。変化技は出さない(マスタの分類から導く。ハードコードしない)。完了: `domain/moves.ts` の `damagingLearnsetMoves` を計算・逆算・調整の技欄に適用。変化技だけの種族は案内(`noDamagingMovesNotice`)を出し要求を送らない。`status-move` は安全網として残す。ADR-0328。
- [x] **I-web-3(PR-2)**: 入力の順を「技 → その技の分類に応じた攻撃/特攻の入力 → 計算」にする。既定案(A): 攻撃・特攻の両方の入力を常に出し、選んだ技が使う方を強調する(技を切り替えても両方の値が残る)。 完了(I-web-1・I-web-3 とも): 技の直後に「攻撃」「特攻」の2ブロックを常に出し(選んだ技の方に「(この技で使用)」+aria-current)、各ブロックにプリセット・SP 数値欄(0〜32)・性格補正を持たせた。性格はマスタから A/C の補正の組合せで解決し、A と C の同方向は入力時に無効、不正入力は明示エラーで計算しない。旧「攻撃側の調整」は廃止。丸め・engine・API は不変。ADR-0329。iOS 向けの決定は docs/ai-shared/decisions/2026-10-04-web-calc-attacker-input-flow.md。
- [x] **I-web-4(PR-1)**: 持ち物のメガストーンの表示名を、マスタの正式名称(例: メガリザードンX → リザードナイトX。データレーンがマスタ側を直す)に切り替える。Web が組み立てている「{基本種名}のメガストーン」(ADR-0326)は、マスタの名前が日本語として使えないときのフォールバックにする。完了: `megaStoneDisplayName`(日本語の文字を含めば nameJa のまま、無ければ従来のフォールバック)を計算・逆算・判定・構築の全表示と `itemsWithStoneLabels` に適用。ADR-0328(ADR-0326 §4・ADR-0324 §2・ADR-0175 §4 を更新)。
- iOS: 同じ画面があるので、iOS レーンへの横展開はデータレーンが iOS へ連絡する(I-web-1〜3 の仕様は Web の実装・ADR を参照)。
