## 1. 目的とユースケース

ダメージ計算で決めた「攻撃側」「防御側(相手の振り方 = SP・性格・持ち物)」「場」をそのまま使い、**技を 2〜3 手続けて使ったとき**に

- 合計で相手を倒せるか(確定か、何%か)
- 自分のランクを上げる技を使った後に、相手を素早さで抜けるか
- 相手が先に動く場合、相手の技を耐えられるか

を 1 回の操作で確かめる。独立した画面にはせず、ダメージ計算の中の拡張として置く(§4-3)。

以下の数値は現行の engine(`engine.CalcDamage`・`RealStats`・`EffectiveStat`)で計算した例。特性・持ち物なし、場の効果なし、急所なし。
種族値は公開されている値(ミミッキュ 55/90/80/50/105/96、ガブリアス 108/130/95/80/85/102、カイリュー 91/134/95/100/100/80)。
SP の書き方は「H2 A32 S32」= HP 2・攻撃 32・素早さ 32。

### UC-1: 素早さを上げる攻撃技 → メイン技(例: ニトロチャージ → メイン技)

「ニトロチャージで素早さを 1 段階上げてから、メイン技で倒せるか。上げた後に相手を抜けるか」。

- 1 手目はニトロチャージのダメージ(素早さは上がる前の値で行動順を決める)。命中後に素早さ +1。
- 2 手目は素早さ +1 の状態で行動順を決め、メイン技のダメージを出す。
- 合計ダメージ(1 手目 + 2 手目)で倒せる確率を出す。
- 相手の素早さが分からなくても「上げた後の素早さ」と「抜ける素早さのライン」を出す(§2-3)。

数値の例は実装時に @smogon/calc 0.12.0 で期待値を作る(§5 AC-9)。

### UC-2: 能力を上げる変化技 → メイン技(例: りゅうのまい → げきりん)

「りゅうのまいを選んだら、攻撃 +1・素早さ +1 の状態で次の技のダメージを計算する」。

- 例: いじっぱり H2 A32 S32 のカイリュー(素早さ 132)が、わんぱく H32 B32 S2 のガブリアス(HP 215)に
  - そのままげきりん: 170〜204(確定 2 発)
  - りゅうのまい → げきりん: 1 手目はダメージなし、攻撃 +1・素早さ +1。2 手目のげきりんは 258〜306(**確定 1 発**)
  - 素早さは 132 → 198。ようき S32 のガブリアス(169)を、りゅうのまいの前は抜けず、後は抜ける

### UC-3: メイン技 + 先制技(例: ミミッキュ じゃれつく + かげうち)

「ミミッキュのじゃれつく + かげうちで、このポケモンを倒せるか。どれくらい削れるか」。

- 例: いじっぱり H2 A32 S32 のミミッキュ(素早さ 148)が、ようき H2 A32 S32 のガブリアス(HP 185)に
  - じゃれつく: 138〜164 / かげうち: 31〜37 / 合計 169〜201
  - 2 手で倒せる確率は 256 通り中 132 通り = **51.5625%(表示 51.6%)**
- 相手をわんぱく H32 B32 S2 にすると(HP 215)、じゃれつく 102〜120 + かげうち 24〜28 = 126〜148 で **倒せない(0%)**。
  → 「相手の振り方」を変えると結果が変わる(UC-5)。

### UC-4: 相手が先に動く場合に耐えるか(相手の技を利用者が選ぶ)

「相手が使いそうな技を自分で選び、相手が先に動いたときに自分が耐えるかも見たい」。

- UC-3 の続き: 1 手目(じゃれつく、優先度 0)は、ミミッキュ 148 < ガブリアス 169 なので**相手が先**。
  相手の技に「じしん」を選ぶと、ようき A32 のガブリアスのじしんはミミッキュ(HP 132)に 103〜123 → **耐える(100%)**。
  2 手目のかげうち(優先度 +1)は自分が先なので、相手は 2 回目を撃てない。→ 相手の行動は 1 回。
- UC-2 の続き: 1 手目(りゅうのまい)は、カイリュー 132 < ガブリアス 169 なので**相手が先**。
  相手の技に「げきりん」を選ぶと、ようき A32 のガブリアスのげきりんはカイリュー(HP 168)に 216〜254 → **耐えない(0%)**。
  (この例は特性なし。カイリューのマルチスケイルは §3-4 の扱い)

### UC-5: ダメージ計算の「相手の振り方」と一緒に使う

防御側の SP・性格・持ち物・特性・ランクは、ダメージ計算の防御側の入力(プリセット・よく計算する相手を含む)をそのまま使う。
連続技のために別の入力欄を作らない。

## 2. 入力と出力

### 2-1. 入力

| 項目 | 内容 | 既定 |
|---|---|---|
| 形式 | `format`(single / double)。double は今の計算と同じ扱い | ダメージ計算の値 |
| 攻撃側 | `Individual`(種族・性格・特性・持ち物・SP・ランク・状態異常)。ランクは 1 手目の開始時の値 | ダメージ計算の攻撃側 |
| 防御側 | `Individual`(同上)。**相手の振り方**はここ | ダメージ計算の防御側 |
| 場 | `FieldState`(天候・フィールド・壁)。全手で同じ(§3-5) | ダメージ計算の値 |
| 手の並び `steps` | 1〜3 件(§7 Q1)。各手は `moveId`、任意の `critical`(急所)、任意の `hits`(多段の回数) | 1 手目 = ダメージ計算の技 |
| 各手のランク変化 | **技から自動で決める**(マスタの技の追加効果。§3-1)。利用者は「確率で起きる追加効果を起きたことにする」を手ごとに選べる(§7 Q4) | 確率 100% のものだけ |
| 相手の技 `opponentMove` | 任意。`moveId` 1 つ。相手が行動する手ごとに同じ技を使うとする | なし(耐えるかを出さない) |
| 相手の素早さ `opponentSpeed` | `unknown`(分からない)か `fromDefender`(防御側の SP・性格・持ち物から計算) | `unknown` |
| 素早さの場 `speedField` | 任意。トリックルーム・追い風(自分側・相手側)。判定(ADR-0702)と同じ意味 | すべて false |

### 2-2. 出力

| 項目 | 内容 |
|---|---|
| 各手 `steps[]` | 技、手の開始時と終了時の自分のランク、適用したランク変化(と、適用しなかった確率つきの変化)、ダメージ(`CalcResult` と同じ形。変化技は null)、その手の自分の素早さ(実数値に補正を掛けた値)、優先度、行動順(`self_first` / `opponent_first` / `speed_tie` / `depends_on_opponent_speed`) |
| 合計 `total` | 合計ダメージの最小・最大(実数と%)、**全手で倒せる確率**(表示用は `KOChance.displayChancePercent` と同じ規則)、**何手目までで倒せるか**(手ごとの累積の確率) |
| 素早さ `speed` | 最初と最後の自分の素早さ、相手の素早さ(`fromDefender` のときだけ)、**抜ける素早さのライン**(§2-3) |
| 相手の攻撃 `opponentAttack` | `opponentMove` があるときだけ。1 回ぶんのダメージ(`CalcResult`)、相手が行動する回数(最小・最大)、**耐える確率**(回数ごと) |
| 印 `unsupported` | 各手の `CalcResult.unsupported` を手の順に連結し重複を除いたもの + 連続技の印(§3-4) |

### 2-3. 相手の素早さを知らない場合の表現

相手の素早さ(SP・性格・スカーフ)を知らないのが普通なので、`opponentSpeed: unknown` を既定にする。そのときは

1. **ライン(数値)**: 手ごとに「この手の時点の自分の素早さ = 198 → **相手の素早さが 197 以下なら先に動ける / 198 なら同速 / 199 以上なら相手が先**」
   を返す(トリックルーム中は向きを反対にして返す)。
2. **種族の例**: クライアントが素早さサービスの既存 API `POST /api/speed/v1/position` の `raw` モード(`value` = その素早さ)を呼び、
   素早さ表(無振り・準速・最速・スカーフ… の 6 行。ADR-0601 §2)のどの行を抜けるかを示す。画面では
   「抜ける: 最速ガブリアス(169)など N 行 / 同速: … / 抜けない: 最速スカーフ○○ など」の形で、境目の上下 3 件程度を出す。
   calc-svc は素早さサービスを呼ばない(兄弟サービスを互いに呼ばない。ADR-0012)。オフライン(WASM)の時は 1. のラインだけ出す。
3. **行動順**: 優先度が違う手は素早さに関係なく決まる(`self_first` / `opponent_first`)。優先度が同じ手は
   `depends_on_opponent_speed` とし、ラインを添える。
4. **耐える確率**: 相手の行動回数は「最小(相手が遅い場合)」と「最大(相手が速い場合)」の 2 通りを返し、画面は**最大(悪い方)を主**に出す。

例(UC-2): 「りゅうのまいの後 198。**197 以下を抜く**(最速ガブリアス 169 は抜ける)」。

## 3. 計算の規則

### 3-1. 手の進め方とランク変化の順

各手 i(1..n)について、次の順で進める。

1. 行動順を決める(§3-2)。この手で相手が先なら、相手の技のダメージを先に受ける(耐える確率の計算に入れる)。
2. 自分の技のダメージを `engine.CalcDamage` で出す。自分と相手のランクは**この手の開始時の値**(ニトロチャージの素早さ +1 は、
   ニトロチャージ自身のダメージにも行動順にも効かない)。
3. 技の追加効果のランク変化を適用する(-6〜+6 に収める)。
   - 自分への変化(りゅうのまい・つるぎのまい・ニトロチャージ・インファイトの防御/特防 -1・りゅうせいぐんの特攻 -2 等)は自分のランクへ。
   - 相手への確率 100% の変化(がんせきふうじの素早さ -1 等)は相手のランクへ(§7 Q5。推奨は含める)。
   - 確率 100% 未満の変化(メタルクローの攻撃 +1〈10%〉等)は**既定では適用しない**。出力に「確率 10% で攻撃 +1(未適用)」として返す。
   - 変化技はダメージなし(2. を飛ばす)。ランク変化を持たない変化技は手に置けない(400)。
4. 次の手へ。相手のランクは相手の技の追加効果では変えない(相手の技は 1 つの固定の攻撃として扱う)。

合計ダメージ・倒せる確率は、各手の 16 段階(多段技は 1 発ごとの 16 段階。ADR-0142 §3)を**独立な乱数として畳み込んで**厳密に数える
(engine の `koProbabilitySeq` と同じ考え方。float の確率の足し合わせはしてよいが、ダメージそのものは整数のまま)。
2 手目以降のダメージは、1 手目で相手が残った前提で計算する(相手は満タン扱い。§3-4)。

### 3-2. 行動順(優先度と素早さ)

判定(ADR-0704 §2)と同じ規則。

- 優先度が違えば、優先度が高い方が先(トリックルームの影響を受けない)。かげうち・しんそく等の優先度はマスタの `priority`、
  フィールドで優先度が変わる技は技の処理の定義(`MoveRule.PriorityBoost`。ADR-0143)から取る。
- 相手の技が選ばれていないときも、相手は優先度 0 の技で動くものとして行動順を出す(耐える確率だけ出さない)。
- 優先度が同じなら素早さで決める。トリックルーム中は遅い方が先。同じ素早さは `speed_tie`(どちらとも決めない)。
- 素早さ = 実数値 → ランク → 4096 基準の補正(追い風・こだわりスカーフ・特性/持ち物の素早さ補正〈ADR-0139〉)を連結して 1 回だけ五捨五超入 → まひ(×1/2)。
  判定の `services/judge/internal/judge/speed.go` と同じ式(§4-1 で engine に移す)。

### 3-3. 持ち物・特性で扱う範囲

| 扱う | 理由 |
|---|---|
| ダメージ計算が既に扱う特性・持ち物のダメージ補正(各手の `CalcDamage` がそのまま反映) | 新しい式を持たない |
| 素早さの補正(こだわりスカーフ・天候/フィールド依存の特性の 2 倍 等。ADR-0139 の語彙) | 判定が既に実装済み。行動順に必須 |
| こだわり系の持ち物で手ごとに技が違うとき、印 `choice_locked` を付ける(計算はする) | 実際は技を変えられない。ID の switch は書かず、持ち物の役割(ADR-0175)で判定する |

| 扱わない(v1) | 理由 |
|---|---|
| 行動後・ターン終了時に起きる特性(かそく・じしんかじょう等) | 「技で段階を変える」範囲の外。ターンの終わりの処理を持たない |
| 優先度を変える特性(いたずらごころ等) | マスタに語彙が無い。マスタに入ったら扱う |
| 1 回だけ効く特性・持ち物(ばけのかわ・きあいのタスキ・マルチスケイルの「満タンのときだけ」) | 2 手目以降の相手の残り HP は乱数で分布になる。§3-4 の印を付け、§7 Q6 で段階的に扱う |
| 反動・回復・状態異常のダメージ(いのちのたま・たべのこし・やけど 等) | 複数ターンにまたがる持続(§3-5) |
| 相手の技の追加効果(相手のニトロチャージで相手が速くなる等) | 相手の技は「1 つの固定の攻撃」に限る(入力を増やさない) |

### 3-4. 連続技に固有の印(未対応の印。ADR-0123 の形)

- `defender_full_hp_assumed`: 2 手目以降も相手を満タンとして計算した(残り HP で威力が変わる技・満タンでだけ効く特性/持ち物があるとき。
  どれが該当するかは技の機構 `variable_power` 等と、特性・持ち物の効果定義の条件から決め、ID を直書きしない)
- `choice_locked`: §3-3
- `chance_effect_not_applied`: 確率 100% 未満の追加効果を適用していない(出力の手に添える。画面では「確率で発動」チップ)

### 3-5. 対象外にするもの(複数ターンにまたがる持続)

天候・フィールドの残りターン、壁の切れ目、技による天候の変化(あまごい等)、やけど・どくのダメージ、たべのこし、反動、まもる。
**理由**: どれも「ターンの終わり」や「何ターン目か」を数える処理が要り、手の並びが 2〜3 手でもターン数・行動の有無で結果が枝分かれする。
v1 は「技を選ぶと段階が変わる」に絞り、場は**入力した状態が全手で続く**とする(ダメージ計算の場の入力をそのまま使い、画面にそう書く)。

### 3-6. 既知の制約

- **命中**: 倒せる確率に命中率を掛けない(ダメージ計算と同じ)。画面に「命中を考えると 90% × 100%」の補足を出す(§7 Q3。推奨)。
  技の命中率はマスタの moves.accuracy にあるが、engine の `Move` には無い(API の公開 `Move` にも無い)。
- **急所**: 手ごとに `critical` を選べる(既定は急所なし)。急所の確率は計算に入れない。
- **乱数**: 16 段階を等確率で厳密に数える(既存の確定数と同じ)。表示の丸めは `displayChancePercent` の規則。
- **相手の行動**: 相手は自分の手ごとに 1 回だけ、選ばれた 1 つの技で攻撃する。交代・まもる・変化技は考えない。

## 4. 設計案

### 4-1. engine(純粋。`engine/combo.go`)

新しい式は持たない。既存の `CalcDamage`・`RealStats`・`EffectiveStat` と確定数の畳み込みを組み合わせる。

- `GuaranteedSelfStages(m Move) Ranks` と `GuaranteedTargetStages(m Move) Ranks`: 確率 100% のランク変化(`GuaranteedSelfSpeedStage`〈ADR-0177 §4〉を全能力に広げたもの。
  `GuaranteedSelfSpeedStage` はこれを使う形に置き換え、結果は変えない)
- `FinalSpeed(in Individual, field Field, sf SpeedField) (int, []UnsupportedMark)`: 判定の `services/judge/internal/judge/speed.go`
  (`Speed`・`ResolveSpeedMod`・`CompareSpeed`)と `turnorder.go`(`CompareTurnOrder`)を engine に移す。ADR-0177 §3「engine は素早さの補正を評価しない」を改める(ADR 予定 0179)。
  WASM(オフライン)でも行動順を出すため、サービス側ではなく engine に置く
- `CalcCombo(in ComboInput) (ComboResult, error)`: §3 の手の進め方。入力・出力は §2。手の数の上限は定数 `MaxComboSteps`(§7 Q1)
- 合計の倒せる確率は、`HitRolls` を持つ多段技も含めて手の列を畳み込む(`koProbabilitySeq` を「回数 n の繰り返し」から「違う手の列」に広げる)

### 4-2. calc-svc の API(`api/openapi.yaml` から。ADR 予定 0252)

- 新しい `POST /api/calc/combo`(`operationId: calcCombo`)。リクエストは §2-1、応答は §2-2。エラーは `/api/calc` と同じ形
  (400 `invalid_input`・422 `unknown_species` / `unknown_move` 等・503 `master_unavailable`)。検査の順序は ADR-0208 §3 に合わせ、
  手の数の範囲外は ID の解決より前に 400。
- 公開 `Move` に `effect`(追加効果のランク変化。内部の `MasterMove.effect` と同じ形)を足す。Web の技の選択肢に「攻撃 +1・素早さ +1」の
  チップと「ランクが変わる技」の絞り込みを出すため。古いサーバーは返さないのでキーごと省略可。
- 計算イベント(record)は v1 では発行しない(絶対ルール 5: record が落ちても計算は成功する。履歴の形は単発の計算用なので、連続技の履歴は要望が出たら別に決める)。

**判定サービス(judge-svc)は使わず、廃止する(推奨。§7 Q2)**。理由:

1. ユーザーの指示が「判定画面ではなくダメージ計算の拡張」。
2. judge-svc は calc-svc を HTTP で呼ぶ形(ADR-0700)で、2〜3 手 × 両方向だと上流呼び出しが増え、オフライン(WASM)でも動かない。
3. 判定の資産(素早さの式・行動順・場の効果)は §4-1 で engine に移せば残る。判定の契約(`outspeed-and-ko`)にはクライアントが無い(画面は非表示)。

廃止は連続技の Web 画面が入った後に、判定レーンが行う(CB-7)。

### 4-3. クライアントの置き場所(下部タブ 4 = ダメージ〈計算・逆算・調整〉・構築・素早さ・記録 の案 B を前提)

**案 A(推奨): 計算画面の結果カードの下に「続けて使う」を足す**
- 今の計算(攻撃側・防御側・場・技)が 1 手目になる。結果カードの下に「+ 次の技」ボタン → 技のピッカー(G-01 の技の選択肢を再利用)。
  手はカードの横並び(技のアイコン・ランク変化のチップ・各手のダメージ)。その下に合計のバー(相手の HP に対する合計ダメージの幅)と
  「2 手で倒す 51.6%」、素早さの行(「198 → 197 以下を抜く」と種族の例)、相手の技(任意)と「耐える 100%」。
- 良い点: 入力を二重に持たない(UC-5 がそのまま満たせる)。ダメージ計算の拡張というユーザーの指示に一番近い。
- 悪い点: 計算画面が長くなる。→ 手が 1 つのときは「+ 次の技」ボタンだけにし、使ったときだけ広げる。

**案 B: ダメージタブの 4 つめの切り替え「連続技」(計算・逆算・調整・連続技)**
- 攻撃側・防御側・場の入力は計算と共有し、結果の部分だけ連続技の表示にする。
- 良い点: 計算画面を長くしない。悪い点: 切り替えが増え、「計算の続き」という流れが切れる。

**案 C: 調整画面の目標に「連続技で倒す」を足す**
- 「抜けて倒せる最小の振り方」を探せる(ADR-0177 の目標の拡張)。
- 悪い点: 探索(SP の総当たり)× 手の組み合わせで重い。v1 の対象外にし、案 A の後の段階で検討する。

iOS は Web と同じ案(計算の画面 `CalcScreenView` の結果の下)。

## 7. ユーザーの回答(2026-10-11。選択肢は推奨を先頭に並べたもの)

**決定: 1〜3・5〜9 は各項目の推奨(a)どおり。4 は「(b) 常に適用しない」(確率 100% の効果だけを扱う)。** 理由(ユーザー): 追加効果の確率を目当てに計算することはない。追加効果が出た場合は、残り体力に対して次の技で倒せるかを見るのが主な使い方。確率が 100% 未満の効果は計算に入れない(印も出さなくてよい)。

1. **手の数の上限**: (a) 3 手(推奨。りゅうのまい → りゅうのまい → げきりん まで書ける。総当たりは 16^3 = 4096 通りで軽い)/ (b) 2 手 / (c) 4 手以上
2. **判定サービスの扱い**: (a) 連続技の Web が入ったら judge-svc を廃止する(推奨。§4-2)/ (b) judge-svc を残して連続技の API を judge 側に置く / (c) 残すが使わない
3. **命中率**: (a) 倒せる確率には掛けず、補足として「命中 90% × 100%」を出す(推奨。ダメージ計算と同じ考え方)/ (b) 倒せる確率に掛ける / (c) 出さない
4. **確率 100% 未満の追加効果**: (a) 既定は適用せず、手ごとに「発動したことにする」を選べる(推奨)/ **(b) 常に適用しない ← 決定** / (c) 発動・不発の両方を返す
5. **相手のランクを下げる技(がんせきふうじの素早さ -1 等)**: (a) 確率 100% のものは相手に適用する(推奨。抜けるかに直接効く)/ (b) 自分への変化だけにする
6. **きあいのタスキ・ばけのかわ(1 回だけ耐える)**: (a) v1 は印だけ付け、次の段階で「1 手目で倒れても HP 1 で残る」を扱う(推奨。連続技で特に効く)/ (b) v1 から扱う / (c) 扱わない
7. **攻撃側の制限**: ユーザーの要望は「攻撃側は素早さを上げる技を持つポケモンに限る」だが、UC-3(じゃれつく + かげうち)は素早さを上げない。
   (a) 制限しない。技のピッカーで「ランクが変わる技」を上に出す(推奨)/ (b) 1 手目はランクが変わる技に限る / (c) 素早さを上げる技を覚えるポケモンだけを攻撃側に選べる
8. **置き場所**: (a) 案 A 計算画面の結果の下(推奨)/ (b) 案 B ダメージタブの 4 つめの切り替え / (c) 案 C 調整の目標
9. **相手の技の数**: (a) 1 つ(推奨。入力を増やさない)/ (b) 手ごとに違う技を選べる
