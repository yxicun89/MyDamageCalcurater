## 2026-10-04: 計算画面の攻撃側の入力を「技 → 攻撃/特攻の2ブロック」にする(Web レーン。ADR-0329。iOS が揃える)
Decision: Web の計算画面は次の形になった。iOS の同じ画面を同じ仕様に揃える。
- 並び: 攻撃側・防御側カード → 技 → 「攻撃」「特攻」の2ブロック → 持ち物の候補の比較 → 結果。攻撃側の種族を選ぶまで2ブロックは出さない。旧「攻撃側の調整」(カード内の1つのラジオ)は廃止。
- 2ブロックは常に両方出す。選んだ技の分類が使う側(物理・変化 = 攻撃、特殊 = 特攻)の見出しに「(この技で使用)」を足し、アクセシビリティ上も「現在の項目」にする。枠の太さ等の視覚の強調に加えて文字でも示す(色だけに頼らない)。技が未選択なら強調しない。
- 各ブロック(上から): プリセット(無振り・A特化・A振り(無補正)。特攻は C 表記。ブロックの値と一致するものを選択表示し、どれとも一致しなければ選択なしで「カスタム」と出す)/ SP の数値欄(整数 0〜32、ラベル「攻撃のSP」「特攻のSP」)/ 性格補正(上昇・補正なし・下降。ラベル「攻撃の性格補正」「特攻の性格補正」)。プリセットを選ぶと数値・補正に値が入る: 無振り = 0・補正なし、特化 = 32・上昇、振り(無補正) = 32・補正なし。数値を変えても補正は変わらず、補正を変えても数値は変わらない。既定は両ブロックとも 0・補正なし。
- A と C を同じ向き(上昇と上昇・下降と下降)にする組み合わせは不可。もう一方が上昇なら、こちらの「上昇」と「特化」プリセットを選べなくし、理由の一文を添える。もう一方の値を黙って書き換えない。
- 要求の組み立て: H・B・D・S の SP は 0。攻撃と特攻の SP は両方とも要求に載せる(技が使わない側もそのまま。お気に入りに入る個体も同じ)。合計は最大 64 で上限 66 を超えない。
- 性格はマスタの性格一覧から解決する(WASM・API で同じ要求にするため。実在しない性格は送らない): (1) 両方補正なし → 無補正(従来と同一)。(2) A・C の両方の補正に合う性格のうち ID が昇順で最初のもの(補正なしの側は上昇でも下降でもない性格)。ただし選んだ技が使う側が上昇でもう一方の攻撃系が補正なしなら、マイナスをもう一方の攻撃系に置く性格を優先する(物理 = +A/−C、特殊 = +C/−A。従来の A特化・C特化の代表性格と同じ。素早さに効くため)。(3) 無ければ、選んだ技が使う側だけを合わせる(使う側が補正なしなら無補正)。(4) それも無ければ解決失敗。
- 不正入力は黙って丸めず明示エラーにして計算しない(古い結果も出さない): SP は10進整数 0〜32 のみ(前後の空白は無視、先頭の 0 は可、空欄は 0。符号・小数点・指数・全角・33 以上は不正)。技が使わない側の欄が不正でも計算しない。性格が解決できないときも同じ。直せば計算し直す。
- 値は技の切り替え・攻守入れ替え・攻撃側の種族の変更で保つ。
- お気に入りに入れる攻撃側(SP・性格)もこの入力から解決したものにする。不正・性格が解決できないときは追加できない。
- 文言(iOS と同じ): 「攻撃」「特攻」/ 「(この技で使用)」/ 「攻撃の調整」「特攻の調整」/ 「攻撃のSP」「特攻のSP」/ 「攻撃の性格補正」「特攻の性格補正」/ 「上昇」「補正なし」「下降」/ 「カスタム」/ 「攻撃のSPは0〜32の整数で入力してください」(特攻も同様)/ 「この性格補正の組み合わせに当たる性格がマスタにありません」/ 「攻撃と特攻の両方を上昇、または両方を下降にすることはできません」。プリセット名は既存どおり(無振り・A特化・A振り(無補正)・C特化・C振り(無補正))。
Reason: 「この努力値ならどれくらいか」を数値で試したい要望(I-web-1)と、物理・特殊の両刀で技を替えるたびに入れ直さずに済ませる要望(I-web-3)。丸め(4096 基準・五捨五超入)は変えず、Web は値を渡すだけ。
Impact:
- iOS: 計算画面の攻撃側を上記の形にする(`docs/plan/improvements/web.md` の I-web-1・I-web-3 の横展開)。性格の解決は iOS のマスタ(性格一覧)から同じ規則で行い、ID の並びで同じ性格を選ぶ。
- 他レーン: engine・API(`api/openapi.yaml`)・services・ゴールデンは不変。逆算・調整・判定の画面は対象外。
