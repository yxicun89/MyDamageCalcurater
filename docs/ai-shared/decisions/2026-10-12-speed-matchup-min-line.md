## 2026-10-12: 素早さ画面を「相手を選んで上を取る最低ライン」にする案(I-speed-4。ADR-0610。ユーザー確認待ちの点あり)
Decision: 素早さ画面は表をやめ、自分と相手のポケモンを入力して「上を取る最低ライン」を出す形にする(推奨案。ADR-0610)。
- 上を取る = 素早さだけで行動順が先(engine.CompareSpeed が self_first)。トリックルーム中は遅い方。同速は含めず「S○ で同速」を併記。
- 出力 1(相手を選んだとき): 相手の想定(既定 無振り・準速・最速・最速スカーフ)ごとに、性格(下降・なし・上昇)ごとの「上を取れる SP の区間」と「同速の SP」。表示は性格ごとの最小 SP(案 A)、見出しに「準速で抜ける」等の要約語。
- 出力 2(自分の素早さが決まったとき): 表の 6 プリセットごとに「P a 族まで抜ける・b 族と同速・c 族以上に抜かれる」と read model の数・境界の例。『準速○○族以上』= 自分の素早さ v に対して「準速 c 族以上には抜かれる」(c = min{X | X+52 > v})。
- API: speed 契約 0.7.0 に `POST /api/speed/v1/matchup`・`POST /api/speed/v1/reach` を追加(後方互換。/table・/position・/pokemon は残す)。計算は speed のコア(純粋)で、値は engine.FinalSpeed と同じ(一致テストあり)、行動順は engine.CompareSpeed。
- 画面: Web・iOS とも表(ADR-0608 / 0517)と周辺パネル(ADR-0609 / 0527)を外す。「この相手で連続技を計算」で計算画面の連続技(CB-6 / CB-8)へ攻撃側 = 自分・防御側 = 相手を渡す。ダメージ・確定数は素早さ画面に出さない(判定は廃止予定。combo-calc §7 Q2)。
Reason: ユーザー要望(ec 経由)「相手と自分を入れて、ここまですれば上を取れるを表示。『これ以上』も表なしで。『準速○○族以上』の表記」。式は連続技と共有して数値を一致させる(データレーン 01 の訂正)。
Impact: speed-svc(core・httpapi・契約 0.7.0)、Web(web/src/speed)、iOS(Speed*)。未確定(ユーザー確認): Q1 同速の扱い / Q2 相手の想定の既定 / Q3『準速○○族以上』の向き / Q4 届かないときの提案 / Q5 下降補正の行 / Q6 表を完全に外すか / Q7 連続技へ渡す内容(ADR-0610 §6)。spec のテストはブランチ feat/speed-redesign(失敗する状態。implementer 待ち)。
