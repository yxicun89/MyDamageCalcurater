## 2026-10-04: Wishlist の残り(フェーズ3 headless・フェーズ4)の進め方(既定案で進行・一部ユーザー確認済み)
Decision: ユーザー指示「全てのフェーズで最後まで終わらせる」(2026-10-04 深夜)を受け、次の既定案で進める。
- **フェーズ3 headless**(メルカリ・ドラゴンスター): headless Chromium で描画後の構造を手動確認の範囲で確かめ(2026-10-03 のユーザー許可の範囲)、
  確かめられたサイトだけ chromedp の取得処理を作る。Chromium は refresher 専用イメージにだけ載せ、夜間の CronJob でだけ取る(2026-10-03 のユーザー決定)。
  Cloudflare 等で取れないサイトは、回避を試みずリンクだけにする。
- **フェーズ4-1 表記揺れの辞書**: ジャンルごとの別名(例 `S.H.Figuarts` = `SHフィギュアーツ` = `フィギュアーツ`)を持ち、title_mismatch の判定で同一視する。設定画面(PWA・iOS)で編集。
- **フェーズ4-2 価格の推移**: 取得のたびにサイト別の目安(low・mid)を履歴に残し、詳細シートに日ごとの推移を簡単なグラフで出す(PWA は SVG、iOS は Swift Charts。新しい npm 依存は入れない)。保存は 1 商品×1 サイト×1 日 1 行、180 日で削除。
- **フェーズ4-3 公式サイトの販売状況監視**: 商品の `source_url`(公式ページ)を夜間に取得し、本文の決まった語(予約受付中・販売中・在庫あり・販売終了・受付終了・SOLD OUT 等)から状態を判定、変化を記録して画面に出す。
  サイト固有の構造は推測しない(語の一致だけ)。取得は他サイトと同じ節度(ホスト単位の間隔・正直な UA)。
- **フェーズ4-4 プッシュ通知**: **作らない**(ユーザー指示 2026-10-04「通知いらない」)。iOS ネイティブ・PWA の Web Push とも行わない。
Reason: 深夜のため質問せず、仕様(apps/wishlist/CLAUDE.md §12 フェーズ4)と既存の決定に沿う既定案で進める。朝にまとめて確認する。
Impact: API 契約・DB(migration 000005〜)が増える。各機能は spec-writer → implementer → critic → PR で 1 つずつ入れる。
