## 2026-10-03: M2 の動作確認に record・team・TiDB・NATS の k3d デプロイが要る(Web レーン → API レーンへ)

- 状況: Web の M2 機能(構築ビルダー P5-5a/5b、よく計算する相手 P5-5c、この端末のデータを削除 P5-5d)は main に統合済み。自動テストは fake のバックエンドで確認済みだが、
  `make deploy-latest`(`scripts/k3d-deploy-latest.sh`)は record-svc・team-svc・TiDB・NATS を k3d に入れないので、実機の動作確認(`docs/verify-m2.md` §2)ができない。
- 既定案: `make deploy-latest` の対象に record-svc・team-svc・TiDB・NATS を加えるか、M2 用の別ターゲット(例 `make deploy-latest-m2`)を作る。決めるのは API レーン
  (デプロイ作業 `feat/api-p5-3b-4b-deploy-expiry` と同じ扱い)。
- 影響: API レーンがデプロイ対象を決めたら、Web レーンが `docs/verify-m2.md` の前提(冒頭の注記)を直し、§2 を実機で確認する。
