## 2026-10-12: Web の計算画面の「連続技」(CB-6 段階 B。ADR-0359)。iOS(CB-8)はこれに揃える
Decision: 計算画面の結果の下に「連続技」の節を置いた(案 A)。iOS の `CalcScreenView` も同じ構成・語にする。
- **構成**: 手がメイン 1 つだけのときは「次の技」ボタンだけ。押すと、手のリスト → 追加の技のピッカー → 相手の振り → 相手の技 → 相手の素早さ(防御側の振りから計算する切り替え) → 素早さの場(折りたたみ: トリックルーム・追い風〈自分〉・追い風〈相手〉) → 結果 → 注記。
- **手**: 最大 3 手(`MAX_COMBO_STEPS`)。メイン(上の技欄の技)は外せない。追加の手は外せる。上へ/下へで並べ替え(メインより前に置ける)。各手に急所(変化技には出さない)。メインの急所は「詳細」の急所と同じ値。追加の手の候補は攻撃側の覚える技のうち攻撃技かランクを変える変化技(`changesRanks`)。
- **ランクのチップ**: 「攻撃 +1」「素早さ +1」(相手のランクを変える技は「相手の素早さ -1」)。能力の並びは攻撃・防御・特攻・特防・素早さ。上昇 = brand.primary、下降 = warning(ADR-0357 と同じ意味)。符号は文字でも出す。
- **入力は二重に持たない**: 攻撃側・場・条件・ランクは計算画面の値。防御側の振りは計算画面の結果の行から「相手の振り」で選ぶ。
- **計算する条件**: 手が 2 件以上、または相手の技を選んだとき。相手の素早さは既定「分からない」(`unknown`)で、切り替えたときだけ `from_defender`。
- **結果の項目**: 各手(技名・ランクのチップ・ダメージの最小〜最大 %・変化技は「ダメージなし」・行動順〈先に動く / 相手が先 / 同速。決まらないときは出さない〉)、合計(「合計 91.4〜108.6%」とバー)、倒す確率(「N 手で倒す 51.6%」/ 確定は「N 手で倒す(確定)」/ 不可能は「倒せない」)、素早さ(「素早さ 132 → 198」)、相手の素早さが分からないときは最後の手の線(「197 以下を抜く / 198 は同速 / 199 以上は相手が先」。トリックルーム中は向きが逆)、分かるときは「相手の素早さ 169」。相手の技を選んだときは「耐える N%」(fast = 相手が先とした悪い方。0 / 100 は予約して 0.1〜99.9 に丸める)・「相手の行動 1〜2回」・「1回ぶん 40.2〜47.8%」。
- **印**: 単発と同じ「この結果は正確でない可能性があります(未対応: …)」の形。連続技だけの理由の語: choice_locked =「技を変えられない持ち物」、defender_full_hp_assumed =「2手目以降も相手が満タンとして計算」、speed_undetermined =「素早さへの影響を判定できない」。
- **注記**: 「場は全手で同じ状態が続きます。命中は考えません。」を常に出す。
- **失敗**: 連続技の節の中だけにエラーを出し、単発の結果は壊さない。
Reason: ユーザー指示(2026-10-11)「判定画面ではなくダメージ計算の拡張として作る」。
Impact: iOS(CB-8)は上の項目と語に揃える。素早さの種族の例(speed の reach)と素早さ画面からの導線は Web の段階 C のあとで追記する。

## 2026-10-12: 連続技の素早さの種族の例の文言(CB-6 段階 C。ADR-0359 追記。iOS は CB-8 でこれに揃える)
Decision: 相手の素早さが分からないとき、最後の手の自分の素早さ(`lastSelfSpeed`)で speed API の reach(raw)を引き、**準速**の行だけを 1〜3 行で出す。
- 「準速 118 族以上には抜かれる(例: ○○)」(`faster.min`・`slowestFaster` の名前)
- 「準速 117 族までは抜ける(例: ○○)」(`slower.max`・`fastestSlower` の名前)
- 同速の区間があれば「準速 116〜117 族とは同速」(1 つなら「準速 116 族とは同速」)
- 区間が無い行は出さない。名前が無ければ「(例: …)」を付けない。リストの名前は「素早さの基本値の例」(用語集で「種族」は禁止語。「○ 族」だけ使う)。
- 出さない: オフライン・reach の失敗(注記も出さない)・トリックルーム中。連続技の結果は壊さない。
- 防御側の振りが無くなり先頭に戻ったときの通知: 「選んでいた相手の振りがなくなったので、先頭の振りに戻しました」(status)。
- 素早さ画面の「この相手で連続技を計算」は計算画面の攻撃側 = 自分・防御側 = 相手を入れて連続技の節を広げる(素早さの SP・性格・ランクは「自分の素早さ」の入力へ反映する。スカーフは反映しない。下の 2026-10-12 追記を参照)。
Reason: ADR-0610 の「族」の数え方。表を出さずに「どの族まで抜ける」を分かるようにする。
Impact: iOS(CB-8)は同じ語・同じ条件(オンラインの reach)で出す。

## 2026-10-12: 連続技の「自分の素早さ」の入力と素早さ画面からの引き継ぎ(I-web-32。ADR-0359 追記。iOS は CB-8 でこれに揃える)
Decision: 連続技の節に「自分の素早さ」(素早さの SP・素早さの性格補正・素早さのランク)の入力を持つ。要求の攻撃側の個体に重ねて送る(ComboRequest の形は変えない)。
- 素早さの SP: 未入力は個体の値のまま。0〜(32 と「66 − 素早さ以外の SP の合計」の小さい方)。ランク: -6〜+6。
- 性格補正: 「計算画面の性格のまま」(既定)/「素早さ上がる」/「素早さ補正なし」/「素早さ下がる」。選んだときは、攻撃側の性格の素早さの補正だけを差し替える(攻撃・特攻の補正は両立する範囲で残す。上がる: 素早さ↑、↓は元の↓を残す。なければ攻撃↑なら特攻↓・特攻↑なら攻撃↓・それ以外は特攻↓。下がる: 素早さ↓、↑は元の↑を残す。なければ防御↑。補正なし: 素早さを含むなら無補正)。
- 既定(SP 0・性格そのまま・ランク 0)は今の挙動と同一(個体をそのまま送る)。入力を変えたら結果を引き直す。
- 素早さ画面の「この相手で連続技を計算」: speed の SP・性格(plus/neutral/minus → 上がる/補正なし/下がる)・ランクを入力へ入れる。こだわりスカーフは連続技に指定する項目が無いので反映せず、「素早さ画面で指定したこだわりスカーフは、連続技の計算では反映できません。」を出す(入力を触ると消す)。
- 素早さの例(reach)は反映後の最後の手の自分の素早さで引く。直近の入力(lastCalcInput)には素早さ入力を保存しない。
Reason: 素早さ画面で調べた自分の素早さの条件を、そのまま連続技の行動順に使えるようにするため(ユーザー承認の持ち越し)。
Impact: iOS(CB-8)は同じ項目・同じ既定・同じ引き継ぎにする。スカーフは連続技に引き継がない(こだわり系は技が固定され連続技と両立しないため、やらないと決定。2026-10-15 ユーザー決定)。両 UI とも未対応で揃える。
