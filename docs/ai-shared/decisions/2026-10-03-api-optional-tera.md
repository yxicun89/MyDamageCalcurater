## 2026-10-03: テラスタルをオプションの機能として計算に反映する(API レーン → Web・iOS・判定レーンへ。ADR-0224)
- ユーザー決定(2026-10-03): 「テラスタルは機能だけ追加しておいて、オプションで選択できるでいい。ダブルはなんでもいい」。既定(teraType 省略)は従来どおりで、指定したときだけ @smogon/calc 0.12.0 の Champions 世代と同じに反映する
- 攻撃側の teraType: タイプ一致(テラス=元タイプ=技 ×2.0、テラスだけ一致 ×1.5、てきおうりょく ×2.25 / ×2.0、テラス≠元タイプの元タイプ技は ×1.5)と接地(テラスひこうは浮く・元ひこうでもテラス中は接地)に反映。印 `attacker_tera_type` は**付かなくなる**
- 防御側の teraType: 接地・サイコフィールドの先制技・すなあらし/ゆきの防御補正には反映、**タイプ相性には反映しない**(oracle の Champions 世代の癖。本編 SV とは違う)。印 `defender_tera_type` は**残る**
- 既存クライアントへの影響: iOS の構築メンバーは teraType を calc に送っているので、攻撃側にテラスを持つメンバーの数値が変わる(印も消える)。Web は WASM が同じ engine を使うので同じ変化
- Web・iOS レーン: テラスの選択 UI(計算画面で任意に選べる・既定は「なし」)は各レーンで追従する。Web は `web/src/engine/types.ts` の印の説明(attacker_tera_type は現在付かない)を直す
- 判定レーン: judge は teraType を送らないので変化なし
- 未決(人間の確認): 防御側の相性を本編どおり反映するか(oracle と食い違うので known_diffs の承認が要る。既定案: 反映しない)。ADR-0224 の未決事項
