## 2026-10-11: タイプバランス画面の作り直し(G-05 / I-web-13f / ADR-0352。iOS・type-balance レーンへ)
Decision: Web のタイプバランス画面は次の構造にした。iOS も同じ構造に追う(部品の対応は docs/design.md「iOS の追い方(G-05)」)。
- 入力済みのメンバー・仮想敵の枠はポケモンカード(画像かエンブレム・名前・タイプバッジ)。追加は「+」の空きタイル(「メンバーを追加」「仮想敵を追加」)。
- 結果の升目は記号 + 文字(色だけにしない): 弱点=上向き(赤系)、耐性=下向き(緑系)、無効=×(青系)、等倍=横線。攻撃範囲は抜群=上向き(緑系)・いまひとつ=下向き(黄系)・無効=×(赤系)・等倍/攻撃技なし=横線。安全=チェック(緑系)・注意=三角(黄系)、抜群を取れる=上向き(緑系)。倍率の文字は従来のまま(「×2 弱点」)。
- 列・行の見出しはタイプバッジ。人数(集計・安全に受けられる・抜群を取れる)は大きい数字。穴・候補のタイプはバッジ(区切りは「・」)。
- 受ける/与える倍率には記号を付けない(分類が応答に無く、Web で判定し直さないため)。
Reason: 方針(文で説明しない・色だけに頼らない)をタイプバランス画面に適用した Web の結果を iOS が追うため。
Impact: iOS タイプバランス画面(type-balance レーンが追う)。API・engine・balance サービスの変更なし。語の追加・変更なし。
