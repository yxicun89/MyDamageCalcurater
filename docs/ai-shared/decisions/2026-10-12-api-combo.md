## 2026-10-12: 連続技 API `POST /api/calc/combo` と公開 `Move.effect`(CB-4。データレーンが API レーンを代行 / ADR-0252)
Decision: calc-svc に `POST /api/calc/combo`(operationId `calcCombo`)、pokedex-svc の公開 `Move`(getMove・getMovesByIds・searchMoves)に `effect` を足した。
- リクエスト: `format`・`attacker`・`defender`・`field`(`CalcRequest` と同じ形)+ `steps[]`(1〜3。`{ moveId, critical?, hits? }`)+ 任意 `opponentMoveId` + 任意 `opponentSpeed`(`unknown` 既定・`from_defender`)+ 任意 `speedField`(`trickRoom`・`selfTailwind`・`opponentTailwind`)。
- 応答: WASM の `calcCombo`(CB-5)と同じ形(`steps[]`・`total`・`speed{…, opponentSpeed, opponentSpeedKnown}`・`opponentAttack`(null か `{selfHp, minActions, maxActions, fast, slow}`)・`unsupported`)。unknown の相手の素早さは 0(null ではない)。
- エラー: 新しい code なし。手 0 件・4 件以上は ID の解決より前に 400 `invalid_input`、ランク変化の無い変化技の手・変化技の相手の技・多段の回数も 400 `invalid_input`、`opponentSpeed` の語彙外は 400 `invalid_enum`、**未知の技は 400 `unknown_move`**(combo-calc.md AC-16 の 422 は HTTP の語彙に無いので `/api/calc` と同じにした)。
- 計算イベントは発行しない(record・team・NATS が止まっていても成功。絶対ルール 5)。gateway の経路・NetworkPolicy は変更なし(`/api/calc/*` の前方一致)。
- 公開 `Move.effect`: move_effects の `Chance` が 100 のときだけ、内部 API の `MasterMove.effect` と同じ値(PascalCase: `{"Chance":100,"Target":"self","Stages":{"atk":1,"spe":1}}`)。確率 100% 未満・効果なしはキーごと省く。検証に通らない行は 503 `master_unavailable`。
Reason: Web(CB-6)・iOS(CB-8)がオンラインで連続技を使えるようにする。技の候補で「ランクが変わる技」を出すため。
Impact:
- **Web(CB-6)への依頼**: オンラインは `POST /api/calc/combo`、オフラインは WASM の `calcCombo`。応答の型は同じ。技の候補の `Move.effect` は PascalCase だが、WASM の `effect` は大文字小文字を区別せずに受ける(`rule` と同じ。CB-5 側に PascalCase を受けるテストがあると安心)。`effect` が無い技は「ランク変化なし」として扱う(古いサーバーも返さない)。`opponentSpeed` が unknown のとき、素早さ表の例は `POST /api/speed/v1/position` の raw を呼ぶ(combo-calc.md §2-3)。
- **iOS**: 生成型(swift-openapi-generator)に `calcCombo`(`ComboRequest`・`ComboResult` ほか)と `Move.effect` が増える。`APIProtocol` に準拠する手書きの型は無いので、既存のビルドは壊れない見込み(未確認。iOS レーンで iOS のテストを流す)。画面は CB-8。
- **デプロイ順**: calc-svc と pokedex-svc は独立に出せる(追加だけ)。Web の CB-6 は両方が出た後でよい。
