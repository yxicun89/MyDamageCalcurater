## 2026-10-11: Web のナビを 4 区分にした(案 B の Web 実装 / ADR-0356。iOS・ec レーンへ)
Decision: Web のナビは上位 4 つのタブ(ダメージ・構築・素早さ・記録)にした。ダメージの中だけ下位のタブ(計算・逆算・調整)。iOS も同じ区分・同じ語・同じ順にそろえる。
- URL は変えない(`/calc` `/reverse` `/adjust` `/team` `/speed` `/favorites`)。旧 `/balance` は `/team` に置き換える。タイプバランスの別画面は無く、構築編集の中の節になった(ADR-0421)。
- 上位のタブを押すと、その区分で最後に見ていた画面へ戻る(ダメージで調整を見て素早さへ行き、ダメージに戻ると調整)。訪れた画面は入力を保ったまま残す。
- 幅 600px 未満は上位のタブを画面の下に固定、それ以上は上部。区分のアイコン: ダメージ=衝撃(`movePhysical`)・構築=チーム・素早さ=稲妻・記録=星(下位の計算/逆算/調整のアイコンと重ならない)。
- 用語集に区分の語を足した(docs/glossary.md「ナビの区分」)。
Reason: ホームに戻らずに移れるようにし、入力を保つため(ユーザー決定の案 B)。
Impact: iOS の `RootView`・各入口(区分の名前・順・アイコンの意味)。API・engine の変更なし。
