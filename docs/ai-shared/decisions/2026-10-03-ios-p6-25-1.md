## 2026-10-03: iOS に素早さ比較画面を作る(P6-24。iOS レーン → 素早さ・API レーンへ)

Decision: ユーザー決定(2026-10-03)で、iOS に素早さ比較画面を作る。iOS は `GET /api/speed/v1/pokemon`・`GET /api/speed/v1/table`・
`POST /api/speed/v1/position`(gateway の `/api/speed/*`)を使い始める。契約は `services/speed/api/openapi.yaml`。iOS は契約を変えず、
root の `api/openapi.yaml` も変えない。生成は契約ごとに別ターゲット(`PokeCalcSpeedAPI`)で、`ios/scripts/openapi-gen.sh` を「契約・設定・出力先」の
組のループにした(判定 P6-25・タイプバランス P6-26 も同じ形で足す)。判断は ADR-0503、受け入れ条件は ADR-0501「P6-24 の受け入れ条件」。
Reason: Web にだけあった素早さ比較を iPhone でも使えるようにする(要件 §2・docs/speed-design.md。iOS は「後で」とされていた)。
Impact:
- 素早さレーン・API レーンへ: speed の契約を変えるとき(`PresetId`・`MinimalPresetId`・`NatureId`・`ErrorCode`・`PositionRequest` の範囲、新しい mode など)は、
  iOS の生成物と同期テストが落ちる。変更する PR で `make ios-gen` を実行して生成物を同じ PR に含め、DECISIONS.md に 1 行残す(iOS レーンが文言・ドメインを追従する。
  `make ios-gen-check` が CI で検出する)。後方互換な追加(省略可の項目)は生成物の更新だけで済む。
- `ErrorCode` に値を足すと、古い iOS アプリは応答をデコードできず「接続できません」になる(`UnsupportedMark` の ADR-0215 と同じ問題)。
  エラー code を増やすときは、新しい code を足す前に iOS 側の対応(未知の code を許す形への変更)を相談する。
- ADR-0802 の `{code,message}` への統一は iOS も前提にする(契約外のステータスでも本文が JSON ならその `code` を使う)。
- 絶対ルール 5: speed の失敗は計算・構築に影響しない(`PokeCalcService` と別のプロトコルで、画面も独立)。
- iOS が使う入力の範囲(SP 0〜32・ランク ±6)は `SPLimits`/`RankLimits` を共有し、契約との一致を `make ios-check-request-limits` が検査する。
