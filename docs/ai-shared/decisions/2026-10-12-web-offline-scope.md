## 2026-10-12: オフラインで使える範囲を画面に出す・計算の直近入力を端末に覚える(Web。ADR-0358 案 A 承認、段 1・2・4)
Decision: ユーザーが ADR-0358 の案 A を承認。Web は段 1・2・4 を実装した(段 3 の事前保存は別 PR)。
- オフラインのとき画面の上に 1 行: 「保存済み: ○匹。計算・逆算が使えます。素早さ・構築・お気に入り・調整はオンラインで」。保存済みが 0 のときは「保存済みのポケモンはまだありません。オンラインで一度開くと保存されます。…」。UI に「種族」は使わず「ポケモン」「○匹」。判定は廃止済みなので入れない。調整は API 専用なのでオンライン側。
- API 専用のタブ(調整・素早さ・構築・お気に入り)には「オンラインのみ」の理由を添える。押せなくはしない(調整・構築は計算する場所に関係なくオンラインのマスタで開ける。ADR-0411)。
- 計算画面の直近の入力(攻撃側の種族・性格・SP・持ち物・特性・状態、防御側、技、条件)を端末に 1 件だけ保存し、アプリを開いたときに戻す(案内は出さない。今のデータに無い種族があれば全体を捨てる)。逆算・調整・お気に入りの一覧は対象外。
- 利用者の画面に例データの名前を出さない。例データは単体テストと既定の取得口(テストが差し替えなかったときだけ)に限る。
Reason: 「オフライン画面がテストデータしか無く使い道が無い」(ec ラウンド 4)への対応。使える範囲を先に伝え、再訪時の入力し直しを減らす。
Impact: iOS は同じ範囲(端末に保存済みのポケモンで計算・逆算)・同じ言い方(「保存済み: ○匹」)にそろえる。直近の入力は端末内だけ(SwiftData / ファイル)。ADR-0308 決定 4 は「計算画面の直近 1 件だけ端末に書く」に変更。

### 追記(段 3 実装。Web I-web-31)
Decision: 「このアプリについて」に「オフライン用にポケモンのデータを保存」を実装した。オンラインのときだけ押せ、全ポケモンを直列(同時 1 件)で端末に保存する。保存済みは飛ばし、中断・失敗の後は続きから再開できる。進捗は「保存中 12 / 349」、完了は「保存済み: ○匹。オフラインで使えます」、失敗は「保存済み: ○匹。もう一度押すと続きから保存します」(端末に書けないときは空き容量の案内)。
Impact: iOS は同じ言い方・同じ挙動(オンラインのときだけ・直列・保存済みを飛ばす・中断と再開・端末に書けない失敗を見せる)にそろえる。一覧は公開 API の `GET /api/pokedex/species`(limit 上限 200)をカタカナの頭文字ごとに引いて key で重複排除、上限に達した頭文字は 2 文字目で再分割。新しい API はない。
