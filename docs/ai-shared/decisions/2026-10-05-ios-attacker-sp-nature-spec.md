## 2026-10-05: iOS の計算画面に攻撃側の SP・性格補正と技の絞り込みを入れる(iOS レーン。ADR-0518。F-01 / I-ios-1・I-ios-5。受け入れ条件とテストが先)
Decision: Web の ADR-0329・0328 に揃える。攻撃・特攻の 2 ブロック(SP の数値欄・性格補正の 3 択・カスタム印)を技セレクタと「詳細」の間に常に出し、値は技・種族・攻守入れ替え・構築の呼び出しで消さない。
性格はマスタから Web と同じ規則で解決し、不正入力は丸めず明示エラー(計算しない)。プリセットのピル行は今の場所・識別子のまま「技が使う側のブロック」のプリセットとして働く(ブロックごとのプリセット・カードの並べ替えは F-12 と一緒に後続)。
計算画面の技の選択肢は変化技を除く(構築から呼んだ変化技だけの個体は既定のダメージ技に・ダメージ技を覚えない種族は案内して計算しない・status-move は安全網)。逆算・調整はすでに絞り済み、判定と構築編集の 4 技は絞らない。
Reason: 「この SP ならどれくらいか」を数値で試したい要望(F-01)。Web が完了しているので差を作らない。丸め(4096 基準・五捨五超入)は engine のまま。
Impact:
- iOS: 受け入れ条件は ADR-0501 末尾「攻撃側の SP・性格・技の絞り込みの受け入れ条件」、判断は ADR-0518。実装者への足場は `TODO(implementer` を検索(`AttackerStatInput.swift`・`CalcViewModel+AttackerStats.swift`)。
- 既存テストの期待値は仕様変更で直す(一覧は ADR-0518「既存テストへの影響」。理由をコミットメッセージに書く)。
- 他レーン: 契約・engine・services・ゴールデン・Web は不変。文言は Web の `ja.ts`(「データにありません」)に合わせ、Web の申し送りの「マスタにありません」とは 1 語だけ違う(出荷済みを正とした)。
