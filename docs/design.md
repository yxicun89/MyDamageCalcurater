# デザインガイド

## 方向性

- **B: Liquid Glass 系のクリーン**(操作パネル・計算画面)
- **C: カード/ホロのコレクション風**(ポケモン表示・構築)
- **ポップ・カラフル**(ADR-0334): タイプ色のカード・丸いボタン・アイコン・やさしい背景のグラデーション。ブランド色・状態色は「ポップ配色」に限る(旧「背景は無彩色。色を持つのはタイプだけ」を改めた)
- 静止画をきれいに、動きは操作への反応だけ
- **文で説明しない**(G-05。ADR-0339): 「ここに何がある」を文で書かず、ボタン・アイコン・カード・色・操作時の動きで分からせる。決まりは「見た目の作り直し方針(G-05)」
- **言葉はやさしく**: 画面の言葉の正は [glossary.md](glossary.md)(ADR-0337)。対戦の標準の用語は変えず、アプリ内部・開発者向けの語を出さない

### タイプバッジ

タイプ名は**バッジ(ピル)**で出す。背景に上のタイプ色を敷き、文字はそのタイプ色に対して読める無彩色にする
(2026-09-25、issue #306)。タイプ色を**文字色**にそのまま使うと、ページ背景(bg.base)に対して
WCAG 2.2 SC 1.4.3(通常文字 4.5:1)に届かない(ライトで14タイプ、ダークで5タイプ。でんき 1.64:1、こおり 1.91:1 など)。

- 文字色は `#000000`(黒)か `#FFFFFF`(白)のどちらか。**そのタイプ色に対するコントラスト比が高い方**を選ぶ
- text.primary(ライト `#14161A` / ダーク `#F2F3F5`)は文字色に使わない。かくとう(最良で 4.12:1)と
  どく(同 4.31:1)が黒側・白側のどちらを選んでも 4.5:1 に届かないため。純黒・純白なら18タイプすべて届く
  (最小は かくとう の 4.59:1、次が どく の 4.79:1)
- 文字色はテーマで切り替えない。タイプ色がライト・ダーク共通の固定値なので、読みやすい側も共通で決まる
- タイプ色は変えない(この表の色は正。issue #306 の対象外)。変えるのは文字色と、バッジにする形だけ
- Web は `--type-<id>-ink`(tokens.css)に置き、バッジは `--type-<id>` を背景、`--type-<id>-ink` を文字色にする。
  未知のタイプ ID でも壊さないため、参照は必ず既定値つき(`var(--type-xxx, …)`)にする
- 形は「形・余白」のピル(`radius.pill`)。iOS も同名のトークン(`typeInk(_:)`)を持つ

## 見た目の作り直し方針(G-05)

ADR-0339(docs/usability-round3.md G-05)。今の画面は「ここに何がある」「〜を選んでください」を文で説明している。
これをやめ、**ボタン・アイコン・カード・色・動き(操作したときだけ)で分かる**作りに直す。目指すのは、今のスマホアプリ・ゲームの
UI のような、見て押せば分かる画面(ユーザーの言葉では「ポップ・カラフル」)。

土台は変えない: 「ポップ配色」「タイプ色」「タイプバッジ」の値、「共通の部品」の `.ui-*`、「入力のラベル」(見えるラベルは残す)、
「動き」(常時動くものを置かない)、コントラストの検査。この節は**それらの使い方**と、足す部品を決める。Web が先に作り、iOS は同じ方針で追う
(下の「iOS の追い方(G-05)」)。画像の表示(G-06)と技の選択肢(G-01)はこの節に従う。

### 文を減らす決まり

画面に出す文字は次の4種類だけにする。

| 種類 | 例 | 形 |
|---|---|---|
| 名前 | ポケモン・技・持ち物・特性の名前、構築 1 | データの名前そのまま |
| 短いラベル | 欄・ボタン・タブ・見出し(「攻撃側」「技」「計算」「保存」) | 名詞か動詞 1 語。目安 8 文字まで。文にしない |
| 数値・結果 | 72.1〜85.3%、確定2発、実数値 | 大きく・太く(「文字」のサイズ) |
| 状態の一言 | 「計算できませんでした」「まだありません」 | アイコン + 1 行 |

- **置き換える**: 「何がある」→ 見出しのアイコン + 短い名前。「何をする」→ ボタン(アイコン + 動詞 1 語)。
  「どれかを選ぶ」→ 区切りボタン・チップ・タイル(選択肢そのものを見せる)。「どういう状態か」→ 色 + アイコン + 一言
- **文を置いてよいのは次のときだけ**:
  1. エラー・失敗(何が起きたか + 次の一手。2 文まで。`.ui-notice--error`)
  2. 空の状態(一言 1 行 + 次の行動のボタン。下の「空の状態」)
  3. 取り消せない操作の確認(削除の 2 段階)
  4. ラベルだけでは単位・向きが分からない数値の欄(「入力のラベル」の `aria-describedby` の説明。1 行)
  5. 「このアプリについて」(非公式表示・データの出典・データの扱い。説明そのものが目的の画面なので例外)
- 1 つのカード・節に置く補足(補足 12・`text.secondary`)は **1 行を 1 つまで**
- それでも説明が要るときは、文を画面に出し続けず、見出しの横の「説明」ボタン(情報のアイコン)で開く。開く段階は 1 段まで
  (段階的に出す。2 段以上は迷いやすい)。開いた中も 3 行まで
- 言葉は [glossary.md](glossary.md) の語。新しい語は先に用語集へ足す。「入力のラベル」の見えるラベルは消さない(短くするだけ)

### アイコンの決まり

- **形**: 線画・24×24・線の色は文字色に従う(`web/src/ui/Icon.tsx` の `ICON_SHAPES`、`.ui-icon`)。自作の単純な形にし、
  公式・他のアプリのアイコンを写さない。塗りの強調(選択中など)は部品の塗り(`brand.primary`)で行い、アイコンの形は変えない
- **アイコン + 短いラベルを基本にする**。アイコンだけで意味が通じるものは少ない(検索・閉じる程度)ため。
  アイコンだけにしてよいのは、意味が広く通じる操作(検索・閉じる・追加 +・削除・入れ替え ⇄・上へ・下へ)で、かつ
  一覧の各行のように同じボタンが繰り返し並ぶときだけ
- アイコンだけの部品は、用語集の語で**必ず読み上げ用の名前**を持つ(Web は `aria-label`、または `Icon` の `label`)。
  文字と並ぶアイコンは装飾として支援技術から隠す(今の `Icon` の既定)
- 今ある 18 個(計算・逆算・素早さ・タイプバランス・判定・構築・お気に入り・調整・このアプリ・既定の四角・入れ替え・追加・削除・
  編集・検索・注意・情報・完了)に、作り直しで次を足す: 技の分類 3 つ(ぶつり・とくしゅ・へんか)・閉じる・開く(下向きの山)・
  計算履歴(時計)・説明(?)・上へ・下へ(実装済み: I-web-13a。名前は `close`・`open`・`history`・`help`・`up`・`down`。増減ボタン用に `minus` も足した)。足すたびに iOS の `PopSymbol` と意味をそろえる
- **タイプの印**: 正はタイプバッジ(タイプ色のピル + タイプ名)。行の頭など狭い場所では、タイプ色の丸(12px)を印にしてよいが、
  そのときはタイプ名を読み上げ用の名前か、同じ行・見出しの文字で必ず持つ(色だけに頼らない)。公式のタイプのアイコンは使わない。
  色は `var(--type-<id>, …)`(既定値つき)。タイプ色を文字色にしない(「タイプバッジ」)
- **技の分類の印**(ぶつり・とくしゅ・へんか): 3 つの自作アイコンで出す(ぶつり=放射状の衝撃、とくしゅ=同心の波、へんか=半分の円 を既定案にする)。
  分類で色を変えず文字色のまま(タイプ色と取り違えないため)。読み上げ用の名前は「ぶつり」「とくしゅ」「へんか」
- **ポケモンの画像**: ADR-0808 の `/images/*` から出す(G-06)。画像が無い・読めないときはタイプ色のエンブレム(ADR-0325)。
  画像は装飾(alt は空)、名前は隣の文字が担う。画像とエンブレムは同じ寸法の枠に収め、読み込みでレイアウトを動かさない

### 動きの決まり(G-05)

- 正は「動き」の節。動くのは**操作への反応だけ**: 押下で少し縮む、区切りボタンの塗りが移る、ピッカーのシートの出入り、
  候補が絞られる切り替え、確定数のバッジが弾む。時間はトークン(`duration.*`)だけ。シートの出入りの時間はトークンを足して決める(0.25 秒以内)
- 常時動くもの(回り続ける読み込み・点滅・自動で流れる表示・背景の動き)は置かない
- OS の「視差効果を減らす」(`prefers-reduced-motion: reduce`)では全演出を 0 にする(`web/src/ui/motion.ts`)
- 動きだけで意味を伝えない。変わったことは数値・文字・アイコンにも出る
- 触覚は iOS だけ(Web は無し。「動き」の理由のまま): 確定数が変わった(軽)、ピッカーで選んだ(選択)、削除した(注意)

### 見やすさの決まり(G-05)

- アイコンだけの部品は読み上げ用の名前を必ず持つ。見えるラベルがある部品は、その文字を名前に含める(WCAG 2.2 SC 2.5.3)
- 押せる範囲は 24×24 CSS px 以上(SC 2.5.8)。主な操作は 44px を目安にする(iOS の最小高さ 36pt は「共通の部品」のまま)
- 色だけに頼らない: タイプ色の丸には名前、相性には記号と文字、選択中には塗り + 枠かチェックの印
- コントラスト: 文字 4.5:1(SC 1.4.3)、アイコン・部品の境界・選択中の印 3:1(SC 1.4.11)。今の検査(`contrast.test.ts`・
  `typeBadgeContrast.test.ts`・`popPalette.test.ts`)は残し、新しい色の組は同じ検査に足す。色はトークンだけ(`noColorLiterals.test.ts`)
- ピッカーのシートは「このアプリについて」の確認ダイアログと同じ作法(開いたら中へフォーカス・Esc で閉じる・Tab は中で回る・
  閉じたら開いたボタンへ戻す)。区切りボタンは矢印キーで動かせる(ラジオの作法)
- テストを弱めない。見た目のテスト(`*.visual.test.tsx`)に、新しい部品のクラス・読み上げ用の名前・文の数を足す

## 入力のラベル

入力は「何を入れる欄か」が**画面の文字**で分かるようにする(2026-09-25、issue #304。WCAG 2.2
SC 3.3.2 ラベル又は説明)。読み上げ用の名前(accessible name)だけを持ち、画面には何も出ない欄を作らない。

- 領域(カード・枠)には**見える見出し**を置く。計算は「攻撃側」「防御側」、逆算は「自分」「相手」、
  タイプバランスは「メンバーn」「仮想敵n」(fieldset の legend。既にある)
- 見出しの階層は h1(アプリ名)→ h2(領域の見出し)→ h3(領域の中の名前。選んだポケモンの名前)
- 各入力には**見えるラベル**を置き、`label` の `for` で欄と結び付ける。ラベルの語は短くする
  (「ポケモン」「持ち物」「技」「特性」「技n」「観測n」)。どちら側の入力かは領域の見出しが担い、
  ラベルでは繰り返さない
- **accessible name には見えている文字を必ず含める**(SC 2.5.3 見出しどおりの名前)。領域の見出しと
  欄のラベルは**同じ語から組み立て**、同じ文字列を画面のコードに2回書かない。欄の accessible name は
  「<領域の見出しの語>の<ラベルの語>」の形にする(見出し「攻撃側」+ ラベル「ポケモン」→「攻撃側のポケモン」)。
  この組み立ては文言資源(`web/src/i18n/ja.ts`)が持ち、画面は組み立て済みの語だけを使う
- 未選択の select を空欄にしない。先頭に「ポケモンを選ぶ」のような文言の option を置く。この option は
  `hidden` にして一覧には出さず、選択中の表示にだけ出す(選び直すときの一覧に空の行を増やさないため)
- 数値を入れる欄は、ラベルだけで意味が伝わらないときは**説明の文**を添え、`aria-describedby` で結び付ける。
  逆算の観測欄は、単位(%/HP)と観測した側(与えた/受けた)の組み合わせで説明の文が変わる
  (「相手の HP が減った割合(%)」「自分の HP が減った実数値(HP)」など)
- 見えるラベルを、視覚的に隠す指定(`clip`・`width: 1px` など)で消さない。読み上げ専用にしたら
  この節の目的(初見で分かること)を満たさない
- 形は「形・余白」のトークンに従う。select・数値入力は入力の角丸(`--radius-input`)、ボタンはピル
  (`--radius-pill`)。ブラウザ既定の見た目のまま置かない(計算・逆算の技の select、「観測を追加」ボタン)

## 幅への対応(ブレークポイント)

画面の横幅(viewport の幅)だけで決める。端末の種類・向きでは分けない。

- ブレークポイント: 600px(2026-09-24、issue #98)。600px 以上を「広い幅」、600px 未満を「狭い幅」とする
  - 根拠: 中身の最大幅はカードの 720px。狭い側の上限を 600px にすると、広い側では左右に並べても
    1枚あたり 260px 以上になり、持ち物・ポケモンの select が潰れない。実機の 320px・375px は狭い側に入る
  - 値は4の倍数(「形・余白」と同じ作法)。CSS では `@media (min-width: 600px)` を広い幅の目印にする
- 狭い幅(600px 未満): 計算・逆算のカードは横に並べず、1列に縦積みにする
  - 計算: 上から 攻撃側カード → 攻守入れ替えボタン → 防御側カード。ボタンは2枚のカードの間の行に置き、中央寄せ
  - 逆算: 上から 自分側カード → 相手側カード
  - 縦積みでも DOM の順序とキーボードのフォーカス順は上の並びと同じにする(CSS の `order` などで視覚順を入れ替えない)
- 広い幅(600px 以上): 「画面: ダメージ計算」の左右配置(攻撃側 ⇄ 防御側)に戻す
- どの幅でもページ全体を横スクロールさせない。select・数値入力は列の幅まで縮める(中身の固有幅で列を広げない)
- 例外(issue #333、2026-09-25): 画面切り替えタブ(`.app-tabs__list`)は、5つの名前の合計幅が320・375pxでは
  必ずページ幅を超える(折り返すと1文字ずつ縦に割れて読めなくなる。issue #333)。タブ列**だけ**を横スクロール
  可能にし(`overflow-x: auto`)、各タブは `white-space: nowrap` で折り返さない。中央寄せ(`justify-content`)を
  普通の `center` にすると、はみ出した内容の先頭側にスクロールで到達できなくなるブラウザの既知の癖がある
  (centered flexbox overflow clipping)ため、`justify-content: safe center` を使う(はみ出すときは先頭寄せに
  自動で切り替わる。Chromium で実測確認済み)。`safe` キーワードの Safari 対応は人間の確認が要る
  (docs/verify.md の Web の確認〈P4-5〉と合わせて確認する)。

## 画面: ダメージ計算

```
┌────────────────────────────┐
│ [攻撃側カード]  ⇄  [防御側カード] │  各カード: 画像(あれば)/エンブレム・名前・タイプ・持ち物
│ [技セレクタ  威力・分類・相性]    │
│ [攻撃(この技で使用)] [特攻]       │  各ブロック: プリセット・SP の数値(0〜32)・性格補正
├────────────────────────────┤
│ 結果(防御側の代表調整ごと)      │
│  無振り       72.1〜85.3%  確定2発 │  行: 調整名・%幅・ダメージバー・確定数
│  H振り        61.0〜72.2%  確定2発 │  (物理技の既定は5行: 無振り/H振り/H振り+B補正/
│  HB特化       44.3〜52.5%  乱数2発 │   HB振り/HB特化。特殊技はD系、ADR-0009)
│  +持ち物のトグル                   │
├────────────────────────────┤
│ よく計算する相手(チップ)          │
└────────────────────────────┘
```

- 攻撃側・防御側は左右、結果は下(左右に並べるのは広い幅のとき。狭い幅は「幅への対応(ブレークポイント)」)
- 防御側は努力値を入力しない。技が物理なら HB 系、特殊なら HD 系の行に自動で切り替える
- 入力はタップで選ぶ。数値の直接入力は「詳細」を開いたときだけ。**例外**: 攻撃側の SP 欄(2026-10-04、ADR-0329)。
  技の直後に「攻撃」「特攻」の2ブロックを常に出し、各ブロックはプリセット(無振り・特化・振り(無補正)のタップ)・
  SP の数値欄(0〜32)・性格補正(上昇・補正なし・下降)を持つ。選んだ技が使う方の見出しに「(この技で使用)」を足し、
  太い枠で強調する(色だけに頼らない)。値は技・種族・攻守入れ替えで保つ
  **iOS**(ADR-0518): ブロックは技セレクタと「詳細」の間に常に出す。SP の数値欄の数値キーボードには「完了」(キーボードのツールバー)を置く。
  性格補正の3択は `Menu` を使わずボタンの並び(アクセシビリティの大きい文字サイズでは縦積み)。見出しの強調は「(この技で使用)」の文字と見出しの太さで行う。
  プリセットのピルの行は今の場所のまま、選んだ技が使う側のブロックのプリセットとして働く(ブロックごとのプリセットは後続)。
  技の選択肢はダメージ技だけ(変化技は出ない。Web の ADR-0328 と同じ)
- 技の欄の上に「技の並び」のチップ(習得順〈既定〉・五十音順・タイプ順。`.ui-chip` の radiogroup。2026-10-04、ADR-0335)。
  タイプ順はタイプ名の見出し(optgroup)つき。並びは端末に覚え、計算と逆算で共有する。既定の技は並びに依らず learnset の先頭のダメージ技
- **見た目の作り直し(G-05。I-web-13b。ADR-0345)**: 攻撃側・防御側のカードは、見出し(h2)の下に `PokemonCard`(画像かエンブレム・名前 h3・タイプバッジ・
  持ち物の印。メガ種族は固定のメガストーン)を顔として置き、その下に選ぶ欄(select。`Picker` ができるまで)。
  結果の行は「ダメージ幅の大きい数字 + 確定数のバッジ(brand.primary の塗り・on.primary の文字。見出しの大きさ)」を 1 行目、ダメージバーを 2 行目、調整・持ち物・特性を caption で最後に
  (見た目の順 = DOM の順。`order` を使わない)。技の相性(ばつぐん等)は枠だけのバッジ。性格補正は `SegmentedControl`、SP は − / + と文字の数値欄
  (不正な値を誤りとして出すため数値欄にしない)、プリセット・条件(急所・やけど・天候・フィールド・壁)・「持ち物の候補も比較」はチップ(選択中は塗り + チェック。主な操作は 44px)、
  ランクは増減ボタン。防御側の残りHPの長い説明は「説明」ボタンの奥(単位の 1 行は残す)
- カードの上端に「攻撃側」「防御側」の見出しを出し、ポケモン・持ち物・技の欄にも見えるラベルを付ける
  (「入力のラベル」)
- ダメージバーは**装飾**として扱う(2026-09-25、issue #306)。同じ行に %幅 と 確定数 を文字で出しており、
  バーはその同じ値を目で分かる形にしただけなので、支援技術には渡さない(Web は `aria-hidden="true"`、
  `role="meter"` と `aria-value*` は持たせない)。名前の無い meter として読み上げられるのを避けるため。
  バーが唯一の伝達手段になる作りに変えるとき(行から %幅 の文字を外すなど)は、この扱いを見直す
- **「未対応」の印**(2026-09-25、issue #271 / #270、ADR-0123。**2026-09-25 追記: iOS レーンの決定
  〈docs/ai-shared/DECISIONS.md 2026-09-25「未対応の印の表示」、ADR-0501「P6-17」〉に合わせて置き場所・色を
  改訂**): engine が正しく計算できない技・持ち物・特性を選んだときは、**数値はそのまま出したうえで**
  「この結果は正確でない可能性がある」印を添える(計算を拒否しない。ADR-0123 §1)。
  - **置き場所は「全行にあるか」で決める(target で決め打ちしない)**: 印の内容(技・持ち物・特性の ID と
    理由の組)が**全行に共通してあれば結果の先頭に1回**、**一部の行だけにあれば、その行の中**に出す
    (`web/src/domain/unsupportedLabels.ts` の `splitUnsupportedMarks`)。技由来の印は行によらず同じ内容で
    全行に付くことが多く、行ごとに出すと同じ文言が5〜10回並んでしまうため(iOS レーンの指摘)。持ち物の
    比較で行ごとに変わる印は、今までどおりその行だけに残る
  - 印が1件でもあれば、結果の**先頭に案内を1つ**(`role="status"`)出す。issue #305 の
    「観測を説明できる候補がない」案内と同じ置き場所・同じ作法。両者は独立した別要素として共存できる
  - **色だけに頼らない**: 印は必ず文字で出す。結果の先頭は「この結果は正確でない可能性があります
    (未対応: <印>、<印>)」、行の中は「未対応: <印>、<印>」。印1つの書式は
    「<技/攻撃側の持ち物/攻撃側の特性/防御側の持ち物/防御側の特性>「<対象の名前>」(<理由>)」
    (理由が「効果を計算に反映していない」のときは括弧を省く。文言は `web/src/i18n/ja.ts` の
    `unsupportedText`)。アイコン(⚠ など)は装飾として `aria-hidden="true"` にし、印の意味を担わせない。
    **色は既存の補足文(caption・`text-secondary`)と同じにする**。数値は通常の式の目安として出ており
    エラーではないため、警告色(`danger`)やタイプ色は使わない(iOS レーンの決定に揃える)
  - 印は engine が返した順のまま出す(並べ替え・重複除去をしない)。変化技には印が付かない

## 画面: 逆算

- 攻撃側(自分)・防御側(相手)・技を選び、観測したダメージ(HP%)を入力
- 候補(性格補正あり/なし × 持ち物)を一致度の高い順(engine の順。観測を説明できる候補が先)に1件ずつカード表示し、目安の型の名前(HB特化など)を各カードに併記する(2026-09-22 ユーザー決定。型は SP 範囲から一意に決まらないため、型でまとめない)
- 「観測を追加」で2回目以降を入力すると候補が絞られるアニメーション
- G-05(ADR-0346): 自分・相手は見出し(h2)の下にポケモンカード(名前 h3・タイプバッジ・自分は持ち物の印)。ダメージの側と単位は区切りボタン、自分の調整はチップ。候補のカードは 1 行目に型の名前 + バッジ + 予測%の大きい数字、次にバー、下に SP の範囲・持ち物・特性を小さく
- カードの上端は「自分」「相手」の見出し。観測の欄には、単位と観測した側に応じた説明の文を添える
  (「入力のラベル」)
- **「未対応」の印**(2026-09-25、issue #271 / #270、ADR-0123。2026-09-25 追記: iOS レーンの決定に合わせて
  置き場所・色を改訂): 候補の予測%が当てにならない可能性があるときに出す。**全候補に共通する印は候補一覧の
  先頭に1回、一部の候補だけにある印(候補ごとに持ち物が違う等)は、その候補カードの中**に出す
  (「画面: ダメージ計算」の「未対応」の印と同じ振り分け方)。見た目・文言・色だけに頼らない扱いも
  「画面: ダメージ計算」と同じで、候補カードの中は「近い候補」「参考」のラベル(issue #305)と同じ並びに
  置く。印が1件でもあれば候補一覧の先頭に `role="status"` の案内を1つ出す(issue #305 の
  `noExactCandidateNotice` と同時に出ることもあり、互いに独立した別要素として共存する)

## 画面: 構築(P5-5a。ADR-0309・F-08 で作り直し ADR-0332)

一覧と編集の2つの表示を切り替える(URL は /team のまま)。構築名は無い。

```
一覧                                 編集
┌──────────────────────┐   ┌──────────────────────┐
│ [新しい構築]                 │   │ 構築 1            [一覧に戻る] │
├──────────────────────┤   ├──────────────────────┤
│ ┌ 構築 1 ───────────┐ │   │ ┌ 1体目(タイプ色)──────┐ │
│ │ ●●  2/6体 最終更新…  │ │   │ │ ポケモン/技1〜4/持ち物…    │ │
│ │          [開く][削除] │ │   │ │ [上へ][下へ][外す]       │ │
│ └────────────────┘ │   │ └────────────────┘ │
│                             │   │ 2〜6体目(空は種族欄と案内)  │
└──────────────────────┘   │ [保存] 保存していない変更…   │
                                   └──────────────────────┘
```

- 表示名: サーバーの既定名「名称未設定」の構築は「構築 N」(既定名の構築を作成の古い順に数えた番号)。古い名前付きの構築はその名前。
  create/update は `name` を送らない。
- 一覧: 各構築は `.ui-card`。メンバーのアイコン列(画像が無ければタイプ色のエンブレム)・n/6体・最終更新・[開く](主)・[削除](危険。2段階)。
  並びはサーバーの応答のまま。一覧が読めなくても[新しい構築]は押せる。
- [新しい構築]は空の構築を作り、すぐ6枠の編集画面を開く。編集画面には常に6枠(1体目〜6体目)。
  種族が決まった枠はタイプ色のカードで、技4・持ち物・特性・性格・テラスタイプ・SP を出す。空の枠は種族欄と案内だけ。
  枠ごとに[上へ][下へ](空の枠とも入れ替え)・[外す](その枠だけ空に。他は詰めない)。
- 保存は明示(種族の決まった枠を枠の順に詰めて送る)。未保存の印は文字で出す。[一覧に戻る]は未保存なら「保存せずに戻る / 編集を続ける」の2段階。
- Showdown 形式の取り込み・書き出しは G-03 で廃止した(ADR-0342。以前は一覧の下と編集画面の下の折りたたみ)。
- 削除は2段階(`window.confirm` を使わない)。
- **見た目の作り直し(G-05。I-web-13d。ADR-0347)**: 一覧のカードは名前(h3)の下に 6 つの枠(埋まった枠は画像かエンブレム、空きは破線の枠)・n/6体・最終更新、
  [開く]は「編集アイコン + 開く」、削除は「ごみ箱のアイコンだけ」(名前は「<名前>を削除」のまま)。空の一覧は大きいアイコン(48)+「まだ構築がありません」。
  編集画面は見出しの下に 6 枠のタイルの格子(`role="group"` 名前「メンバー」): 埋まった枠は `PokemonCard`(名前・タイプバッジ・持ち物の印。メガは固定のストーン)、
  空きは「+ N体目を追加」の `Tile`。タイルは欄への近道(押すとその枠の先頭の欄へ移る。Tab の順には入れない)。6 枠の欄は従来どおり常に全部出る。
  欄は技 4 つ・持ち物・特性・性格・テラスタイプを 2〜3 列(狭い幅は 1 列)。SP は 6 欄とも − / + のボタン(0〜32 で止まる)+ 文字の数値欄(不正な値は誤りとして出す)、
  合計と残りは数値(「合計 66/66(残り 0)」。超過は danger 色)+ 装飾のバー。上へ・下へ・外すはアイコンだけのボタン(名前は「N体目を上へ」等のまま、44px)。
  未保存の印は警告アイコン + 一言、保存済みはチェック + 一言。技は select のまま(`MovePicker` への置き換えは後続。ADR-0347)、性格は 5 択以上なので select のまま。

## 画面: このアプリについて(P6-18 / issue #328 の Web 分。ADR-0314)

```
┌────────────────────────────┐
│ <h1> アプリ名 / 計算モード        │
├────────────────────────────┤
│ <h2> このアプリについて           │
│  <h3> 非公式表示                  │
│   (非公式の注記。折り返す)        │
│  <h3> データの出典                │
│   ・ダメージ計算の検証 @smogon/calc(MIT License) │
│   ・… 4件                         │
│  [計算に戻る]                     │
├────────────────────────────┤
│ <footer> このアプリについて(リンク)│  全画面の最下部。控えめな文字リンク
└────────────────────────────┘
```

- 入口はアプリ下部のフッター(`<footer>`。main の外)の文字リンク「このアプリについて」(`href="/about"`)。タブには入れない。
  既存画面の邪魔にならないよう、目立たせない(タブ・ボタンより小さい文字・`--text-secondary`)。ただしコントラストは AA を満たす
- `/about` は ADR-0300 §1 のパス連動(押すと pushState、戻る/進むで往復、直接開ける)。この画面ではタブ列を出さない
  (どのタブも選択中でない状態を作らないため)。他タブの画面は hidden で DOM に残し、入力を失わない(ADR-0308)
- 見出しは h1(アプリ名)→ h2(このアプリについて)→ h3(非公式表示・データの出典)。開いたら h2 にフォーカスを移す
- 文言は i18n/ja.ts の `aboutText` に1か所。非公式の注記・出典4件は iOS(`PokeCalcCore.AboutText`)と一字一句同じ
  (DECISIONS.md 2026-09-26「P6-18」)。出典を増減するときは ADR-0002・ADR-0501「P6-18」・iOS と同時に直す
- h3「データの扱い」(P5-5d。ADR-0318): 説明4文(ADR-0209 §8)と「この端末のデータを削除」ボタン。押すとアプリ内の
  `role="alertdialog"`(初期フォーカスはキャンセル・Esc で閉じる・Tab はダイアログ内で循環・閉じたら削除ボタンへフォーカス)。
  進行・完了は `role="status"`、失敗は `role="alert"` + 「もう一度削除する」。端末 ID・設定など端末内の状態は消さない。
  色・余白はデザイントークンのみ(危険操作の文字色は `--danger`)
- 「計算に戻る」は `/calc` へ pushState。常時アニメーションは入れない。ダーク/ライトはトークンで両対応

## 動き
- ダメージバー: spring アニメーションで減る(曲線 `cubic-bezier(0.34, 1.56, 0.64, 1)`。トークン `ease.spring`)
- 確定数が変わった瞬間: バッジが弾む(0.4秒。`duration.pulse`)+ 触覚フィードバック(軽。iOS だけ。Web は触覚なし: iOS Safari は `navigator.vibrate` に対応せず効果が小さいため。2026-09-22)
- 攻守入れ替え: カードが入れ替わる(0.35秒。`duration.swap`)
- ホロ効果: 選択中のカード1枚だけ、端末の傾き(Web はポインタ位置)に連動。ハイライトは白 35%(`holo.highlight`、ライト/ダーク共通)。Web はマウス・ペンのときだけ(タッチでは出さない。指で隠れて見えないため)
- 逆算で観測を追加して候補が絞られるとき: 候補一覧が 0.3秒で切り替わる(`duration.narrow`)
- 押下: ボタン・タブ・チップを押したとき 0.15秒で少し縮む(`duration.press`)。OS の「視差効果を減らす」では 0
- シートの出入り: 0.25秒(`duration.sheet`。G-05)。OS の「視差効果を減らす」では 0
- 常時動くものは置かない。OS の「視差効果を減らす」で全演出を無効化

## パフォーマンス予算
- 画像: サムネ 128px WebP ≤ 20KB、詳細 512px ≤ 100KB、見えている分だけ読み込む(`loading="lazy"`)。画像は任意で、無い・取れない・読み込み失敗のときはタイプ色エンブレム。装飾なので alt は空、エンブレムと同じ寸法の枠に収めてレイアウトを動かさない(ADR-0325)

- Web の初期ロード: JS ≤ 300KB・CSS ≤ 30KB(gzip、WASM 除く)
