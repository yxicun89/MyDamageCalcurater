# プロジェクト概要

自分用の、ポケモンチャンピオンズ向けアプリ。ダメージ計算を中心に、タイプの穴を診断する機能・素早さを比べる機能・
「抜けて倒せるか」を1回で判定する機能を、同じ基盤の上に積み上げている。動作確認は [verify-m1.md](verify-m1.md)、
構成図は [architecture.md](architecture.md)、進捗は [plan.md](plan.md) を参照。

## これは何のためのアプリか

- 対戦前の「ダメージ計算」「役割対策」「素早さ調整」「相手を抜いて倒せるか」を、いちいち別サイトを見比べずに済ませる。
- ブラウザ(オンライン・オフラインの両方)と iPhone アプリで使う。学習目的も兼ね、フロント〜バックエンド〜DB〜
  Kubernetes まで一通り自分の手で組む。
- 個人利用が前提(認証なし)。公開するかどうかは未定で、公開する場合に画像・名称を差し替えられる構造にしてある。

## 機能

| 機能 | できること | 状態 |
|---|---|---|
| **ダメージ計算** | 攻撃側・防御側を選んでダメージ幅(乱数16段階)・確定数・%を計算。相手側は代表的な調整をまとめて表示。観測ダメージから相手の調整を逆算する機能もある | 実装済み |
| **タイプバランス** | 手持ち最大6体の防御相性・攻撃技の範囲を集計し、タイプの穴(弱点が多く打点が無いタイプ)を診断。穴をふさげるタイプと該当ポケモンを提案。仮想の相手を登録して個別の相性も見られる | 実装済み |
| **素早さ比較** | 使用可能な全ポケモンを速い順に並べた表と、自分のポケモンの実数値を並べて、自分がどの位置にいるかを一目で見せる | 実装中 |
| **判定** | 「この道具・調整・技構成で、想定した相手を素早さで抜けて、かつ技で倒せるか」を1回の入力で確認する(技の追加効果によるランク変化も考慮) | 設計段階 |
| **構築ビルダー**(iOS) | パーティを組んで保存する | 実装中 |

対象ルールは「ポケモンチャンピオンズ」のシングルバトル(レベル50・個体値31固定)。細かい仕様は
[requirements.md](requirements.md) に、見た目の方針は [design.md](design.md) にまとめている。

## アーキテクチャの考え方

### 1. 計算ロジックは1か所だけに書く

ダメージ・実数値・逆算などの計算式は、外部に一切依存しない純粋な Go のパッケージ `engine/` に集約している。
サーバー(calc-svc)もブラウザ(WebAssembly にビルドした同じコード)も、**同じ engine を呼ぶだけ**。
式を2か所に書いて食い違う、ということが起きない構造にしてある。

### 2. マイクロサービス構成(学習目的)

機能ごとに独立したサービスに分け、Kubernetes(手元の Mac 上の k3d)で動かす。

- **gateway**: ブラウザ・iOS からの唯一の入口。
- **calc-svc**: ダメージ計算の API(engine を呼ぶだけ)。
- **pokedex-svc**: ポケモン・技・持ち物などのマスタデータの検索・提供。
- **balance-svc / speed-svc**: タイプバランス・素早さ比較のそれぞれの API。
- **MySQL**: マスタデータの保存先。

サービス間の契約は OpenAPI で先に決め、そこから各言語のコードを生成する(手書きしない)。

### 3. マスタデータは外部から取り込む(実データは配布しない)

ポケモンの種族値・技・持ち物などは、任天堂・ゲームフリークの著作物であり、このリポジトリには含めない
(`data/generated/` は Git 管理外)。かわりに、`@smogon/calc`・Pokémon Showdown・PokeAPI から
定期的に取り込む仕組み(importer)を自前で持ち、取り込んだ結果を MySQL に入れて各サービスが参照する。
リポジトリに入っているのはコード・スキーマ・架空データの例だけ。詳しい経緯は [ADR-0002](adr/0002-master-data-source.md)。

### 4. オンライン/オフラインの両対応

ブラウザは、サーバーに繋がなくても WebAssembly 版の engine でその場で計算できる(オフラインモード)。
サーバーに繋げば実際のマスタデータを使った計算ができる(オンラインモード)。どちらも同じ計算結果になる。

## どうやって作っているか

各機能(ダメージ計算・API・画面・タイプバランス・素早さ・判定・iOS)を「レーン」という単位に分け、
AI(Claude Code / Codex)がレーンごとに独立した作業ディレクトリで並行して実装している。決定事項や
引き継ぎは `docs/ai-shared/` に記録し、`main` ブランチに全レーンの成果を集約する。この運用の詳細は
[docs/ai-shared/COORDINATION.md](ai-shared/COORDINATION.md)。
