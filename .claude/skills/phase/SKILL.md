# /phase

対象: $ARGUMENTS(省略時は plan の最初の未完了タスク)

plan は区画ごとのファイルに分かれている(ADR-0172)。`docs/plan.md` の「区画」の表で対象を探す:
- マイルストーン・区画(`M1`・`SP` 等)は、表の該当行のファイル(`docs/plan/m1.md` 等)のタスクが対象。
- タスク ID(`P1-3`・`AJ4`・`I-web-1` 等)は `grep -rnE '^[[:space:]]*- \[.\] (\*\*)?<ID>([^0-9A-Za-z-]|$)' docs/plan/` で行を探す(ID の直後が英数字・`-` でないことを境界にする。`P1-3` が `P1-3b` に、`I-web-1` が `I-web-12` に当たらないように)。
- 省略時は、表の上から順に区画のファイルを開き、最初の `[ ]` の行を対象にする(`[~]`・`[!]` は他のセッションの作業中・ブロック中なので飛ばす)。

対象に含まれる未完了タスクを上から順に、1つずつ次の手順で処理する。

1. 区画のファイル(`docs/plan/<区画>.md`)のタスクを `[~]` にする
2. `quick-scanner` に影響範囲を調べさせる
3. `spec-writer` に受け入れ条件とテストを書かせる
4. `implementer` に実装させる
5. `critic` にレビューさせる。FAIL なら指摘を渡して 4 に戻る(最大3回)
6. 外部 Codex レビュー(`scripts/codex-review.sh` / `codex exec`)は**実行しない**(ユーザー指示 2026-09-21。Codex は別ターミナルで並行して実装しているため、レビューには使わない)。レビューは critic のみ
7. 区画のファイルのタスクを `[x]` にし、1タスク1コミット(`P1-3: ダメージ計算コア` の形式)
8. 3回ループしても通らなければ `[!]` にして `docs/plan/blockers/<レーン>.md` に記録し、依存しない次のタスクへ進む

マイルストーンの最後に `/verify` を実行し、人間向けの動作確認手順を `docs/verify-<M>.md` に書いて止まる。
人間の確認が必要なこと(CLAUDE.md 参照)に当たったら、その時点で止まって依頼する。
